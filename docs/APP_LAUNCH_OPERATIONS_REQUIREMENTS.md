# 万有棱镜 App 推广技术需求与运营交付清单

> 本文供产品、开发和运营内部协作使用，不直接作为外部推广人员的操作手册。
>
> 目标是提前明确：开展抖音、小红书、哔哩哔哩等渠道推广前，运营需要先给开发什么信息、开发需要怎样实现、实现完成后具体向运营交付什么，以及双方如何验收。

## 0. 文档使用方式

```text
公司/产品/运营先确认推广需求和基础资料
                    ↓
开发根据本文实现下载、唤醒、链接、归因和统计能力
                    ↓
开发把正式链接、参数规则、数据入口和使用说明交给运营
                    ↓
运营使用这些内容组织自然推广、达人合作或付费投放
                    ↓
运营把平台账户标识、最终作品地址和审核反馈返回给开发
                    ↓
开发完成平台转化对接、数据核验和问题修正
```

本文描述的是后续需要完成的工作和交付标准，不代表这些功能目前已经全部实现。

## 1. 文档范围

本文说明：

- 运营推广依赖哪些 App 和后端能力
- 下载、唤醒、推广链接和分享链接应该如何实现
- 渠道来源、注册、付费和退款应该如何统计
- 开发需要运营、产品和公司先提供什么资料
- 开发完成后需要向运营提供哪些正式内容
- 运营收到后如何使用，以及需要向开发返回什么

本文不展开：

- 视频、图文和封面的具体制作
- 达人选择、投放预算及商务报价
- 推广文案的最终审核
- 企业广告账户的充值和日常投放操作
- APP 备案、软著和应用市场上架材料；这些内容单独记录在 `Androrid、ios.md`

## 3. 总体链路

```text
抖音 / 小红书 / 哔哩哔哩 / 达人内容 / 付费广告
                         ↓
        https://link.uniprism.cn/l/{link_id}
                         ↓
              后端记录推广点击事件
                         ↓
        尝试通过 HTTPS App Link 打开 App
                 ↓                 ↓
              已安装              未安装
                 ↓                 ↓
          打开 App 指定页面       下载落地页
                                   ↓
                         官方应用市场详情页
                                   ↓
                         安装并首次打开 App
                                   ↓
                  注册 → 测评 → 报告 → 支付
                                   ↓
                  后端记录来源和转化事件
                                   ↓
                         内部推广数据看板
```

注意：网页无法可靠判断 App 是否安装。正式方案应依靠 Android App Links 和 iOS Universal Links：已安装时由系统打开 App，未安装时显示下载落地页。

## 4. 正式 URL 规划（P0）

以下地址是建议值，域名确认后统一替换并上线。

| 用途 | 正式地址建议 | 说明 |
|---|---|---|
| 统一下载页 | `https://link.uniprism.cn/download` | 展示 Android、iOS 和电脑端下载方式 |
| 短推广链接 | `https://link.uniprism.cn/l/{link_id}` | 每个活动、达人和素材生成独立链接 |
| 打开首页 | `https://link.uniprism.cn/open/home` | 已安装打开首页，未安装进入下载页 |
| 打开测评 | `https://link.uniprism.cn/open/test?id=1001` | 打开指定测评 |
| 打开活动 | `https://link.uniprism.cn/open/activity?id=2001` | 打开指定活动 |
| 分享报告 | `https://link.uniprism.cn/share/report?token={share_token}` | 使用安全令牌，不暴露报告 ID |
| 隐私政策 | `https://uniprism.cn/privacy` | App、下载页和应用市场共用 |
| 用户协议 | `https://uniprism.cn/agreement` | App、下载页和应用市场共用 |
| 客服页面 | `https://uniprism.cn/support` | 联系方式、投诉和常见问题 |
| 退款规则 | `https://uniprism.cn/refund` | 付费报告退款说明 |

### 4.1 URL Scheme 备用地址

URL Scheme 只作为兼容备用，不直接作为对外推广链接：

```text
uniprism://home
uniprism://test?id=1001
uniprism://activity?id=2001
uniprism://share/report?token={share_token}
```

禁止使用含义不明确的 `app://`，也禁止在同一个项目中同时使用多个 Scheme 名称。

## 5. 下载落地页（P0）

### 5.1 页面功能

- [ ] 记录页面访问事件及推广参数
- [ ] 自动识别 Android、iOS 和桌面浏览器
- [ ] Android 展示对应官方应用市场入口
- [ ] iOS 展示 Apple App Store 入口
- [ ] 桌面端展示 Android/iOS 二维码
- [ ] 无法识别手机品牌时展示全部市场按钮
- [ ] 应用市场尚未上线时显示“即将上线”，不能跳转虚假地址
- [ ] 提供 App 名称、图标、版本、简介和更新时间
- [ ] 提供隐私政策、用户协议、客服和备案信息入口
- [ ] 支持抖音、小红书和 B站内置浏览器
- [ ] 页面加载失败时保留可复制的应用名称和官网地址

### 5.2 Android 跳转建议

优先顺序：

1. 能识别手机品牌时，展示对应品牌应用市场。
2. 不能识别时，展示华为、小米、OPPO、vivo、应用宝的选择列表。
3. 默认不直接下载 APK，避免来源不明安装、浏览器拦截和版本分散。
4. 如后续必须提供官网 APK，应单独经过安全、备案、升级和统计方案确认。

### 5.3 下载页统计边界

开发必须区分：

```text
landing_view       访问下载页
store_click        点击应用市场按钮
first_open         安装后首次打开 App
```

`store_click` 只能称为“应用市场跳转”，不能称为“下载人数”或“安装人数”。真正安装转化至少以 `first_open` 或广告平台确认的数据为准。

## 6. App 唤醒和内容路由（P0）

### 6.1 Android

- [ ] Flutter 集成并统一维护 Deep Link 处理模块
- [ ] Android 配置 HTTPS App Links
- [ ] 在域名部署 `/.well-known/assetlinks.json`
- [ ] 文件中配置正式包名和 Release 签名 SHA-256
- [ ] 配置正式域名的 Intent Filter
- [ ] 测试冷启动、后台运行和前台运行三种状态
- [ ] 测试链接参数缺失、错误和目标内容不存在的情况

### 6.2 iOS

- [ ] Flutter 集成并统一维护 Deep Link 处理模块
- [ ] Apple Developer 开启 Associated Domains
- [ ] Xcode 配置 `applinks:link.uniprism.cn`
- [ ] 在域名部署 `/.well-known/apple-app-site-association`
- [ ] 文件中配置 Apple Team ID 和 Bundle ID
- [ ] 注册 `uniprism` URL Scheme 作为备用
- [ ] 测试冷启动、后台运行和前台运行三种状态

### 6.3 App 内路由表

| route | HTTPS 示例 | App 目标页面 | 未登录处理 | 内容不存在处理 |
|---|---|---|---|---|
| `home` | `/open/home` | 兴趣探索首页 | 允许访客进入 | 返回首页 |
| `test` | `/open/test?id=1001` | 指定测评 | 按业务规则允许访客或要求登录 | 提示内容不可用并返回首页 |
| `report` | `/open/report?token=...` | 本人的报告或授权内容 | 先登录，登录后继续原目标 | 提示无权限或已失效 |
| `activity` | `/open/activity?id=2001` | 活动详情 | 允许浏览，参与时再登录 | 提示活动已结束 |
| `share_report` | `/share/report?token=...` | 脱敏报告分享页 | 网页可预览允许公开部分 | 提示链接失效 |

### 6.4 登录后的目标恢复

用户通过推广链接进入需要登录的页面时：

```text
保存原始目标路由
      ↓
进入登录页
      ↓
登录成功
      ↓
恢复原始目标路由
```

登录取消或登录失败时返回进入登录前的页面，不能直接退出 App，也不能丢失访客已有测评进度。

## 7. 推广链接生成规则（P0）

### 7.1 不允许手工拼接正式链接

正式推广统一使用短链接：

```text
https://link.uniprism.cn/l/7Ft2Qa
```

短链接在后端保存完整推广信息。这样可以修改落地目标、禁用错误链接，并避免将大量参数暴露给用户。

### 7.2 推广参数字典

| 字段 | 是否必填 | 说明 | 示例 |
|---|---:|---|---|
| `source` | 是 | 推广平台 | `douyin`、`xhs`、`bilibili` |
| `medium` | 是 | 推广方式 | `organic`、`paid`、`creator` |
| `campaign` | 是 | 活动编号 | `2026_summer` |
| `account` | 是 | 发布账号编号 | `official_01` |
| `creator` | 否 | 达人或 UP 主编号 | `creator_008` |
| `content` | 是 | 具体素材编号 | `video_003` |
| `target` | 是 | 打开目标 | `home`、`test`、`activity` |
| `target_id` | 否 | 目标业务 ID | `1001` |
| `platform_click_id` | 否 | 广告平台点击标识 | 平台回传值 |

不要只保存一个 `channel` 字段，否则无法区分同一平台的多个账号、达人、活动和素材。

### 7.3 链接记录表

后端至少保存：

```text
link_id
source
medium
campaign
account
creator
content
target
target_id
status
start_at
end_at
created_by
created_at
```

## 8. 来源归因（P0）

### 8.1 必须记录的三类来源

| 字段 | 定义 | 是否覆盖 |
|---|---|---|
| `first_touch` | 该访客第一次有效推广来源 | 不覆盖 |
| `last_touch` | 当前最近一次有效推广来源 | 新来源可覆盖 |
| `register_attribution` | 注册时采用的归因来源 | 注册完成后固定 |

付费订单还应保存订单归因快照，不能只依赖用户表上的当前渠道。

### 8.2 访客、登录用户和退出登录

- 未登录用户的推广来源和测评进度使用独立访客标识保存。
- 登录时，将本次访客来源和允许合并的访客行为关联到登录账号。
- 退出登录后恢复为新的或原有访客上下文，不能继续读取该账号的私有答题记录。
- 用户再次登录同一账号后，才重新读取该账号的服务端记录。
- 来源合并和答题进度合并必须分开处理，不能因为绑定渠道而泄露登录账号数据。

### 8.3 安装归因限制

用户从网页进入应用市场后，普通 URL 参数不一定能跨越安装过程保留下来。因此开发不能承诺仅通过 `?source=xhs` 就能得到准确安装归因。

正式方案分为：

1. 自然推广：记录落地页和市场点击，首次打开后尽可能通过合规方式关联；无法确定时标记为 `unknown`，不伪造来源。
2. 付费推广：根据巨量引擎、小红书聚光、B站广告后台的当期接入要求，配置应用、转化事件和合规的数据回传。
3. 达人合作：每个达人和每条内容使用独立 `link_id`，至少准确统计点击、市场跳转、注册和后续服务端转化。

## 9. 埋点和转化事件（P0）

### 9.1 核心事件

| 事件名 | 触发时机 | 关键属性 |
|---|---|---|
| `promotion_link_click` | 短链接被访问 | `link_id`、来源参数、时间、设备类型 |
| `landing_view` | 下载页有效展示 | `link_id`、系统、浏览器 |
| `store_click` | 点击某个市场 | `link_id`、`store`、系统 |
| `app_first_open` | App 首次启动 | App 版本、系统、归因结果 |
| `app_open` | App 启动或回到前台 | 版本、系统 |
| `register_success` | 注册成功 | 用户 ID、注册方式、归因快照 |
| `login_success` | 登录成功 | 登录方式，禁止上传密码或验证码 |
| `assessment_start` | 开始测评 | 测评 ID、用户/访客标识 |
| `assessment_stage_complete` | 完成一个阶段 | 测评 ID、阶段编号 |
| `assessment_complete` | 完成全部阶段 | 测评 ID |
| `portrait_view` | 展示人格画像 | 测评 ID、画像版本 |
| `report_view` | 查看报告 | 报告类型、是否付费 |
| `order_created` | 创建订单 | 订单号、商品、金额、归因快照 |
| `payment_success` | 服务端确认支付成功 | 订单号、支付渠道、实付金额 |
| `refund_success` | 服务端确认退款成功 | 订单号、退款金额 |
| `share_created` | 创建分享链接 | 分享类型、令牌 ID |
| `share_open` | 打开分享链接 | 分享令牌、来源 |

### 9.2 数据要求

- [ ] 同一事件有唯一 `event_id`，避免重复计算
- [ ] 客户端时间和服务端接收时间分开保存
- [ ] 支付成功和退款成功以服务端结果为准
- [ ] 金额统一使用最小货币单位，例如分
- [ ] 记录 App 版本、系统、设备类型和登录状态
- [ ] 不记录密码、验证码、身份证原文和完整支付凭据
- [ ] 用户拒绝非必要统计后，按隐私方案停止对应采集

## 10. 后端接口准备（P0/P1）

接口路径可根据现有后端规范调整，但能力必须保留。

### 10.1 解析推广链接

```http
GET /api/promotion/links/{link_id}
```

返回目标页面、有效期、状态及允许公开的推广信息。

### 10.2 记录推广事件

```http
POST /api/promotion/events
Content-Type: application/json

{
  "eventId": "uuid",
  "eventName": "store_click",
  "linkId": "7Ft2Qa",
  "anonymousId": "visitor_uuid",
  "userId": null,
  "platform": "android",
  "appVersion": "1.0.0",
  "properties": {
    "store": "huawei"
  },
  "occurredAt": "2026-07-21T10:00:00+08:00"
}
```

接口必须校验允许的事件名和属性，限制请求频率，并进行重复事件去重。

### 10.3 生成推广链接

```http
POST /api/promotion/links
```

仅允许内部授权账号调用，返回 `link_id`、短链接和二维码内容。

### 10.4 App 版本信息

```http
GET /api/app/version?platform=android&version=1.0.0&build=1
```

建议返回：

```json
{
  "latestVersion": "1.0.1",
  "latestBuild": 2,
  "minimumVersion": "1.0.0",
  "forceUpdate": false,
  "title": "发现新版本",
  "message": "修复已知问题并优化使用体验",
  "storeUrl": "https://正式应用市场详情页"
}
```

iOS 更新必须跳转 App Store；Android 默认跳转对应应用市场，不在 App 内静默安装更新包。

### 11.1 第一版支持范围

禁止：


建议：


## 12. 推广数据看板（P1）

### 12.1 查询维度

- 时间范围
- 平台 `source`
- 推广方式 `medium`
- 活动 `campaign`
- 发布账号 `account`
- 达人 `creator`
- 素材 `content`
- App 平台和版本

### 12.2 核心指标

```text
推广链接访问人数/次数
下载页访问人数/次数
应用市场跳转人数/次数
App 首次打开人数
注册人数
测评开始人数
测评完成人数
人格画像查看人数
付费人数
付费订单数
付费金额
退款人数和退款金额
```

### 12.3 转化率口径

```text
落地页到市场跳转率 = 去重 store_click / 去重 landing_view
首次打开率           = 去重 app_first_open / 去重 store_click
注册率               = 去重 register_success / 去重 app_first_open
测评完成率           = 去重 assessment_complete / 去重 assessment_start
付费转化率           = 去重支付用户 / 去重注册用户
退款率               = 退款订单数 / 支付成功订单数
```

首次打开率受应用市场和归因能力限制。分母、去重方式和归因窗口必须在看板中标明，不能将推测值显示为精确安装数据。

## 13. 抖音、小红书和哔哩哔哩技术准备（P1）

### 13.1 抖音/巨量引擎

公司或投放负责人需要先提供：

- 广告账户或企业账号主体信息
- 巨量引擎中创建的正式应用信息
- 广告账户 ID、应用 ID 等平台实际要求的标识
- 需要优化的转化目标，例如激活、注册、付费

开发拿到后：

- 按平台当期文档评估 SDK、API 或服务端事件回传方案
- 映射本项目事件与平台转化事件
- 在隐私同意后初始化非必要广告归因能力
- 使用测试广告或平台测试工具验证回传
- 记录平台返回的测试结果，不仅验证本地日志

### 13.2 小红书/聚光

公司或投放负责人需要先提供：

- 聚光企业广告账户
- 聚光后台创建的应用和转化目标
- 账户、应用及转化相关标识
- 平台审核或接入页面提出的技术要求

开发拿到后执行与抖音相同的事件映射、隐私检查、测试回传和验收流程。

### 13.3 哔哩哔哩

自然发布或花火达人合作至少使用独立推广短链接记录效果。若购买 B站广告，应由投放负责人从当前广告后台提供应用、账户、计划及转化对接要求，开发再按当期文档接入。

平台的账户入口、字段和技术要求可能调整，不能仅根据本文提前写死 SDK 名称和字段。

### 13.4 iOS 隐私要求

- 使用跨公司、跨 App 的广告追踪或特定第三方归因能力前，评估是否需要 ATT 授权。
- 用户拒绝 ATT 后不得采用设备指纹规避授权。
- 使用的 SDK、收集数据和用途必须与隐私政策及 App Store 隐私申报一致。
- 可优先评估 Apple 提供的隐私保护广告归因能力，但不能把它等同于所有渠道均可得到用户级归因。

## 14. 开发开始前需要别人提供什么

开发不能单方面完成全部推广准备。以下资料必须由公司、产品、运营或投放人员提供。

### 14.1 公司/产品提供

- [ ] 正式 App 名称、包名、Bundle ID 和 URL Scheme 的确认结果
- [ ] 正式域名及 DNS、HTTPS、服务器配置权限
- [ ] App 图标和品牌素材
- [ ] 隐私政策、用户协议、退款规则和客服地址
- [ ] 是否允许访客测评、分享哪些内容和登录恢复规则
- [ ] 归因窗口和首次/最近来源使用规则

### 14.2 应用市场负责人提供

- [ ] 华为详情页 URL

- [ ] 应用宝详情页 URL

- [ ] 各市场当前上架版本及发布时间

这些 URL 只有应用真正上架后才能成为正式链接。开发收到后写入链接配置后台，不硬编码到多个 App 页面。

### 14.3 推广/投放负责人提供

- [ ] 推广开始和结束时间
- [ ] 广告平台账户、应用及转化目标标识
- [ ] 平台审核反馈和当期技术接入要求
- [ ] 最终发布的笔记、视频、广告计划或达人作品地址

开发收到后生成正式短链接、二维码，配置平台转化并验证数据。

## 15. 开发完成后需要提供给运营什么

运营不需要拿到开发源码或内部密钥，但需要拿到能够直接用于组织推广的正式入口、规则、数据和说明。

### 15.1 开发提供给运营的正式内容

| 交付内容 | 开发需要提供什么 | 运营拿到后做什么 | 交付时间 |
|---|---|---|---|
| APP 统一下载入口 | 正式 HTTPS 下载页 URL | 放入推广内容、官网或二维码 | 应用市场链接确定后 |
| APP 唤醒入口 | 首页、测评、活动等 HTTPS 唤醒链接 | 根据推广目标选择对应链接 | App Links/Universal Links 验收后 |
| Android 市场地址 | 华为、小米、OPPO、vivo、应用宝详情页汇总 | 确认各市场可正常下载 | 各市场上架后 |
| iOS 下载地址 | Apple App Store 详情页 URL | 用于 iPhone 用户下载 | App Store 上架后 |
| 推广链接规则 | 参数字典、编号规则和禁止手工修改说明 | 提交活动、账号、达人和素材信息 | 链接系统完成后 |
| 活动专属链接 | 每个平台、活动、达人和素材的短链接 | 分配到对应推广内容 | 每次活动开始前 |
| 推广二维码 | 与每条短链接对应的二维码文件 | 用于图片、视频或线下展示 | 每次活动开始前 |
| 分享链接规则 | 哪些页面可分享、分享有效期和隐私限制 | 设计分享活动和用户引导 | 分享功能上线后 |
| 数据看板 | 地址、登录权限、筛选方式和指标口径 | 查看访问、注册、测评和付费效果 | 正式推广前 |
| 埋点说明 | 事件名、触发时机、数据延迟和限制 | 正确解释推广数据 | 正式推广前 |
| 当前可推广版本 | Android/iOS 版本号、发布时间、支持市场 | 避免推广尚未上线的版本或功能 | 每次版本发布后 |
| 测试结果 | 各平台内置浏览器、真机、唤醒和数据测试记录 | 确认可以开始投放 | 每次大版本推广前 |
| 故障处理方式 | 技术联系人、问题反馈模板和紧急停用链接方式 | 出现问题时快速反馈和暂停推广 | 正式推广前 |


### 15.3 运营拿到后需要返回给开发的内容

运营实际发布或投放后，应将以下信息返回给开发，用于校验来源和平台转化：

- [ ] 最终使用的是哪一条推广短链接
- [ ] 实际发布平台、账号、达人和素材编号
- [ ] 抖音视频、小红书笔记或 B站视频的正式地址
- [ ] 实际开始和结束时间
- [ ] 付费广告账户、计划、广告和创意标识
- [ ] 平台审核拒绝原因或技术接入提示
- [ ] 实际投放金额；仅在需要计算获客成本和 ROAS 时提供
- [ ] 运营发现的链接、下载、唤醒或数据异常

开发收到后：

1. 核对运营是否使用了正确的活动链接。
2. 检查落地页访问、市场跳转、注册和付费事件是否进入系统。
3. 付费投放时检查平台转化回传是否成功。
4. 将最终作品地址和广告标识补充到活动记录。
5. 出现错误时暂停或替换对应短链接，不影响其他活动。

为了能够持续向运营提供以上内容，开发内部需要逐步完成：

- 数据库、服务器和云平台主账号

## 17. 验收清单

### 17.1 下载与唤醒

- [ ] Android 已安装时 HTTPS 链接打开指定 App 页面
- [ ] iOS 已安装时 HTTPS 链接打开指定 App 页面
- [ ] 未安装时正常显示下载页
- [ ] PC 正常显示二维码
- [ ] 各应用市场按钮只使用真实上线地址
- [ ] 抖音、小红书和 B站内置浏览器完成真机测试

### 17.2 路由与账号

- [ ] 冷启动、后台和前台状态均能正确处理链接
- [ ] 未登录进入受保护页面时先登录，成功后恢复目标
- [ ] 登录取消后返回合理页面
- [ ] 退出登录后看不到登录账号的私有测评进度
- [ ] 链接参数错误或内容下架时有明确提示和返回路径

### 17.3 数据

- [ ] 每条推广链接能识别平台、活动、账号、达人和素材
- [ ] `landing_view` 与 `store_click` 分开统计
- [ ] 首次来源不被后续来源覆盖
- [ ] 最近来源可以按规则更新
- [ ] 注册和订单保存归因快照
- [ ] 重复上报不会重复统计
- [ ] 支付、退款金额与后端订单一致
- [ ] 数据看板明确显示口径和归因限制

### 17.4 隐私与安全

- [ ] 未取得必要同意前不初始化非必要广告追踪 SDK
- [ ] 隐私政策与实际 SDK、权限和数据一致
- [ ] 报告分享不暴露连续报告 ID
- [ ] 分享链接可失效和撤销
- [ ] 日志中没有密码、验证码、令牌和个人敏感信息
- [ ] 推广协作方无法取得签名私钥、支付密钥和用户原始数据

## 18. 当前建议的执行顺序

1. 公司确认包名、Bundle ID、URL Scheme 和链接域名。
2. 运维完成 `link.uniprism.cn` 的 DNS、HTTPS 和部署权限。
3. 开发先完成下载页、链接解析、App 路由和基础事件。
4. Android 配置 App Links，iOS 配置 Universal Links。
5. 后端完成短链接、事件接收和来源归因数据结构。
6. App 上架后补入真实应用市场 URL。
7. 完成分享、数据看板、版本更新和真机验收。
8. 确定付费推广平台后，再根据平台后台提供的真实参数完成转化对接。
9. 每次推广只需要新建活动、账号、达人和素材记录，不重复开发整套链路。

达到以上标准后，开发即可把正式下载入口、唤醒链接、活动短链接、二维码、参数规则、数据看板和使用说明交给运营。运营可以据此组织推广，并把实际发布地址、广告标识和异常情况返回给开发继续核验。
