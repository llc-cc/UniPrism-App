## 二、App 开发上线前准备

### 1. 产品和主体信息

- [ ] 正式 App 中文名称
- [ ] 英文名称（如需要）
- [ ] 主体公司全称、统一社会信用代码和营业执照
- [ ] 法定代表人、平台经办人及联系方式
- [ ] 客服电话、客服邮箱和联系地址
- [ ] 官网域名、域名持有人及与 App 主体的关系
- [ ] App 服务类目：教育类或其他类目
- [ ] 是否主要面向未成年人
- [ ] 是否收费，以及收费内容属于报告、会员、课程还是其他服务
- [ ] 是否需要教育等行业前置审批或资质

### 2. 技术身份

- [ ] Android 正式包名
- [ ] iOS Bundle ID（如本期上线 iOS）
- [ ] 正式 URL Scheme
- [ ] Android Release keystore、alias 和 SHA-256
- [ ] iOS Developer Team、证书和 Provisioning Profile
- [ ] 正式版本号、构建号和最低支持系统
- [ ] 正式生产域名、API 域名和静态资源域名
- [ ] App 图标、启动图和应用市场图标

签名文件、密码和证书只进入公司密码管理器或 CI/CD，不放入 Git、普通文档或运营资料。

### 3. 备案和资质

- [ ] 域名完成实名认证和 ICP 备案
- [ ] 确认 APP 备案接入服务商/云服务商
- [ ] 准备主体、负责人、域名、服务器、包名、签名证书等 APP 备案信息
- [ ] 确认服务类目和是否需要前置审批文件
- [ ] APP 备案申请提交并取得备案编号
- [ ] App 内显著位置展示备案编号并提供查询链接
- [ ] 软件著作权名称、App 名称和版本保持一致
- [ ] 准备软著申请表、源程序、说明文档和主体证明
- [ ] 取得软著证书或确认首发市场允许的替代权属材料
- [ ] 核查商标、名称授权和第三方图片/字体/内容授权

### 4. 隐私和用户权益

- [ ] 独立的隐私政策 HTTPS 页面
- [ ] 独立的用户服务协议 HTTPS 页面
- [ ] 个人信息收集清单
- [ ] Android/iOS 权限用途清单
- [ ] 第三方 SDK 名称、提供方、用途和隐私政策链接
- [ ] 首次启动隐私告知和明确同意/拒绝
- [ ] 未同意前不初始化非必要 SDK、不申请非必要权限
- [ ] 权限在实际使用场景中申请，并允许用户拒绝
- [ ] App 内可再次查看隐私政策和用户协议
- [ ] 账号注销入口和服务端删除流程
- [ ] 更正、删除个人信息和撤回授权的方式
- [ ] 未成年人保护与监护人同意方案（如适用）
- [ ] 客服、投诉和隐私联系人可用
- [ ] 隐私政策与实际接口、权限、SDK 和数据保存行为一致

## 四、建议执行顺序

1. 确认正式主体、App 名称、服务类目、收费方式和未成年人范围。
2. 确认正式包名、域名和签名，避免备案、软著和平台账号反复修改。
3. 同步办理 APP 备案、软件著作权、隐私文件和开发者平台账号。
4. 完成正式包、审核材料、真机测试和应用市场提交。
5. 上架后收集正式市场链接，再生成运营推广链接和二维码。
