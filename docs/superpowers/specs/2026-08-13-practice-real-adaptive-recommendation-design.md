# 练习真实画像推荐下一题 V1 设计

## 目标

学生每次提交后，后端使用真实长期能力画像、知识点掌握度、最近作答记录和候选题难度生成一条下一题推荐。App 只展示推荐卡并由学生主动进入，保留原题号导航；管理端展示同一次真实推荐的评分明细和原因。

第一版继续使用 `adaptive-rule-v1`，不训练或调用小模型。当前候选池是会话中的 19 道演示题；后续知识库只替换 `AdaptiveCandidateProvider`，推荐规则、学生 DTO 和 App 交互保持不变。

## 已确认交互

- 提交成功后，评分结果下方出现“推荐下一题”卡片。
- 卡片展示题号、题干、知识点和学生可理解的公开推荐理由。
- 学生点击“进入推荐题”后才切题，不自动跳转。
- 上一题、下一题和题号导航继续可用。
- 当前题已经是唯一候选或推荐生成失败时，不阻塞作答提交；页面不显示空卡片。

## 方案比较与选择

### 方案 A：把推荐快照作为 attempt 事实的一部分持久化（采用）

提交事务先完成判题、观察与画像更新，再从事务内最新画像和历史生成推荐，并把完整推荐快照写入本次 attempt facts。学生 DTO 只投影最小公开字段，管理端白名单投影完整评分。

优点是提交、画像和推荐使用同一状态，幂等重试稳定，管理端看到的就是当时真实结果。代价是提交事务多一次受限查询和 facts 更新。

### 方案 B：提交成功后临时计算但不保存

实现更短，但幂等重试或历史变化后推荐可能不同，管理端无法可靠复现当时分数，因此不采用。

### 方案 C：App 再调用独立推荐接口

会产生评分成功但推荐请求失败的双状态，而且容易让客户端上传能力分数，因此不采用。

## 后端边界

### 候选题提供器

`AdaptiveCandidateProvider` 接收当前会话试卷目录并返回 `AdaptiveCandidateQuestion[]`。默认实现从当前 19 题的已存六维难度、难度特征和 rubric 派生七维需求。提供器返回的 `questionId` 必须属于当前会话题目目录，保证 App 可以直接定位。

知识库接入时由新的提供器读取知识库候选，但仍输出同一结构；会话目录需要在创建会话时包含可被推荐的题目，App 不接触知识库查询规则。

### 能力映射

正式 V1 画像按以下稳定映射进入七维规则：

| 正式画像 | 选题维度 |
|---|---|
| READING | READ |
| UNDERSTANDING | COMP |
| EXPRESSION | REPR |
| TECHNIQUE | STRAT |
| CALCULATION | CALC |
| REASONING | PROOF |
| SELF_CORRECTION | CHECK |

只有 `evidenceCount > 0` 且 `displayBand != null` 才视为已观察；其他情况必须传 `null`，不得转成 0。

### 知识点掌握度

从参与者最近 50 次正式提交的题目知识点和结果派生 V1 掌握度：正确为 4、部分正确为 2、错误为 0，同一知识点取平均并记录 evidenceCount。没有作答证据的知识点保持 `null`。推荐优先使用最低的已观察知识点；若尚无知识证据，使用刚提交题目的知识点作为中性范围，不伪造低掌握度。

### 最近作答和难度

- 最近作答按服务端 `submittedAt` 倒序，最多 50 条。
- 当前刚提交题目从候选中排除。
- 同题、同结构近期出现继续使用现有 variety/transfer 惩罚。
- 题目难度和七维需求只从后端题库元数据取得，App 不上传。
- 60/20/20 十题周期继续按参与者总提交数决定。

### 推荐快照

attempt facts 新增 `adaptiveRecommendationV1`：

- 规则和需求版本；
- 生成时间、目标桶；
- 目标能力维度；
- 目标知识点、掌握档位和证据数；
- 被推荐题的完整 score breakdown、总分、原因和风险。

学生 DTO 新增 `nextRecommendation`，只含：`questionId`、`questionNumber`、`prompt`、`knowledgePoints`、`publicReason` 和 `ruleVersion`。不得返回能力档位、知识掌握分、内部评分项或风险。

## App 状态与页面

`AttemptAssessment` 增加可空的 `PracticeNextRecommendation`。Controller 不计算推荐，只保存服务端投影，并提供 `openCurrentRecommendation()`：按 `questionId` 在当前试卷定位并调用既有 `selectQuestion`。找不到题目时保留当前页并显示可重试错误，不能猜题号。

Mock 仓储只为 UI 验收返回明确标记的顺序推荐，不代表生产算法；Remote 模式只信任后端 DTO。

## 管理端

真实作答审查从已存 attempt facts 白名单读取 `adaptiveRecommendationV1`，增加“真实推荐决策”区：

- 推荐题与总分；
- 命中的目标能力和知识点掌握证据；
- 七项 score breakdown；
- 推荐原因、风险、规则版本。

不返回学生身份、会话 ID、答案或过程原文。没有旧推荐快照的历史 attempt 显示“该作答产生于推荐功能上线前”。

## 失败与幂等

- 推荐生成使用严格解析后的题库元数据；若候选为空，保存 `null` 并正常返回评分。
- 推荐写入与 attempt、观察、画像在同一串行事务中；失败整体重试，避免画像和推荐跨版本。
- 相同 `Idempotency-Key` 直接读取已存快照，不重新推荐。
- P2002/P2034 仍复用现有三次事务重试。

## 验收标准

1. App 请求不包含能力分数、知识掌握度或推荐权重。
2. 提交成功 DTO 有公开推荐，但不含 `totalScore`、`targetDimension` 或 `scoreBreakdown`。
3. `displayBand:null` 或零证据画像进入规则时仍为 `null`。
4. 当前题不被推荐；点击卡片进入推荐题，原导航仍工作。
5. 幂等重试返回相同推荐题和规则版本。
6. 管理端真实作答审查展示同一快照的评分明细，且响应不含答案、过程、身份或会话 ID。
7. 当前 19 题候选提供器可以被测试替身替换，规则函数和 App 无需修改。

## 已知限制

- 知识点掌握度 V1 仅由题目标签和结果保守派生，不等同于完整 BKT/IRT 知识追踪。
- 当前候选只限会话 19 题，知识图谱先修约束等知识库接入后补充。
- 推荐质量仍受三项 Benchmark 红色基线限制，第一版用于真实数据验证，不宣称已经得到最优学习顺序。
