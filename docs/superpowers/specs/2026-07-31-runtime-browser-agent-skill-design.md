# UniPrism 高校社区运行时 Agent + Skill 设计

## 1. 目标

在现有高校内容采集、清洗、审核和云数据库链路上增加一个真正运行在服务器上的浏览器 Agent。Agent 使用 DeepSeek 进行页面理解和行动决策，读取 UniPrism 专用 Skill，并通过本地 Chromium 自动搜索、打开、翻页和提取公开社区内容。

首期范围保持为：

- 学校：北京大学；
- 平台：知乎、百度贴吧；
- 维度：学校、专业、课程、就业、宿舍、食堂、社团；
- 所有首批社区内容必须经过人工审核，不能直接参与 App 问答。

本功能不依赖 Brave Search API，也不增加新的搜索服务 Key。

## 2. 技术选择

### 2.1 运行时 Agent

使用开源 `browser-use` Python 包提供运行时浏览器 Agent：

- `Agent` 负责循环执行“观察页面—模型决策—浏览器动作”；
- `ChatDeepSeek` 读取现有 `DEEPSEEK_API_KEY`，默认模型使用现有 `DEEPSEEK_DIALOGUE_MODEL`，未配置时回退为 `deepseek-chat`；
- 浏览器使用服务器已安装的 Chromium，不启用 Browser Use Cloud；
- 每个“平台 × 维度”是一个独立任务，首期共十四个任务；
- 任务串行执行，避免在当前 3.5 GB 内存服务器上同时启动多个浏览器上下文。

### 2.2 UniPrism 专用 Skill

新增项目内 Skill：

`skills/uniprism-university-community-crawler/SKILL.md`

Skill 是运行时 Agent 的约束和操作说明，不是仅供开发工具阅读的文档。Agent 每次执行前都必须完整加载 Skill，Skill 规定：

- 任务目标、学校、平台和维度；
- 应优先使用的平台公开搜索入口和可替代搜索路径；
- 如何判断页面与北京大学及当前维度是否相关；
- 如何打开结果、翻页、展开公开正文或公开评论；
- 广告、灌水、联系方式、重复表达和无关内容的初筛规则；
- 提交证据时必须提供的结构化字段；
- 页面被登录墙、验证码、访问拒绝或持续空结果阻塞时的停止条件；
- 禁止编造内容、禁止把搜索摘要当作原文、禁止提交未实际访问页面的内容。

## 3. 模块边界

### 3.1 Agent 配置

在 `Settings` 中新增以下环境变量：

- `COMMUNITY_AGENT_ENABLED`：是否启用运行时 Agent，默认 `false`；
- `COMMUNITY_AGENT_MODEL`：默认读取 `DEEPSEEK_DIALOGUE_MODEL`，否则为 `deepseek-chat`；
- `COMMUNITY_AGENT_MAX_STEPS`：单任务最大 Agent 步数，默认 40，最大 80；
- `COMMUNITY_AGENT_MAX_CANDIDATES`：单任务最多提交候选数，默认 30，最大 100；
- `COMMUNITY_AGENT_TASK_DELAY_SECONDS`：两个任务之间的间隔，默认 5 秒；
- `COMMUNITY_AGENT_BROWSER_HEADLESS`：默认 `true`；
- `COMMUNITY_AGENT_SKILL_PATH`：默认指向项目内专用 Skill。

`DEEPSEEK_API_KEY` 和可选的 `DEEPSEEK_BASE_URL` 继续从服务器环境读取，不写入源码、Skill、日志或数据库。

### 3.2 Skill 加载器

`community_agent_skill.py` 只负责：

- 解析并读取指定的 `SKILL.md`；
- 校验 Skill 名称和正文非空；
- 将学校、平台、维度、候选上限等运行参数安全填入任务模板；
- 不允许任务参数覆盖 Skill 中的安全边界。

Skill 缺失或无法解析时，整个 Agent 批次返回 `AGENT_SKILL_NOT_CONFIGURED`，不回退到没有约束的自由浏览。

### 3.3 Agent 执行器

`community_agent.py` 只负责：

- 创建 DeepSeek 模型适配器和本地 Chromium 浏览器；
- 为单个平台和单个维度创建 Agent 任务；
- 注册结构化证据提交工具；
- 收集 Agent 步数、访问页面、阻塞原因、候选数和最终状态；
- 在任务结束后关闭浏览器会话，避免后台残留进程。

Agent 不直接操作数据库，也不直接调用后端 Prisma。它只返回经过 Pydantic 校验的 `CommunityEvidenceCandidate`。

### 3.4 结构化证据工具

Agent 通过自定义工具 `submit_community_evidence` 提交候选，字段包括：

- `platform`；
- `dimension`；
- `url`；
- `title`；
- `text`；
- `published_at`；
- `engagement`。

工具端强制覆盖学校、平台和维度，避免模型把其他学校或其他任务的内容混入当前批次。候选必须满足：

- URL 属于当前平台允许的公开域名；
- 标题和正文非空；
- 正文中存在北京大学或可验证的北大上下文；
- 未包含联系方式等明显个人敏感信息；
- 单任务候选达到上限后拒绝继续提交。

### 3.5 任务编排

现有 `run_community_pilot` 增加发现模式：

- `agent`：使用 Browser Use Agent，首期默认模式；
- `search_api`：保留现有 Brave 适配器，但不再是必需配置；
- `legacy`：保留现有已发现 URL 的确定性抓取能力，便于回归和故障定位。

Agent 模式按以下顺序执行：

1. 知乎：学校、专业、课程、就业、宿舍、食堂、社团；
2. 贴吧：学校、专业、课程、就业、宿舍、食堂、社团；
3. 每个任务结束后先做内存内 URL 和正文指纹去重；
4. 所有任务完成后使用现有社区上传接口分批直传后端；
5. 后端继续执行格式规范、垃圾过滤、SimHash 去重、AI 分析和人工审核入队。

任何单任务失败都只记录该任务，不终止其他十三个任务。

## 4. 页面发现和浏览策略

Agent 可使用公开搜索页面和站内公开搜索入口发现内容，不需要用户预先提供帖子链接。Skill 为不同平台提供搜索词模板，例如：

- `北京大学 宿舍 真实体验 知乎`；
- `北京大学 计算机 就业 知乎`；
- `北京大学 食堂 北大吧`；
- `北京大学 社团 活动 贴吧`。

模型可以根据搜索结果改写关键词，但不得改变学校、平台和当前维度。Agent 可以：

- 打开搜索结果；
- 点击公开帖子；
- 展开公开可见内容；
- 滚动和翻页；
- 返回上一页并继续下一个结果。

出现以下情况时记录阻塞并结束当前任务：

- 页面明确要求登录后才能继续；
- 出现验证码；
- HTTP 403、429 或平台访问拒绝；
- 连续三个动作没有获得新内容；
- 达到最大步数或候选上限。

首期不实现验证码处理、登录自动化、代理 IP、指纹伪装或平台私有接口调用。

## 5. 数据和用户可见性

Agent 提交的候选仍进入现有社区证据链路：

```text
Agent 候选
  → 程序基础过滤
  → URL/正文去重
  → 社区内容清洗
  → DeepSeek 七维度分析
  → human_required
  → 管理端人工审核
  → 审核通过后才允许进入 App 检索
```

App 用户不会看到“正在爬取、清洗失败、没有内容、同步中”等内部状态。未审核内容不能作为回答来源。

用户名、头像、联系方式、账号主页和其他与高校评价无关的个人数据不进入候选模型。

## 6. 监控与日志

命令行和 systemd 日志按批次输出：

- 计划任务数；
- 已完成任务数；
- 被阻塞任务数；
- 失败任务数；
- Agent 总步数；
- 实际访问页面数；
- 候选提交数；
- 去重后数量；
- 上传、拒绝和失败数量。

上传批次元数据增加：

- `executionEngine: "browser-use-agent"`；
- `agentModel`；
- `platform`；
- `dimensions`；
- `taskCounts`；
- `blockedReasons`；
- `skillVersion`。

管理端继续只修改内容采集监控中心，通过现有批次和社区证据审核页面展示这些数据，不修改邀请码、用户统计或其他管理页面。

日志不得输出 DeepSeek Key、后端采集 Token、Cookie、完整请求头或个人联系方式。

## 7. 定时执行

现有 `uniprism-community-evidence.service` 改为执行 Agent 模式，并继续由现有 systemd timer 控制。

- 管理端高校自动采集总开关关闭时，定时任务安全跳过；
- 手动测试可以显式运行 Agent 命令；
- 定时器启停方式保持不变；
- 单次执行尚未结束时，不允许启动第二个相同批次；
- Agent 进程退出后必须关闭浏览器子进程。

## 8. 测试策略

### 8.1 单元测试

- Skill 缺失、格式错误和成功加载；
- 任务模板只允许替换指定变量；
- 十四个任务生成顺序正确；
- Agent 提交其他学校、错误平台、错误维度或非法 URL 时被拒绝；
- 候选数量上限生效；
- 单任务阻塞不影响后续任务；
- 未配置 DeepSeek Key 时返回明确状态且不启动浏览器；
- Agent 模式不读取 Brave Key。

### 8.2 集成测试

通过伪 Agent 驱动真实任务编排，验证：

- 候选经过现有上传接口；
- 同一 URL 和相似正文只保留一份；
- 上传结果进入人工审核状态；
- 运行统计包含完成、阻塞、失败和上传数量；
- 任一 Agent 会话结束后均执行关闭逻辑。

### 8.3 服务器冒烟测试

部署后先关闭定时器，手动运行北京大学贴吧“宿舍”单任务：

1. 确认 Agent 实际启动 Chromium；
2. 确认日志存在页面访问和 Agent 步数；
3. 确认候选直传云数据库；
4. 确认管理端社区证据页面出现待审核内容；
5. 确认 App 无法检索到未审核证据；
6. 手工审核数据质量后再决定是否开启完整十四任务定时执行。

## 9. 已知限制

- 使用网页搜索入口仍可能遇到登录墙、验证码、403、429 或页面结构变化；
- DeepSeek 的浏览器决策存在随机性，必须通过最大步数、候选上限、结构化工具和人工审核控制风险；
- Skill 能提高任务稳定性，但不能保证平台始终允许自动访问；
- 首期只验证北京大学、知乎和贴吧，其他学校和平台必须在首期数据质量通过后按相同注册机制逐步增加。
