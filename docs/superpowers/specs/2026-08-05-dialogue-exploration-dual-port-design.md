# 1.2 对话式发散提问双端口首版设计

状态：用户已确认“公共思维树引擎 + 教学/练习策略”，首版以 Mock 数据先验证大致效果

日期：2026-08-05

## 1. 产品定义

1.2 不是普通 AI 聊天框，而是一个围绕学生个人知识掌握程度运行的“发散式学习与思维过程引擎”。学生的提问、假设、错误思路、验证、回退和复述共同构成学习产物。

核心原则：

1. 主角是学生的提问和思路，系统回答只是继续思考的燃料；
2. 同一内核服务教学与练习，场景策略不同但思维证据统一；
3. 自适应首先依据学生对相关知识原子的掌握证据，其次才参考呈现偏好；
4. 错误思路不删除，必须保留“为什么不成立、退回哪里、后来怎么改”；
5. 模型诊断不能直接给学生定性，只能提出候选，由学生确认或修改；
6. 素材来自知识库允许范围，不在 1.2 内建设第二套内容库。

## 2. 两个复用端口

### 2.1 教学端口

```text
知识原子 / 种子问题 / 自由问题
→ 读取学生掌握快照
→ 选择切口与表达方式
→ 回答 + 素材 + 指向原理的反问
→ 学生深挖或旁散
→ 关键节点复述
→ 生成理解路径图、素材偏好证据和记忆候选
```

适配规则：

- 低掌握：先补前置与定义，优先图、互动、分步公式；
- 中掌握：检查成立条件、概念边界、不同表征转换；
- 高掌握：减少基础解释，进入推导、变式、反例与应用；
- 无数据：明确使用未知档，不假装已经了解学生；
- 历史呈现偏好只能影响同等有效内容的选择，不能覆盖掌握证据。

### 2.2 练习端口

```text
题目
→ 学生给出初始思路或问题
→ 系统追问依据与成立条件
→ 学生继续推理
→ 验证当前步骤
→ 可行：继续
→ 不可行：沿思路找到首个矛盾点
→ 系统提出卡点诊断候选
→ 学生确认或修改
→ 标记错误路径并回退到上一个有效节点
→ 新建解法分支
→ 生成做题思维过程图与掌握证据
```

首版诊断类型：

- 概念不熟；
- 成立条件不清楚；
- 方法不会选择；
- 推理步骤断裂；
- 计算能力不过关；
- 题意理解偏差；
- 暂时不确定。

候选诊断带 `suggestedBySystem` 和理由。只有学生确认/修改后的 `confirmedByStudent`，或规则验证产生的 `verifiedByStep`，才可以进入正式掌握证据；未确认的模型判断只保存在过程图中。

## 3. 公共思维树

### 3.1 节点类型

- `studentQuestion`：学生提问；
- `studentHypothesis`：学生提出解法或假设；
- `tutorResponse`：系统解释和反问；
- `reasoningStep`：可验证的推理步骤；
- `diagnosis`：卡点候选或确认结果；
- `reflection`：学生复述和收口；
- `backtrack`：从错误路径回到有效节点的显式记录。

### 3.2 节点状态

- `exploring`：正在探索；
- `validated`：已验证可行；
- `contradicted`：出现矛盾或条件不成立；
- `abandoned`：学生主动放弃；
- `backtracked`：已回退并从其他分支继续；
- `completed`：形成有效结论。

### 3.3 分支与回退

普通继续追加到活跃叶；只有学生显式“从这里继续探索”或练习回退后选择新方法，才创建新分支。回退不能删除节点：错误分支保留，新增 `backtrackTargetNodeId` 指向恢复点，随后从该节点创建新分支。

首版限制：单会话最多 40 个节点、单路径最多 6 层、单节点最多 8 个直接分支。达到上限时允许保存、导出、复述和转记忆项，不再继续增长。

## 4. 学生掌握快照

```dart
final class StudentMasterySnapshot {
  const StudentMasterySnapshot({
    required this.atomId,
    required this.level,
    required this.recentEvidence,
    required this.misconceptionTags,
    required this.preferredMaterialKinds,
    required this.observedAt,
    required this.source,
  });
}
```

首版通过 `StudentMasteryRepository` 返回三种 Mock 学生档位：基础薄弱、中等、掌握较好。页面提供档位切换，仅用于展示相同问题在不同掌握程度下的回答与素材变化。

正式接入后快照来自 M2/M3 事件聚合。1.2 不自己计算一个新的“综合掌握度”，也不根据单次模型判断覆盖历史状态。

## 5. 素材调度

四类素材：

- figure：结构、对比、空间关系；
- video：过程、变化和现象，首版明确标注模拟视频；
- interactive：学生可操作参数或白板；
- formula：形式化结论与推导块。

调度输入包括场景、当前原子、关系边、学生掌握档位、当前节点意图和允许素材 ID。单回答最多 2 个素材。

硬约束：

1. 素材 ID 必须在当前原子及允许关系边范围内；
2. 没有必要时允许纯文字，不为装饰配图；
3. interactive 必须可操作；
4. 练习端口素材应服务于验证或补救，不能提前泄露完整答案；
5. 所有调用记录素材 ID、选择原因和对应节点。

## 6. 反问与发散控制

每条成功回答至少包含一个指向底层原理、适用条件或计算依据的反问，例如：

- “这一步使用了哪个结论？”
- “这个结论成立需要哪些条件？”
- “如果参数符号改变，刚才的判断还成立吗？”
- “你能指出不等式方向发生变化的那一步吗？”

禁止使用“你觉得呢”“还有吗”作为独立反问。

教学策略根据掌握程度决定补前置、深挖或旁散；练习策略根据当前步骤决定继续验证、提出诊断候选或触发收口。

## 7. 输入与输出接口

### 7.1 输入端口

- `ExplorationContentRepository`：原子、关系边、种子问题、练习题、素材；
- `StudentMasteryRepository`：学生的原子掌握快照；
- `ExplorationGateway`：回答、反问、诊断候选与素材引用；
- `ExplorationWhiteboardLauncher`：打开 3.3 白板或 Mock 白板；
- `ExplorationTraceRepository`：保存/读取思维过程图。

### 7.2 输出端口

- `MasteryEvidenceSink`：只接收确认或规则验证的掌握证据；
- `MemoryCandidateSink`：把勾选节点转成未来 M2 可消费的候选；
- `InterestEvidenceSink`：记录主动提问深度/广度，来源标记为行为观察；
- `ExplorationEventSink`：素材调用、分支、回退、诊断与复述事件。

所有端口首版使用进程内 Mock；页面和控制器不读取 fixture 常量。

## 8. 首版三个演示场景

### 8.1 二次函数教学

- 起点：“二次函数的顶点为什么在这里”；
- 基础薄弱档：先解释坐标、开口与顶点概念，调用图和互动；
- 中等档：连接一般式与顶点式，调用公式和互动；
- 掌握较好档：进入配方法、参数变化与真实应用；
- 支持深挖、旁散、复述、导出和转记忆候选。

### 8.2 证明不等式练习

- 提供一道首版固定题目；
- 学生可先选一条错误方法；
- 系统不立即给答案，而是追问适用条件；
- 沿错误方法走到首个条件矛盾点；
- 系统建议“方法选择不合适/条件不成立”，学生确认或修改；
- 错误分支标记为 contradicted，回退到上一个 validated 节点；
- 新建正确解法分支并完成复述；
- 输出完整做题思维过程图。

### 8.3 business model Demo

- 根问题：“一家咖啡店怎么赚钱”；
- 可往收入、成本、定价、渠道、护城河、单位经济模型发散；
- 固定验收路径至少 3 层、2 次主动旁散、3 类素材；
- 全程无空泛反问。

## 9. 首版页面

独立“1.2 对话探索实验室”包含：

1. 场景选择：教学 / 练习 / business model；
2. Mock 学生掌握档位选择；
3. 原子、问题库、自由输入三个入口；
4. 对话与素材区；
5. 可折叠思维树；
6. 节点详情、分支、验证、诊断确认和回退动作；
7. 复述、保存、导出和转记忆候选；
8. 事件与证据调试视图；
9. “测试数据，退出实验室后清空”提示。

手机端树使用抽屉/底部面板，宽屏使用右侧面板。首版优先保证功能可操作和状态清楚，不追求最终视觉稿。

## 10. 首版不伪造的能力

- 不调用正式 AI；回答和诊断走确定性 Mock；
- 不接正式 1.1 知识库；素材和关系边来自 fixture；
- 不接正式学生画像；掌握快照用三档 Mock；
- 不接正式 3.3 白板；只提供可拖动参数的 Mock 白板；
- 不持久化到设备或服务端；退出实验室后清空；
- 不自动评价学生提问质量；只记录深度、广度和主动分支；
- 不实现真实视频、语音识别、手写识别和生产级树布局；
- 不实现 John Zheng 的协作流程，只保留策略版本接口并完成 business model 契约 Demo。

## 11. 验收

- 教学端口在三种掌握档位下产生可见的解释/素材差异；
- 练习端口能走完错误思路、发现矛盾、确认诊断、回退和新分支；
- 错误路径在最终树中仍然可见；
- 候选诊断未确认前不进入 `MasteryEvidenceSink`；
- 三个入口都能启动教学探索；
- 一次典型会话调用至少 2 次且至少 2 类素材；
- 所有互动素材可真实操作；
- 素材不越出允许范围；
- 每条回答有原理/条件反问且无“你觉得呢”空反问；
- 树可回溯、折叠、重开分支、保存和导出；
- 节点可转为幂等记忆候选；
- business model 达成 3 层、2 次旁散、3 类素材；
- 小屏无横向溢出，加载、失败、空态和重试可见；
- 单元、Widget 和完整流程测试通过。

## 12. 优化顺序

首版跑通后按实际问题优化：

1. 先修状态错误、证据误写和回退逻辑；
2. 再优化反问质量、诊断准确性和素材匹配；
3. 再优化树布局、动效和移动端操作；
4. 最后接正式知识库、学生掌握数据、AI Skill、白板和服务端存储。
