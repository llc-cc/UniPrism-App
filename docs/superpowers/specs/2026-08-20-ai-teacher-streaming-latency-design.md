# AI 老师流式回答与延迟观测设计

## 目标

将网页端 AI 老师从“等待完整回答后一次性显示”改为“2～3 秒内开始显示正文”。完整教学结果仍需经过结构化校验和持久化后才改变学习进度、历史记录与巩固验证状态。

验收指标：

- 暖机后的正常请求，首段可见正文 P50 不高于 2 秒，P90 不高于 3 秒。
- 每次请求都能区分知识查询、MiniMax 首字、MiniMax 完成、持久化与总耗时。
- 流式失败不会留下半完成的教学节点，也不会重复提交同一轮。
- 原非流式接口继续可用，便于不支持流式的客户端回退。

## 方案选择

采用“新增流式端点 + 保留原端点”的渐进方案。后端通过 MiniMax Anthropic 兼容接口的 SSE 数据流获得文本增量，并向客户端转发经过协议封装的事件；Flutter Web 逐段更新老师消息。模型结束后，后端解析和校验完整 JSON，再一次性提交教学状态。

不采用只缩短提示词的方案，因为它无法解决前端必须等待完整响应的问题；也不采用先显示本地模板回答的方案，因为它会让用户误以为模板内容来自 AI 老师。

## 接口与事件协议

新增：

`POST /api/learning-sessions/{id}/turns/stream`

请求体沿用现有 `/turns` 请求体和幂等键。响应类型为 `text/event-stream`，事件包括：

- `metadata`：请求追踪 ID 与模型名，不含敏感提示词。
- `answer_delta`：可立即展示的老师正文增量。
- `committed`：完整结构化教学结果，数据形状与当前 `/turns` 成功响应一致。
- `error`：稳定错误码、可展示消息以及是否允许回退。
- `done`：流正常关闭。

为了避免把尚未闭合的 JSON 直接显示给学生，模型提示词将可见回答放在固定的 `answer` 字段首部；服务端使用增量 JSON 字符串提取器，只在确认位于 `answer` 字符串内时发送解码后的字符。完整响应仍使用现有 schema 解析器校验。

## 后端数据流

1. API 层完成鉴权、限流、请求校验和幂等检查。
2. Session Service 读取会话、解析知识边界和允许素材。
3. Learning Model Client 以 `stream: true` 请求 MiniMax，并记录请求开始、响应头、首个正文增量和结束时间。
4. API 将合法的 `answer` 增量作为 `answer_delta` 发送给客户端。
5. 模型完成后，Dialogue Engine 对完整 JSON 执行现有校验、教学决策和素材约束。
6. Repository 一次性持久化节点、历史记录和流程状态。
7. API 发送 `committed` 与 `done`。

任何解析、校验或持久化失败都不提交部分状态。若失败发生在首字前，客户端可以自动回退一次到原 `/turns`；若已经显示部分正文，则保留文字并展示重试提示，不自动重复生成，避免产生两份不同答案。

## 前端状态

Remote Exploration Gateway 新增流式提交方法，输出强类型事件流。Controller 管理以下状态：

- `connecting`：请求已发出、尚未收到正文。
- `streaming`：正在追加老师正文。
- `committing`：正文结束，等待结构化结果落库。
- `completed`：用 `committed` 数据替换临时消息并刷新学习状态。
- `failed`：保留已显示内容，允许用户明确重试。

页面只负责渲染状态。临时老师消息使用稳定的 client trace ID，收到 `committed` 后原位替换，避免出现重复历史卡片。用户提交期间保持单轮锁定，但允许滚动和查看已输出内容。

## 性能观测

服务端日志以同一 trace ID 输出：

- `knowledgeMs`
- `modelHeadersMs`
- `modelFirstAnswerDeltaMs`
- `modelTotalMs`
- `persistenceMs`
- `totalMs`
- `inputTokens`、`outputTokens`、模型名和完成原因

响应同时提供不含敏感信息的 `Server-Timing`。日志不得记录密钥、系统提示词、学生原文或模型完整回答。

开发环境为跨端口访问时，OPTIONS 响应增加合理的 `Access-Control-Max-Age`；生产环境优先同源部署。普通老师回答的 `max_tokens` 从 1200 调整为 500，并在提示词中限制正文与追问长度。结构化响应超过限制时按现有错误路径处理，不静默截断入库。

## 测试

后端 Vitest 覆盖：

- MiniMax SSE 分片跨 JSON 转义边界时仍能正确提取 `answer`。
- 首段正文立即发送，完整校验前不持久化。
- 校验或持久化失败不产生半完成节点。
- 幂等重试不生成重复节点。
- 计时字段存在且不包含敏感内容。
- 原非流式端点保持兼容。

Flutter 测试覆盖：

- 收到多个 `answer_delta` 时同一老师气泡逐步增长。
- `committed` 原位替换临时消息并更新历史及教学状态。
- 首字前失败只回退一次；首字后失败不自动重复生成。
- 页面销毁或请求取消后不再更新状态。

完成后运行相关 Vitest、Flutter controller/API/widget 测试与静态分析，并通过一次本地浏览器端到端请求核对首字和完整耗时。

## 发布与回退

流式端点通过客户端能力选择启用；原 `/turns` 保持不变。若线上发现流协议兼容问题，可让客户端恢复调用原端点，无需回滚数据库。此改动不新增数据表，不改变现有教学节点结构。
