# 教学助手学生端完整实施设计

状态：待产品、教研、客户端、后端与算法联合评审

依据：《教学助手 · 学生端功能文档》（2026-08-05，M1–M4 v1/v2）

适用范围：UniPrism Flutter 学生端、UniPrism Discover、教学内容后台及配套服务

目标：把产品功能文档转换为不遗漏功能、数据、接口、状态、失败路径和验收步骤的工程实施基线。

## 1. 文档定位

本文是总实施设计，不是单次迭代的代码任务清单。它负责：

1. 完整保留原需求中的 M1、M2、M3、M4、H 及候选功能；
2. 明确各功能前端、后端、算法、教研和运营分别实现什么；
3. 统一知识原子、记忆状态、能力状态、学习事件和兴趣证据的数据口径；
4. 固化模块依赖，禁止在上游数据未成立时伪造下游能力；
5. 给出分期、测试、监控、迁移和上线门槛；
6. 作为后续各阶段实施计划的唯一需求索引。

本文不承诺一次版本上线全部能力。完整范围按依赖拆成多个可验收阶段，但任何后置能力都必须在覆盖矩阵中保留，不能因为暂缓而消失。

## 2. 当前工程基线

### 2.1 Flutter 已有资产

- `lib/main.dart` 已有登录、兴趣测评、Agent、知识森林、报告、消息和专业体验路由；
- `lib/assessment.dart` 已有五阶段兴趣测评及专业候选收敛流程；
- `lib/professional_experience.dart` 已接入数学专业介绍和课程体验 API，但模型仍以数学专用类型为主；
- `lib/agent_experience.dart` 已有 Agent 对话、来源卡片和知识提炼入口；
- `lib/knowledge_models.dart`、`lib/knowledge_forest.dart`、`lib/knowledge_service.dart` 已有知识候选、确认、主题树和思维导图适配；
- `reactive_mind_map: 1.2.2` 可复用于课程子图和提问树的首版只读展示，但不得直接充当领域模型。

### 2.2 当前缺口

- 当前主页信息架构仍以兴趣探索和专业体验为主，不具备 H.1 今日主线；
- 知识森林当前主要服务个人知识提炼，且测试版为进程内状态，不能替代正式教研知识库；
- 当前 Flutter 代码大量使用 `part of 'main.dart'`，新增教学模块时必须按功能边界拆文件，避免继续扩大单文件职责；
- 当前 App 仓库内的 `.backend_patch` 是暂存后端材料，不代表教学知识库、复习、练习和推荐服务已经部署；
- UniPrism Discover 的主要兴趣和专业资产位于独立后端/前端代码库，M4 必须通过稳定 API 集成，不能复制一份静态数据到 Flutter。

## 3. 全局产品与工程原则

### 3.1 单一数据真相

1. M1–M4 共用同一套 `atom_id`，不允许各模块另建知识点 ID；
2. 背诵材料、闪卡和错题本共用 `memory_item`，只是不同视图；
3. 能力分 `theta` 与记忆稳定度 `stability` 永远分开；
4. 只有无帮助作答才能更新能力分；有提示、游戏、讲解和学习态只更新接触、记忆或兴趣证据；
5. AI 输出只能生成候选，不得直接改变知识结构、题目审核状态、学生正式画像或段位；
6. 任何可展示的学生结论都能追溯到具体事件、题目、审核内容版本和计算版本。

### 3.2 首期范围决策

首期采用“单学科、单主题、完整闭环”而不是按模块横向铺开。

推荐试点：高中数学“函数与二次函数”，首批 30–50 个概念原子。原因：

- 能覆盖课程图、定义/例子/原理、公式与辨析卡；
- 能用函数图像完成首版结构化白板；
- 能用 G2 参数调节验证理科游戏机制；
- 能产生顶点/零点、解析式/图像、定义域等典型错因；
- 能连接现有数学专业体验和 Project 资产。

如果项目首要目标改为验证 M3 错因诊断，则试点切换为高中物理受力分析。两者只能选择一个作为首条生产流水线，禁止并行启动两套教研生产。

### 3.3 v1 明确不做

- 不做学生排行榜、班级榜、好友榜和百分位；
- 不做正式段位承诺；
- 不做完整 Galgame、立绘和全分支剧情引擎；
- 不做全学科自由手绘识别；
- 不让语音识别直接无确认提交正式答案；
- 不接入尚未稳定的 Discover Agent 长期记忆系统；
- 不展示复习积压总数，不做断签清零；
- 不把游戏成绩直接写入能力分；
- 不把受版权保护的教材、教辅、题库原文或插图入库。

### 4.1 Flutter 分层

建议新增目录：

```text
lib/
├─ core/
│  ├─ api/
│  ├─ auth/
│  ├─ events/
│  └─ widgets/
├─ features/teaching_home/
├─ features/preview/
├─ features/review/
├─ features/practice/
├─ features/career_slices/
├─ features/learning_dashboard/
└─ features/whiteboard/
```

每个 feature 内按 `models / service / controller / pages / widgets` 拆分。页面只管理展示和局部交互；网络协议解析放 Service/Model；调度、归因和推荐必须由服务端决定。

### 4.2 后端分层

后端按业务域拆分：

- Repository：数据库读写和版本条件；
- Domain Service：单领域规则，如 FSRS 更新、图谱校验、步骤对齐；
- Flow Service：跨领域编排，如完成练习后同时更新能力、记忆和今日主线；
- API Route：鉴权、参数校验、限流和响应转换；
- Worker：内容生成、曲线监控、难度校准、画像证据同步等异步任务。

## 5. 统一领域模型

### 5.1 教研知识与内容

| 实体 | 关键字段 | 用途 |
|---|---|---|
| `CurriculumView` | curriculum、grade、subject、atom_order | 教材版本到公共原子的视图映射 |
| `ConceptAtom` | id、statement、conditions、principle、status、version、source_rights | 唯一概念事实底座 |
| `AtomExample` | atom_id、kind、representation、content_ref | 至少 3 正例和 1 边界例 |
| `AtomEdge` | source、target、kind、strength、reviewers | 六类关系边 |
| `TeachingAtom` | atom_id、mode、body_ref、figures、media、suits | 同一概念的不同讲法 |
| `QuestionAtom` | atom_ids、difficulty_prior、load_vector、cognitive_load、expected_time | 题目及测量属性 |
| `SolutionGraph` | question_id、paths、checkpoints、equivalence_rules | 多解路径与步骤对齐 |
| `ErrorMap` | question_id、pattern、cause、confidence | 典型错误到错因映射 |
| `AnchorSet` | subject、level、questions、version、exposure_policy | 段位锚题及隔离策略 |
| `TeachingAsset` | type、atom_scope、rights、interactive_contract | 图、视频、交互和公式卡 |

`ConceptAtom` 必须增加：

- `memory_items[]`：派生记忆项及起始阶梯；
- `mnemonic_allowed`：默认 `false`；
- `material_block_ref`：成块材料引用。

### 5.2 记忆与复习

| 实体 | 关键字段 | 用途 |
|---|---|---|
| `MemoryItem` | atom_id、prompt、answer_points、level、source_kind | 可独立判定的最小记忆单元 |
| `MaterialBlock` | title、ordered_item_ids、full_content_ref | 保留文章、公式表或时间线的上下文 |
| `StudentMemoryState` | D、S、R、current_level、due_at、last_event_id | FSRS 状态与记忆阶梯 |
| `ReviewSession` | recipe、estimated_minutes、item_ids、status | 一组 5–8 分钟复习 |
| `ReviewResponse` | item_id、result、hint_level、latency、自评采分点 | 单项复习证据 |

### 5.3 练习、白板与能力

| 实体 | 关键字段 | 用途 |
|---|---|---|
| `PracticeAttempt` | question_id、mode、helped、status、started_at | 一次学习态或评估态作答 |
| `AttemptStep` | sequence、input_mode、semantic_object、raw_ref | 结构化步骤流 |
| `WhiteboardSnapshot` | attempt/message、object_delta、version | 可回放白板状态，不重复存整图 |
| `HintEvent` | level、reason、requested_by_user | 提示使用记录 |
| `DiagnosisResult` | first_failure_step、cause、dimension_weights、confidence | 单次错因诊断 |
| `StudentAbilityState` | dimension、theta、RD、evidence_count、updated_at | 七维能力及置信度 |
| `ItemCalibration` | beta_vector、a、L、t、model_version | 题目难度与认知负荷 |
| `RankAward` | subject、rank、anchor_set_version、awarded_at、state | 棘轮式段位事实 |

### 5.4 兴趣、专业与主页

| 实体 | 关键字段 | 用途 |
|---|---|---|
| `CareerSlice` | source_kind、source_id、duration、completion_rule | 专业名片、一关挑战或任务卡切片 |
| `AtomApplicationLink` | atom_id、kind、ref、relation、strength | 知识点到应用的反向索引 |
| `InterestEvidence` | source、fact_type、canonical_tags、confidence | 明确区分表达、观察、测评和推断 |
| `CrossProductProgress` | content_id、completed_step、version | Discover 与教学助手单调合并进度 |
| `DailyAction` | kind、reason、duration、priority、source | H.1 今日行动 |
| `GrowthEvent` | verified_behavior、points、cosmetic_unlock | H.3 非能力型激励 |

### 5.5 不可变学习事件

所有状态由事件重算，状态表只是投影。首版事件类型至少包括：

- `atom_opened`、`atom_completed`、`prerequisite_remediation_started`；
- `question_asked`、`dialogue_branch_created`、`material_opened`、`tree_node_saved`；
- `game_started`、`game_failed`、`game_completed`、`independent_check_completed`；
- `review_session_selected`、`review_item_answered`、`review_session_interrupted`、`review_session_completed`；
- `practice_started`、`attempt_step_submitted`、`hint_requested`、`attempt_completed`；
- `diagnosis_accepted`、`diagnosis_review_requested`、`teacher_diagnosis_confirmed`；
- `career_slice_opened`、`career_slice_completed`、`application_link_dismissed`；
- `profile_fact_corrected`、`profile_fact_locked`；
- `daily_action_opened`、`daily_action_completed`。

每条事件包含：`event_id`、`user_id`、`session_id`、`client_trace_id`、`occurred_at`、`content_version`、`algorithm_version`、`payload`。客户端使用幂等键重试，服务端不得因网络重试重复更新状态。

### 6.3 响应和错误

统一响应包含 `ok`、`data`、`traceId`；错误包含稳定 `code`、用户可读 `message` 和是否可重试的 `retryable`。

关键错误码：

- `CONTENT_NOT_APPROVED`：内容未通过审核；
- `CONTENT_VERSION_CHANGED`：作答期间内容版本变化；
- `PREREQUISITE_REQUIRED`：前置原子未满足；
- `ATTEMPT_CONFLICT`：多设备并发提交；
- `STEP_UNPARSABLE`：步骤无法结构化；
- `DIAGNOSIS_INCONCLUSIVE`：证据不足，需要区分题；
- `REVIEW_SESSION_EXPIRED`：会话配方已失效，重新采样；
- `CAREER_PROFILE_UNLINKED`：跨产品账号未绑定；
- `RATE_LIMITED`：对话或模型调用限流。

## 7. M1 预习实现

## 7.1 1.1 课程介绍与学习过程编排

### 7.1.1 后台生产步骤

1. 导入公开课标条目，建立 `CurriculumView`；
2. AI 仅生成概念原子草案；
3. 学科组长按可判定性、教学动作唯一性、非退化性裁剪；
4. 构建 `PREREQUISITE_OF / ENABLES / EQUIVALENT_TO / CONTRASTS_WITH / APPLIED_IN / GENERALIZES_TO`；
5. 执行无环、孤立点、深度、对称边、跨学科会签和强度分布校验；
6. 冻结结构层版本；
7. 为每个原子生产定义、成立条件、至少 3 个不同表征正例、至少 1 个边界例和具体原理；
8. 生产 4–7 个教学原子并填写 `suits`；
9. 生产题目、解法图、error_map 和载荷 `w`；
10. 审核通过后进入 `pilot`，积累 100–300 次有效作答；
11. 指标正常进入 `approved`，异常进入 `quarantine`；
12. 所有变更先生成影响分析，再决定迁移、重挂或下线。

### 7.1.2 学生端步骤

1. 进入课程，获取本节子图而不是一次加载全学科图；
2. 默认聚焦当前原子，展示预计时长、训练能力和“为什么学”；
3. 用真实前置边显示递进关系，不按目录伪造关系；
4. 合并 M2/M3 状态，显示已掌握、需回补、未开始，但不展示羞辱性红色积压；
5. 前置不足时打开回补页，并保存 `return_token`；
6. 回补完成后返回原位置；
7. 服务端按 `suits` 选择图文、视频、互动或推导，不由客户端自行猜测；
8. 完成原子后记录停留、素材选择和理解确认；
9. 根据编排进入 1.2、1.3、M3 学习态或下一个原子；
10. 课程结束生成可复述的能力总结，不只展示完成百分比。

### 7.1.3 管理后台状态机

```text
draft → in_review → pilot → approved
  ↑        │          │        │
  └─驳回───┘          └异常→ quarantine
approved ─变更/课标调整→ deprecated
```

- AI 只能创建和修改 `draft`；
- 常规内容需要学科专家一审和适龄性复核；
- 定理证明、实验安全、正式测评和竞赛内容双人独立审核；
- 结构变更需要学科组长和影响报告；
- 跨学科边需要双方会签；
- `quarantine` 内容立即停止新投放，但历史事件保留。

### 7.1.4 监控与失败处理

- 前置图有环：阻断提交；
- 原子孤立：告警并禁止批准；
- 素材丢失：降级到同原子的其他教学原子；
- 学习曲线不下降：自动隔离并进入复核；
- 内容版本更新：正在学习的会话固定旧版本，下一会话使用新版本；
- 学生状态缺失：显示未知起点，安排低风险诊断，不假定已掌握或未掌握。

## 7.2 1.1 附：教研知识库与外部资源

### 7.2.1 三层责任

- 结构层：资深教研负责，AI 可起草不可采纳；
- 内容层：教研与 AI 协作，必须通过事实、公式、查重和适龄验证器；
- 判定层：教研标注、模型辅助、真实数据校准。

### 7.2.2 版权分级

- C0：课标、考纲、政府公开文件，可使用；
- C1：定理、定律、方程式等事实，可使用，表达需自有；
- C2：教材/教辅讲法，仅进入物理隔离的参考池，独立起草并查重后进入审核；
- C3：受保护题目原文、插图和习题册，不得入库和分发。

每个内容版本必须保存来源、权利等级、获取时间、允许用途和审核人。C3 在采集入口直接拒绝，不能依赖后续人工发现。

### 7.2.3 批量能力

- 按课标批量导入草案；
- 按学科、学段和状态筛选；
- 批量导入关系边并检测冲突；
- 能力维度变更后批量重标载荷；
- 导出教师可读知识地图；
- 批量操作必须预览影响、二次确认、记录操作者和可恢复版本。

## 7.3 1.2 对话式发散提问

### 7.3.1 两个入口

1. 从 1.1 当前原子进入，系统使用教研钩子问题；
2. 从问题库或自由输入直接进入，服务端先判定学段、相关性和安全边界。

### 7.3.2 单轮实现步骤

1. 保存用户问题并创建稳定节点 ID；
2. 限定检索范围为当前原子及允许的关系边；
3. 判断回答需要图、视频、交互或公式卡；
4. 只返回已审核且权利允许的素材；
5. 生成回答并附一个指向底层原理的反问；
6. 学生选择深入当前分支或显式创建支线；
7. 侧边提问树增量更新；
8. 任何消息可打开白板，并绑定消息节点和快照版本；
9. 关键节点要求学生复述；
10. 会话结束保存树，允许勾选节点转为 M2 记忆项。

### 7.3.3 问题库运营

- 教研首批提供反直觉、边界、溯源、连接和高频真实问题；
- 真实问题按频次、树深、复述质量和多人追问进入候选池；
- 教研审核后才能成为正式种子问题；
- 超纲问题标明层级后只讲大意；
- 不相关问题创建支线并提供返回主干；
- 不适宜内容拒绝并记录安全分类，不进入画像。

### 7.3.4 Skill 化

Skill 输入概念或问题，输出起点、反问、发散控制、素材调度和收口策略。Skill 版本必须可评测、灰度、回滚。Business model 演示需达到：至少 3 层、至少 2 次主动旁散、至少 3 类素材、无空泛“你觉得呢”反问。

与 John Zheng 的默认协作边界为：John Zheng 提供发散教学方法、示范会话和评测样本；UniPrism 负责 Skill 工程化、课程边界、素材接入、安全、部署和运行成本。Skill 的产品代码、评测集与生产版本归 UniPrism 维护；合作方方法材料按协议保留署名和使用范围。未完成书面归属确认前，合作产物只能用于隔离演示环境，不能进入生产课程。

### 7.3.5 成本与失败

- 每会话设上下文、节点、素材和 token 上限；
- 达到规模上限时先总结主干，再由学生选择继续哪条分支；
- 模型失败保留问题节点并允许重试；
- 素材检索为空时返回纯文本，不伪造配图；
- 交互组件加载失败时展示说明和稍后重试，不用静态截图冒充互动；
- 所有自由输入经过未成年人安全策略和频率限制。

## 7.4 1.3 游戏化学习

### 7.4.1 共用规则

1. 关卡机制必须与知识结构同构；
2. 结束必须把行为翻译成课本语言并绑定原子；
3. 失败有可见后果但可以零成本继续或重开；
4. 游戏过程不更新能力分；
5. 完成后用一道无提示独立题验证，只有该题更新能力和掌握度；
6. 玩法、停留和选择只作为“行为观察”兴趣证据。

### 7.4.2 文科路径

1. 选择 5–15 分钟情境；
2. 展示学生真正想达成的目标；
3. 阅读推进，在关键节点用语言、史实或语义完成选择、填空、排序或判断；
4. 选择错误改变关系或剧情结果，但不强制回档；
5. 卡点可打开对应原子补课，返回原节点；
6. 结局页复盘关键选择、真实知识差异和原子关系；
7. 生成记忆项和兴趣证据。

v1 使用文本、卡片和轻交互，不建设立绘和完整剧情引擎。

### 7.4.3 理科路径

机制库保持八类：构造、参数调节、有限操作闯关、资源权衡、规则推理、对抗博弈、模拟沙盒、分类排序。

首期只建设：

- G2 参数调节：拖动函数参数并即时重算图像；
- G3 有限操作：在限定步骤内完成代数变换。

单局步骤：

1. 加载原子、目标、状态模型和判定条件；
2. 30 秒内让学生完成第一次真实操作；
3. 每次操作即时重算且记录状态变更；
4. 首个失败位置给针对性反馈；
5. 允许秒重开；
6. 通关后执行收口翻译；
7. 发起无提示验证题；
8. 写入接触、记忆和兴趣事件。

一套机制配置必须覆盖至少 10 个原子，否则不能作为通用框架验收。

## 8. M2 复习实现

## 8.1 统一记忆项与阶梯

背诵材料是有序记忆项集合，闪卡是一项的快速呈现。两者共用同一状态和调度。

记忆阶梯：

- R0 再认；
- R1 提示回忆；
- R2 无提示回忆；
- R3 易混辨析；
- R4 单步应用；
- R5 迁移变式。

每次先要求学生产出，再展示答案和反馈。首次复习从 R1 开始；连续两次成功升一级，R3 以上需要稳定度门槛；连续两次失败降一级；`R < 0.3` 回到 R1。

## 8.2 2.1 背诵材料

### 8.2.1 内容生产

- 古诗文按句或联切片，判字词和顺序；
- 公式与成立条件必须同项；
- 定义拆成 3–6 个采分点；
- 时间线按事件和相对顺序切片；
- 外语形、义、用法分项但保持词条关联。

### 8.2.2 学生步骤

1. 进入材料块，显示完整上下文和薄弱位置热力；
2. 服务端按阶梯返回跟读、首字提示、渐进挖空、全遮挡、排序或应用形态；
3. 学生逐项产出，提示需要主动申请；
4. 点击“我说完了”后展示标准答案和采分点；
5. 学生逐点勾选刚才是否覆盖；
6. 记录自评、提示和后续表现偏差；
7. 更新项级 D/S/R 和块级完成投影；
8. 中断时保存当前项，恢复后不从头开始。

v1 中文背诵不强制 ASR。外语发音评测作为可配置增强，采购或自研必须通过单独准确率验收。

## 8.3 2.2 闪卡

支持问答、挖空、辨析、图像、序列、应用和听力卡。

实现步骤：

1. 2.3/2.4 调起卡片流；
2. 根据当前阶梯渲染题面；
3. 学生先答，不能先翻答案；
4. 正确立即进入下一张，不插入庆祝动画；
5. 错误才展开解释、关联原子和重学入口；
6. 连错两次自动降级并用中性语言说明；
7. 记录结果、反应时和提示；
8. 单卡目标 15 秒，按卡型分别监控实际耗时。

配图规则：空间结构、易混淆对、流程时序必配；纯定义和结论不配装饰图。助记仅在 `mnemonic_allowed = true` 时显示；学生自建助记进入独立审核和分享队列，不污染正式调度。

## 8.4 2.3 FSRS 调度引擎

### 8.4.1 状态更新

采用 FSRS 公共参数冷启动，保存 D/S/R 和模型版本。额外计算：

```text
urgency = (1 - predicted_R) * exam_weight * downstream_impact
```

`downstream_impact` 来自知识图谱；图谱未完成时降级为 1.0，但事件中标明使用降级算法，后续可重算。

### 8.4.2 组卷配方

每组 12–20 项、预计 5–8 分钟：

- 热身 2–3 项：到期项中 R 最高；
- 主体约 55%：urgency 高且 R 在 0.5–0.9；
- 薄弱约 15%：误解或连续失败项，降低一阶；
- 探索 5–10%：带 propensity 的随机样本；
- 收尾 1–2 项：高 R 项。

目标无帮助正确率 0.85–0.95；低于 0.7 触发选材告警。配方比例由实验配置管理，不硬编码在 App。

### 8.4.3 跨模块更新

- R0–R3 只更新记忆；
- R4/R5 无提示作答同时更新能力和记忆；
- R4/R5 使用提示只更新记忆；
- M3 无提示正确视为一次成功复习；
- S 低的原子提高 M3 候选优先级。

### 8.4.4 积压处理

- 不显示总积压、欠债天数或红点数字；
- 每次重新计算状态并采样一组，不要求补完旧队列；
- 严重过期项降到 R1；
- 断档超过两周，只采样最高考试权重和后继影响的一小组；
- 只限制每日新增记忆项，不限制学生主动继续复习；
- 考前冲刺由学生主动开启，使用独立配方和清晰结束条件。

## 8.5 2.4 复习体验

1. 点击复习先请求 2–3 个引擎候选组；
2. 默认提供“今天该复的”和“快速过一遍”；薄弱项足够时增加“攻薄弱”；
3. 记录学生选择，作为动机信号；
4. 会话显示预计时长和确定终点；
5. 按热身、主体、薄弱、收尾运行，不插入广告、成就或推荐；
6. 可随时暂停，恢复时校验会话是否仍有效；
7. 结束只展示用时、变熟项目和下次预计相见时间；
8. 反复降级仍失败时提供 M1 原子重学入口；
9. 错题生成的辨析项进入同一队列；
10. 快速模式若长期替代正式复习，只提示一次“需要完整巩固”，不惩罚、不锁死。

## 9. M3 练习实现

M3 固定顺序：3.3 采集 → 3.1 分析 → 3.2 决策。任何阶段不得绕过上游生成看似精确的结论。

## 9.1 3.3 白板与交互式步骤图

### 9.1.1 独立能力层

白板支持：

- 演示模式：系统逐步播放、暂停和回退；
- 作答模式：学生输入结构化步骤；
- 协作模式：对话和白板状态同步。

白板对象存语义和增量操作，不只存位图。位图只用于预览缓存，不能作为诊断数据源。

### 9.1.2 首期学科 DSL

数学函数试点对象：

- 坐标系、坐标点、函数曲线、参数、零点、顶点、定义域标记、辅助线；
- 代数步骤对象包含 LaTeX、等价变换类型、来源步骤和成立条件；
- 判定图像与解析式是否一致、顶点/零点是否正确、等价变换是否合法。

若选择物理试点，对象改为物体、力矢量、作用点、方向、大小、名称、参考系和斜面，优先判漏力、多力、反向和受力对象错误。

### 9.1.3 学习态

1. 从 M1/M2 打开互动步骤；
2. 默认只显示当前一步；
3. 学生填写或操作后即时判断方向；
4. 卡住时按方向、方法、降级子问题逐层给提示；
5. 提示必须由学生主动申请；
6. 错误方向允许走有限步骤看到冲突；
7. 阶梯到底仍拆子问题，不给完整答案；
8. 完成后要求复述为什么这样做；
9. 全程不更新能力分，只记录卡点、提示和理解证据。

反复卡死的默认兜底：允许学生选择“先看一个更简单的同构例子”；完成例子后返回原题。若仍失败，可结束当前任务并进入 M1 回补，但不直接把原题答案掉下来。

### 9.1.4 评估态

1. 获取题图、解法图和输入能力；
2. 创建无帮助 `PracticeAttempt`；
3. 学生按步骤提交；
4. 每步结构化、回显并允许修正；
5. 完成后才展示完整步骤图；
6. 支持回放、任意步追问、隐藏后续和多解对比；
7. 无提示步骤流进入 3.1；
8. 使用提示后整次或对应证据不更新能力，但仍更新记忆。

### 9.1.5 语音与手写

- 常规 ASR 转写后进入学科术语后处理；
- 数学口语转 LaTeX、物理口语转对象、化学口语转结构式；
- 歧义必须回显多个解析或请求确认；
- “这里”等指代结合触点事件解析；
- 语音只生成草稿，学生确认后才提交；
- 手写识别失败提供公式编辑器、拖拽对象和文本输入兜底；
- 化学 v1 优先拖拽拼装，自由手绘后置；
- 几何 v1 只在给定图上标注，自由作图后置。

### 9.1.6 快照与存储

每条消息保存白板版本引用；快照采用“初始对象 + 操作增量 + 周期压缩快照”，避免每步保存整张图片。删除对话时按保留策略处理白板原始输入，已匿名化的学习事件不级联删除。

## 9.2 3.1 精准错误识别

### 9.2.1 七个主维

- READ 审题；
- COMP 理解；
- REPR 表征与读图；
- STRAT 策略与建模；
- CALC 计算与执行；
- PROOF 推理与证明；
- CHECK 检查与合理性。

学生端显示最多七维和人话解释；学科子维控制在 4–6 个，只供教师和推荐器使用。读图作为 REPR 子维可单独展示。

### 9.2.2 错因体系

单次错因保持七类：事实/概念缺失、概念误解、表征错误、策略错误、执行/计算错误、检查失败、非知识因素。错因是离散事件结论，能力是长期连续状态，不能混为一个字段。

### 9.2.3 诊断流水线

1. 接收结构化步骤和原始引用；
2. 按等号链、换行、停顿、笔迹分组或语音断句切分；
3. 与 `SolutionGraph` 多路径 checkpoint 对齐；
4. 优先用符号等价和规则判定，再用结构相似，最后才用模型；
5. 标记 correct、过程错结果对、wrong、skipped 或 unparsable；
6. 找到第一个独立错误，后续连锁错误不重复归罪；
7. 优先匹配预制 `ErrorMap`，其次步骤规则，最后模型归因；
8. 按载荷将失败分配到能力维度；
9. 置信度大于 0.85 自动采纳；0.6–0.85 降权并显示需更多证据；低于 0.6 不更新能力并进入复核；
10. 无法区分候选错因时推荐区分题；
11. 错因派生 M2 辨析卡，卡点提供 M1 回补，弱维进入 3.2 推荐。

教师复核结果必须回写诊断规则版本和训练数据，不能只修改本次展示。

## 9.3 3.2 难度、能力、推荐和段位

### 9.3.1 题目模型

模型输入题干、题图、原子、题型、学段和学科；输出七维难度 `beta`、载荷 `w`、区分度 `a`、认知负荷 `L` 和预计时间 `t`。

冷启动顺序：教研种子标注 → 历年真题得分率迁移 → 小流量投放 → 真实数据校准 → 回流训练。新题先进入 pilot，不进入正式测验或锚题。

### 9.3.2 用户测定

1. 首次用 5–15 题自适应定级；
2. 每维保存 `theta` 和 RD；
3. 无提示作答用正确性、用时和提示状态连续评分；
4. 又错又快惩罚最重；
5. 久未测维度 RD 膨胀，并提高测量优先级；
6. 有提示、游戏、对话和学习态不计能力；
7. P0 使用 Elo + 趋势型动态 K；
8. P2 是否迁移 Urnings 由独立技术验证决定，段位定义不随算法改变。

### 9.3.3 推荐

1. 按原子相关性和前置掌握生成候选；
2. 预测成功率落在 0.70–0.85；
3. 检查认知负荷是否超过当前承受力；
4. 疲劳、长会话和新原子降低 L；
5. 弱维和高 RD 优先；
6. 不连续投放同一错因；
7. 穿插已掌握题保持节奏；
8. 记录 propensity，确保离线评估和校准无偏；
9. 实际成功率偏离目标带时告警和回滚模型版本。

### 9.3.4 段位

- 段位按学科，不给七维分别设段位；
- 段位绑锚题组，不绑某个分数线；
- 达到置信区间下界后才能进入定段考；
- 定段考使用隔离锚题、无提示、限时、不进入日常题库；
- 授予后棘轮式只升不降；长期不练只标“需要复习”；
- 发现代做或数据污染时才回滚；
- 默认只显示段位，等级分放二级页；低龄用户可完全隐藏；
- 不逐题展示分数变化，按周展示个人成长；
- P0 不显示段位，P1 明示“内测段位”，P2 才固化名称和映射。

锚题必须每段 15–30 题、有备用组、禁止进入错题本和分享，并监控泄漏与漂移。

## 10. M4 生涯规划实现

M4 采用 Discover 能力切片，不复制另一套专业库、职业库、标签本体或画像。

## 10.1 4.1 专业认知

### 10.1.1 通用化现有 Flutter 模型

1. 把 `MathMajorIntroData` 等数学专用类型抽象为专业、阶段、方向、挑战和 Project 通用协议；
2. 保持已有五阶段结构和六交互原语；
3. Flutter 只消费结构化 API，不内置 17 个专业静态配置；
4. 现有数学页面通过适配器迁移，保证旧入口和进度不丢失。

### 10.1.2 三种切片

- 专业名片：overview 单卡，约 30 秒；
- 一关挑战：完整 Challenge 的可独立第一关，3–5 分钟；
- 完整入口：跳转或内嵌 Discover，20–40 分钟。

切片必须有目标、操作、判定和总结。不能以半截页面或预告片代替完整单元。大学难度内容在投放前增加高中先修检查；不满足时只展示专业名片或高中改编挑战。

## 10.2 4.2 职业认知

任务卡固定包含岗位、真实任务名、频率、六原语类型、情境、约束、单一提交对象、判定规则、首个失败、工作后果、老手/新手差异、练习边界和证据等级。

实现步骤：

1. 使用从业者访谈或公开规范生产任务卡；
2. 内容团队标记 L1 教学简化、L2 公开资料、L3 从业者审校；
3. 复用六原语渲染，不新增第七种自定义页面；
4. 一屏只要求一个可判定决策；
5. 错误指出真实工作中的首个失败和后果；
6. 完成后连接专业方向和知识原子；
7. 写入职业兴趣行为证据。

v1 不展示薪资。医疗和法律内容只呈现教育性流程与下一步检查，不给个人诊断或法律结论。艺术、表演、销售等无法适配六原语的职业使用访谈视频和观察任务，不强行任务卡化。

## 10.3 4.3 兴趣与能力探索

1. 复用 Discover 的五阶段测评、三层标签本体和候选收敛；
2. 账号绑定后读取同一份画像；
3. 教学助手发送思维树、游戏、能力、复习和浏览事件；
4. 后端转换为 `InterestEvidence`；
5. 明确标记 `user_statement / behavior_observation / assessment / inference`；
6. 冲突事实并存，按用户锁定、最近表达、已验证行为、测评、模型推断排序；
7. 学生可查看、修改、锁定、导出和删除画像；
8. 每条专业建议可追溯到画像事实；
9. 未成年人默认关闭主动营销消息和跨产品公开分享。

五阶段在教学助手内按阶段分次完成，不要求一次连续 20 分钟。阶段进度跨产品单调合并。

## 10.4 4.4 知识与应用场景

### 10.4.1 内容生产

1. 读取已冻结的原子清单；
2. 模型可生成专业、Project、任务卡和场景候选；
3. 教研审核关系是否具体、真实且适龄；
4. 每个原子最多保留两条最强连接；
5. 场景描述控制在 100–200 字并落到具体工作动作；
6. 建立反向索引供 Discover 从专业跳回高中原子。

挂载率以真实为准，目标观察区间 30–50%，不能为达到比例硬编。

### 10.4.2 学生步骤

1. 只在原子学完或独立题做对后请求连接；
2. 若学生关闭过同类推荐，服务端不再返回；
3. 最多显示一条主连接和一条次连接；
4. 打开专业名片、挑战或任务卡；
5. 记录停留、完成和返回学习；
6. 在 Discover 内提供反向跳回原子或本节子图；
7. 行为作为兴趣观察，不直接改写“适合某专业”的结论。

## 10.5 跨产品集成契约

- 账号与画像双向共享；
- 专业和职业内容由 Discover 提供，教学助手只读；
- Challenge/Project 进度使用完成度和版本的单调合并；
- 学习行为由教学助手单向发送给画像服务；
- 原子应用索引由教学助手维护，Discover 可反向读取；
- v1 不接入 Discover Agent；
- 账号未绑定时允许浏览公共切片，但不合并画像和进度；绑定后按用户确认合并匿名历史。

## 11. H 主页与游戏化助手实现

原需求中 H 尚未细化。为保证实施闭环，v1 采用以下明确默认方案。

## 11.1 H.1 今日主线

主页最多展示三个行动：

1. 必须行动：教师任务或即将到期考试相关任务；
2. 最优学习行动：预习、练习或正式复习中收益最高的一项；
3. 低电量行动：快速复习、专业名片或短挑战。

每项展示原因和预计时长。教师任务可提高优先级，但不能静默挤掉高风险遗忘项；冲突时页面同时说明“老师要求”和“系统建议”。学生可以自由进入其他模块，系统不惩罚偏离推荐。

推荐生成步骤：

1. 汇总课程进度、复习状态、弱维、教师任务和近期兴趣；
2. 先应用硬约束和截止时间；
3. 对剩余候选计算学习收益、时长和疲劳匹配；
4. 去重同一原子和同一交互类型；
5. 选择最多三个并生成可解释原因；
6. 记录展示 propensity、打开和完成事件。

## 11.2 H.2 助手角色

v1 使用“学习同伴”定位：文字气泡、静态形象和少量状态变化，不使用拟人化权威导师口吻，不声称理解学生情绪或替代教师。

助手负责：

- 解释今日行动原因；
- 在模块切换时维持上下文；
- 用中性语言说明降级、暂停和失败；
- 在升段等少数关键节点承接仪式反馈。

v1 不做语音陪伴、换装养成和与文科剧情角色共用。后续外观解锁只消费 H.3 行为奖励，不影响教学结果。

## 11.3 H.3 成长与激励

成长值只来自可验证学习行为：完成一组复习、完成一个原子、完成无帮助练习、纠正一个错因、完成职业切片。时长、点击量和能力分本身不给奖励。

规则：

- 不按正确率直接奖励；
- 不与等级分、段位和人际排名绑定；
- 不做断签清零；
- 连续参与可以显示“最近保持节奏”，中断后保留历史；
- 奖励只解锁外观、主题、学习记录卡或新内容入口；
- 异常快速点击和代做事件不产生奖励；
- 升段可有一次明确仪式，但奖励不反向影响评分。

## 11.4 H.4 信息架构

v1 底部导航采用四项：

- 今日：H.1、助手和近期成长；
- 学习：课程、预习、练习、复习和错题视图；
- 探索：专业、职业、兴趣测评和知识应用；
- 我的：能力、段位、画像、报告、消息、隐私和设置。

当前“兴趣探索/专业体验/消息/我的”迁移到新导航时保留原路由，通过适配层迁移入口。能力雷达放“我的→学习能力”，首页只展示一条最值得关注的变化，不展示七维大图。

## 12. 候选功能归位

### 12.1 错题本

不是独立数据系统。它是 M3 错误事件、原题引用、诊断结果和派生记忆项的聚合视图。删除错题本条目只隐藏视图，不删除能力和复习历史。

### 12.2 教师任务

- 教师创建课程、原子、题目或复习目标；
- H.1 接收并解释插队原因；
- M3 执行题目，M2 执行复习项；
- 教师看到完成、困难和待复核，不读取学生私密兴趣画像；
- 截止后不制造负债红点，只在教师端标记未完成事实。

### 12.3 学习看板

放在“我的→学习能力”，包含七维能力、记忆趋势、最近证据、下一步训练和数据置信度。家长端只展示趋势和建议，不展示未经确认的错因或兴趣推断。

### 12.4 课外拓展

挂在原子或原子群上，不建立与课程平行的内容体系。拓展内容标明不计课程进度，超纲层级清晰，完成后可产生兴趣和接触事件但不自动更新能力。

## 13. 数据安全、隐私与合规

1. Flutter 不保存模型密钥、数据库凭据或后台权限；
2. 所有学生接口校验用户、学段、内容权限和数据归属；
3. 模型只接收当前任务必要文本，不发送完整画像或无关历史；
4. 原始语音、手写和白板数据设置最短必要保留期，结构化事件与原始媒体分开；
5. 学生可删除画像、语音和个人知识；法定保留的审核日志使用匿名主体；
6. 兴趣行为观察不能升格为用户表达；
7. 教师、家长和学生使用不同视图与权限；
8. C2 参考池与生产库物理隔离；
9. 批量改状态、删除、迁移和重标必须可审计；
10. 医疗、法律、升学和职业结论显示证据等级与适用边界；
11. 未成年人默认最小画像、最小通知和禁止公开分享；
12. 锚题、正式测评题和答案使用独立权限、访问水印和泄漏监控。

## 14. 可观测性与实验

### 14.1 内容质量

- 原子学习曲线是否随练习下降；
- 图谱环、孤立点和前置深度；
- 题目难度七日漂移；
- 载荷残差与非标注维度相关；
- 变式同构性和生成验证器通过率；
- 课标覆盖缺口和版权等级分布。

### 14.2 学习质量

- M1：学生能否说出本节训练能力；
- M2：14 天留存、正确率带、完成率、主动发起、断档恢复和异常快点；
- M3：步骤对齐、错因准确率、低置信占比、白板使用率和移动端耗时；
- M4：连接点击、反向跳转、学习流程触达和关闭率；
- H：今日行动打开率、完成率、低电量入口使用和非惩罚式回流。

### 14.3 实验规则

- 所有推荐实验记录展示 propensity；
- 同一学生在实验周期内保持稳定分组；
- 不以未成年人高频停留或付费为优化目标；
- 任何影响能力分、段位或画像事实的实验必须可回滚和重算；
- 实验结束前不把临时参数写死为正式产品口径。

## 15. 测试策略

### 15.1 后端单元测试

- 原子状态机非法跃迁被拒绝；
- 前置图环、孤立节点、非对称边和全 1.0 强度被发现；
- C3 内容在入库入口拒绝；
- 记忆阶梯升降、FSRS 更新和 urgency 计算可重放；
- 复习配方满足槽位、长度、时长和正确率保护；
- 有提示事件不更新能力；
- 步骤对齐、首错识别和置信度门控；
- 区分题在诊断不确定时返回；
- Elo/Glicko 更新、动态 K、RD 膨胀和锚题隔离；
- M4 进度单调合并和兴趣证据来源不升级；
- 学习事件幂等和多设备冲突处理；
- 权限、限流、字段长度和模型输出清洗。

### 15.2 Flutter 测试

- 课程子图、前置回补和返回原位置；
- 素材加载、降级和互动组件真实可操作；
- 提问树建分支、回溯、保存和转记忆项；
- 游戏收口后才能进入独立验证；
- 背诵热力、渐进挖空、采分点和断点恢复；
- 闪卡答对不停留、答错展开和连续失败降级；
- 复习选组、暂停恢复和不显示积压；
- 白板三模式、结构化对象、回放和输入兜底；
- 低置信诊断显示“不确定”而非硬结论；
- 能力页不出现他人分数；
- M4 切片与 Discover 进度合并；
- 今日主线最多三项且含原因和时长；
- 隐私删除、账号未绑定和空状态。

### 15.3 集成与验收场景

完整首期场景：

1. 教研创建并批准函数原子、关系边、教学内容、题目和记忆项；
2. 学生进入课程子图并回补一个前置原子；
3. 通过参数互动理解二次函数顶点变化；
4. 从钩子问题发散两层并保存一个记忆节点；
5. 完成一题结构化分步练习；
6. 系统识别第一个错误为“把顶点当作零点”，且置信度满足规则；
7. 错因生成辨析卡并进入复习；
8. FSRS 在下一会话正确调度该项；
9. 复习 R4 无提示作答同时更新能力与记忆；
10. 原子出口显示一个真实专业或应用连接；
11. 行为以“观察”回流兴趣画像；
12. 次日主页推荐下一条可解释行动；
13. 全链路可由事件重算，无重复状态更新。

## 16. 分阶段实施顺序

### 阶段 0：产品与教研冻结

- 确认首批学科和 30–50 原子边界；
- 确认 Newman 为能力体系主干并完成七维评审；

### 阶段 1：知识底座与事件流

- 建立原子、关系边、内容、题目、记忆和审核模型；
- 完成最小管理后台、图谱校验和版权分流；
- 建立不可变学习事件和状态投影；
- 完成首批原子内容生产。

- 上线课程地图、前置回补和教学原子编排；
- 上线材料块、基础闪卡、R0–R3 和 FSRS；
- 上线 H.1 简版今日行动。

退出门槛：课程完成、复习调度和事件重算闭环通过。

### 阶段 3：M3 最小闭环

- 建设首个学科 DSL 和结构化步骤输入；
- 上线规则优先的步骤判定和错因；
- 上线 P0 内部 Elo 推荐，不展示段位；
- 错因自动派生辨析卡。

### 阶段 4：M1 增强与 M4 切片

- 上线提问树、素材调度和 Skill 版本；
- 上线 G2/G3 首批游戏机制；
- 通用化专业体验 API；
- 上线原子应用反向索引和兴趣证据回流。

退出门槛：跨模块和跨产品事件、画像来源与进度合并正确。

### 阶段 5：白板增强与评分稳定

- 增加语音草稿、手写兜底、快照回放和更多学科对象；
- 完成难度模型、锚题集和 P1 内测段位；
- 数据稳定后评估 Urnings 和 P2 正式段位。

退出门槛：锚题漂移、推荐成功率、段位节奏和泄漏防护达到正式门槛。

### 阶段 6：H 完整体验与规模化

- 完成助手角色、成长激励、信息架构迁移；
- 单学科单学段打穿后复制其他学科；
- 每次复制先冻结结构层，再生产内容和判定层。

2. 统一学习事件与学生状态投影；
3. M1 课程编排与发散学习；
4. M2 记忆项、FSRS 与复习会话；
5. M3 白板、诊断与 P0 推荐；
6. M4 Discover 集成与原子应用索引；
7. H 今日主线、助手与成长体系；
8. 全链路验收、灰度、数据校准与正式段位。

每份实施计划必须列出准确文件、接口签名、数据库迁移、失败测试、验证命令和独立提交边界；不得跨计划复制领域模型或另建 ID。

## 20. 原文开放项的 v1 默认决策

本节把原功能文档中的开放项转换为可执行默认值。评审可以修改默认值，但不得在开发中由各模块自行选择不同口径。

### 20.1 1.1 课程与知识库

- 编排顺序：v1 由教研固定原子主路径；系统只动态选择教学原子呈现和插入回补，不自动改变知识结构顺序；
- 课外拓展：挂在原子或原子群，章节页仅聚合展示；
- 首批范围：高中数学函数主题 30–50 原子；若改为物理受力分析，M1–M4 同步切换，不并行双试点；
- 课程地图：学生默认看本节子图，教师后台可看全图；
- 产能基线：每原子结构、教学和判定层按 11–17 人时估算，排期采用 15 人时中位数；锚题、材料切片和场景映射另行计入，不能包含在这 15 人时内。

### 20.2 1.2 发散提问

- 树规模：单会话最多 40 个问题节点、主干深度最多 6、单节点直接子分支最多 8；达到上限后先总结再由学生选择继续方向；
- 提问质量：v1 只记录深度、广度、原理指向和复述结果，不给学生提问能力分；数据稳定后再评估是否新增能力维度；
- 支线判定：问题超出当前原子允许关系图两跳，或连续两轮无法映射到主干目标时标为支线；安全问题直接拒绝而不是支线；
- 预习时长：从 1.1 原子进入的主干时间计入预习，学生主动支线不计入课程完成度但保留学习记录；
- 素材检索：结构化标签和关系边先做硬过滤，向量检索只在允许集合内召回和重排；
- 问题库：首批函数主题至少 50 个种子问题，五种问题类型各不少于 8 个；真实问题需达到 5 名学生重复出现或产生 3 层以上有效树，再进入教研候选池；
- 模型成本：单轮最多 3,000 模型 token，单会话最多 24,000 token、30 轮；达到任一上限时触发总结收口；所有限额由服务端配置并记录成本；
- Skill 合作：按 7.3.4 的责任和归属执行，未签署书面边界只允许演示。

### 20.3 1.3 游戏化学习

- 首批机制：函数试点做 G2 参数调节和 G3 有限步骤闯关；
- 通用边界：配置可以替换原子、参数和判定规则但不修改渲染器，一套框架覆盖至少 10 个原子才通过规模化验收；
- 文科产能：每条 v1 情境 800–2,000 中文字、5–8 个知识交互节点，由模型起草、教研审核和未成年人内容复核；
- 情境合规：不使用成人恋爱、性暗示、羞辱、胁迫、赌博诱导或不可逆伤害作为驱动力；社交后果限定为误解、关系距离、任务失败和信息缺失；
- 技术栈：理科交互、1.2 可玩素材和 3.3 白板共用学科 DSL、状态模型和渲染层；
- Galgame：v1 不接“有戏”引擎；完成轻互动有效性验证后才能评估升级；
- 游戏奖励：统一写入 H.3 的已验证行为事件，不产生独立货币，不与能力分绑定；
- 法律和金融：v1 作为高中阶段拓展内容，明确标记非课内、非投资或法律建议，不进入义务教育主线。

### 20.4 2.1 背诵材料

- 来源优先级：教研自研与 C0/C1 公共事实优先；C2 只进参考池；学生拍照只进入个人草稿，经 OCR 确认后使用，不进入公共调度池；教材原文不直接导入；
- 首批材料：函数试点只做公式表、定义和成立条件；扩科时第二批增加古诗文；
- 采分点：模型生成草案，教研审核后发布；正式材料不得运行未审核采分点；
- 自评校准：最近 20 项中自评正确率比后续无提示正确率高 30 个百分点以上时，增加独立验证比例，并提示“我们多做一次确认”，不展示“高估自己”标签；
- 外语发音：v1 优先采购成熟服务并封装供应商接口，只有成本或准确率不达标时再立项自研。

### 20.5 2.2 闪卡

- 派生数量：每原子默认 4–8 张 R0–R3 记忆卡；R4/R5 复用 M3 题目，每原子准备 1–3 道；
- 校准门槛：确定性问答、挖空和公式卡经审核即可进入正式复习；带干扰项的辨析卡和自动生成卡需至少 200 次有效作答并通过区分度检查；
- 学生自建：默认私有；申请班级分享需教师审核、敏感内容过滤和举报入口；永不自动进入公共正式池；
- 图卡模板：产品视觉设计负责跨学科规范，学科教研负责信息正确性；首期只制作函数图像与易混淆对；
- 15 秒指标：问答、挖空和辨析卡以 80% 作答在 15 秒内为验收；序列、听力和应用卡单独统计，不用 15 秒强行裁剪内容。

### 20.6 2.3 调度引擎

- FSRS 重拟合：累计至少 50,000 条包含延时结果的有效复习事件且覆盖不少于 8 周后首次评估重拟合；此前使用公开参数和版本化实验；
- `exam_weight`：由平台教研负责人按公开考纲版本制定，字段包含适用年份、地区、来源和审核人；
- 前置图降级：图谱未完成时 `downstream_impact = 1.0`，响应和事件标记降级算法版本；
- 组长度：默认 12–20 项和 5–8 分钟；按卡型预计时长截断，宁可少于 12 项也不超过承诺时间；
- 教师任务：普通教师项最多占一组 30%，其余仍由引擎配方生成；强制测验使用独立会话，不污染日常复习配方；
- 配方实验：每个实验臂至少 500 名完成过两次会话的学生，并运行至少 14 天；若样本不足则保持默认配方，不提前定论。

### 20.7 2.4 复习体验

- 教师和家长视图：学生端不显示积压总数；教师看高/中/低遗忘风险和受影响原子，家长只看复习节奏与趋势；
- 提醒：默认需要用户授权，每周最多 3 次，21:00–08:00 不推送；完成当日会话后不再提醒；
- 选组数量：默认 2 个；薄弱项达到 6 个时增加“攻薄弱”为第 3 个；
- streak：只记录历史参与节奏，不清零、不发哀求通知，H.3 统一负责展示；
- 快速模式：不硬限流；连续 3 次选择快速模式时，下次把正式组放在首位并解释收益，但仍允许选择快速模式。

### 20.8 3.1 诊断

- 能力框架：阶段 0 以 Newman 为主干完成教研评审，未通过评审不得训练载荷模型；
- 首批范围：跟随统一试点只做数学函数，不同时启动数学和物理；
- 载荷标注：两名教研独立标注，一名组长仲裁；分类一致性或连续载荷一致性低于 0.80 的题目不得进入正式池；
- 无法解析：保留原作答，允许文本、公式编辑器或教师复核；本次不更新能力、不判学生错误，只标记输入证据不足；
- 错题本：固定为 M2/M3 聚合视图，不建设第二套状态。

### 20.9 3.2 评分与段位

- 段位命名：P1 默认使用围棋式“级/段”并明确内测；P2 发布前一次性冻结名称，发布后不修改；
- 显示策略：默认只显示段位，等级分在二级页；学生可以隐藏全部，但不能开启排行榜或他人对比；
- 锚题责任：学科组设计、平台测量负责人审核、产品安全负责人制定隔离；每段 15–30 题并准备同规模备用组；
- 难度模型：首版采用可解释的多模态特征模型和教研先验，不以单次大模型评分直接作为正式难度；训练、推理和标注成本单独立项核算；
- 历年得分率：优先获取合法授权或公开统计；无法获得时只做内部推荐，不发布正式段位；
- 认知负荷初始公式：`L = 0.35×步骤数 + 0.25×并行条件数 + 0.20×表征切换数 + 0.10×符号新颖度 + 0.10×工作记忆对象数`，各项先归一化到 0–1，再由真实数据校准；
- 学段可及区间：数据未标定前不显示具体天花板；达到每学段至少 5,000 次有效锚题作答后再冻结区间；
- Urnings：只有离线回放显示其校准误差、置信区间覆盖和自适应偏差三项均优于现行 Elo/Glicko，且迁移演练不改变已授段位时，才能进入 P2。

### 20.10 3.3 白板

- 插入时机：学习态默认在原子出口固定一次，学生可随时主动打开；不按“每几分钟”强制打断；
- 卡死处理：先给同构简单例，再允许回到 M1 回补；学习态不直接展示原题完整答案；
- 答错路径：单次错误就地追问，重复同错因降级重讲，仍失败写入薄弱点并结束当前题；
- 复述判定：按 3–6 个教研采分点计算语义覆盖，覆盖低于 60% 或模型置信不足时请求学生补充，不直接判“不会”；
- 复用评估：阶段 0 对中科图灵九章执行协议、对象模型、渲染、回放、许可证、性能和可维护性六项检查；通过四项以上且无许可证阻塞时优先适配；
- 学科顺序：统一试点优先数学函数；扩科顺序为物理受力、化学结构式、生物流程；
- 分端策略：手机优先语音、拖拽和给定图标注；平板开放手写；Web 优先键鼠和公式编辑器；
- 几何范围：v1 只在给定图上标注；
- 术语表：首个学科至少 500 条术语、口语变体和歧义规则，由教研与语言工程共同审核；
- 快照成本：只存对象增量，原始语音/笔迹默认保留 30 天用于纠错，压缩语义快照随学习记录保留；具体保留期受用户删除和法规要求覆盖。

### 20.11 4.1 专业认知

- 渲染方式：专业名片和单关切片在 Flutter 原生渲染，完整体验通过 SSO 深链进入 Discover；
- 专业覆盖：现有 17 个专业用于试点，正式扩大前补充文史哲、社会科学和艺术方向，避免理工偏置；
- 难度落差：每个切片声明高中先修原子；不满足时展示高中改编版本或名片，不直接投放大学级任务；
- 进度：切片和完整版共享，使用版本化 monotonic merge；
- 非数学 Project：由 Discover 内容团队按六原语和完整 Project 合同生产，教学助手团队只负责切片和学习连接。

### 20.12 4.2 职业认知

- 冷启动任务卡：优先“结构工程师配截面”L2 卡，判定依据使用公开国标并经过工程师事实复核；
- 产能基线：单名内容人员每周完成 2–4 张 L2 卡；L3 卡按每张至少一次 60–90 分钟访谈和事实签字单独排期；
- 医疗/法律边界：只给教育性流程和下一步检查，不给个案诊断或法律结论；
- 六原语外职业：艺术、表演、销售使用访谈视频、作品观察或角色复盘，不新增自定义交互原语；
- 内容同步：Discover 是唯一内容源，通过版本 API 和变更事件同步；Flutter 不复制静态任务卡库。

### 20.13 4.3 兴趣画像

- 同步频率：学习事件先实时写入教学事件库，每 5 分钟批量同步 Discover；失败指数退避并进行每日对账；
- 画像归属：同一账号只有一份画像，两个产品共享修改、锁定和删除；
- 未成年人：关闭营销主动消息、公开分享和基于敏感画像的推送，家长不能直接修改学生明确表达；
- 五阶段切片：每阶段可独立完成，单次目标 3–5 分钟，候选池在阶段结束时更新；
- 行为证据初始置信度：主动提问树和无提示能力证据 0.8，游戏完成 0.5，专业/职业浏览 0.4，主动额外复习 0.3；同类重复信号使用饱和函数合并，不能线性累加到 1.0。

### 20.14 4.4 应用映射

- 生产方式：模型生成候选，教研审核关系真实性、适龄性和具体性；
- 挂载率：30–50% 只作为试点观察区间，不是绩效目标；
- 场景文案：必须包含具体角色、真实动作、使用原子的那一步和可验证结果，禁止泛泛“培养思维”结尾；
- 文科范围：试点不降低具体性要求；无法建立真实原子级连接时暂不挂载；
- 反向落点：默认跳回具体原子，并带返回 Discover 的 token；原子版本不存在时降级到本节子图。
