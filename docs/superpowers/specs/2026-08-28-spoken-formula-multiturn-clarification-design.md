# 语音公式多轮澄清与行列式支持设计

## 背景

当前流程是一次性识别：语音转成文字后只解析一次，遇到歧义或超时只允许整段重录或切换公式键盘。这样会丢失已经正确识别的部分，也无法处理“先说主体、再补充边界或行列信息”的自然输入方式。

本次目标是在不放宽公式安全校验、不保存音频、不引入服务端会话状态的前提下，交付可测试的多轮补充语音闭环，并补齐二阶行列式的安全 AST 表达能力。

## 用户流程

1. 首轮解析返回 `clarification` 时，界面保留识别文字、已审核候选和澄清焦点。
2. 当响应包含 `continueRecording`，界面显示“继续补充语音”。
3. 用户点击后只录制补充内容；上一轮文字仍保存在当前控制器状态中。
4. 补充录音结束后，客户端将“上一轮累计文字 + 中文逗号 + 本轮补充文字”作为新的完整 `text` 调用现有解析接口。
5. 新请求拥有独立的 5 秒解析预算。成功时展示候选并等待用户明确插入；仍有歧义时可以继续补充，最多 3 轮。
6. 达到 3 轮上限后不再提供继续录音，只保留整段重录和公式键盘兜底。

## 冻结协议

后端澄清动作新增唯一字面量：

```text
continueRecording
```

请求体保持现有结构，不新增必填字段。客户端仍发送完整合并后的 `text`，因此服务端保持无状态，旧客户端和旧服务端可分别兼容部署。

澄清选项规则：

- 存在 2–3 个独立通过 AST、LaTeX 和候选审计的候选时，返回 `selectCandidate` 选项。
- 无法安全给出候选或需要补充结构信息时，返回 `continueRecording` 与 `useKeyboard`。
- `retryRecording` 表示放弃累计文字并重新开始，继续作为界面独立兜底。
- 禁止把模型原始 LaTeX、无法完整解析的 AST 或未通过审计的局部结构展示给用户。

## 前端状态机

`SpeechFormulaState` 新增累计文字和续录轮数，具体字段名遵循现有 Dart 命名风格：

- `accumulatedTranscript`：最近一次已提交解析的完整文字。
- `continuationTurn`：已经完成的补充轮数，范围 0–3。

状态边界：

- `continueRecording`：保留累计文字和上一响应，启动新的录音 operation；新录音的迟到回调仍由 operation id 隔离。
- 本轮 final：去除首尾空白；若为空则不发请求；否则用中文逗号连接累计文字并解析。
- `retryRecording`：清空累计文字、候选、澄清和轮数，开始全新录音。
- `useKeyboard`、取消或完成插入：结束语音流程，不自动写入任何候选。
- 每一轮请求只允许当前 operation 更新状态，避免上一轮网络响应覆盖新一轮录音。

## 后端 AST 扩展

新增两个规范节点：

```ts
type MatrixNode = {
  type: 'matrix';
  rows: MathAstNode[][];
};

type DeterminantNode = {
  type: 'determinant';
  body: MatrixNode;
};
```

MVP 约束：

- 只接受 2–4 行、2–4 列的矩形矩阵；所有行列数必须一致。
- 行列式 `body` 必须是 `matrix`，不接受任意字符串或 raw LaTeX。
- 节点计数、深度、候选数量继续受现有全局限制。
- LaTeX 分别渲染为 `bmatrix` 和 `vmatrix`；渲染结果仍必须通过 `latexGuard`。
- Compact AST、JSON Schema、MiniMax 提示、反向朗读和候选审计必须同步认识新节点。

首个公开验收语句：

```text
二阶行列式，第一行 x 加一、二 x 减三，第二行 x 减一、x 平方
```

期望公式：

```latex
\begin{vmatrix}x+1&2x-3\\x-1&x^{2}\end{vmatrix}
```

没有明确“第一行/第二行”或单元格分隔不足时，不猜测位置，返回澄清并允许继续补充语音。

## 数据与隐私

- 本次不上传或持久化音频。
- 服务端继续不记录原始识别文字。
- MVP 仅在浏览器当前控制器内保存累计文字，刷新页面即清除。
- 仅复用现有 `resolutionId` 做当前响应内候选选择，不创建服务端续录会话。

## 验收标准

- 澄清界面可保留上一轮文字并进行至少一次补充录音。
- 补充文字与累计文字合并后重新请求，且每轮获得新的 5 秒预算。
- 整段重录会清空累计上下文；旧回调不能污染新轮次。
- 最多允许 3 次补充，候选始终需要用户明确选择/插入。
- 后端响应和 Flutter 严格解析均接受 `continueRecording`。
- 二阶行列式 AST 可解析、压缩编解码、审计、渲染和反向朗读；非法维度被拒绝。
- 相关 Flutter 测试、后端单元测试、类型检查和 Web 构建通过。

## 暂不包含

- 跨页面或跨设备恢复续录会话。
- 服务端保存用户纠错语料。
- 三轮以上的无限追问。
- 未经审计的“尽量展示”或直接插入模型生成的 LaTeX。
- 对所有矩阵自然语言变体做一次性交付；本轮先覆盖明确行列槽位表达和 MiniMax 安全兜底。
