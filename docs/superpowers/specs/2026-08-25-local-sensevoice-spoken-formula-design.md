# 本机 SenseVoice 语音公式分层转换设计

状态：待用户复核设计

日期：2026-08-25

## 1. 目标与已确认边界

在当前 Windows 开发电脑上完成可实际测试的高中数学语音公式链路，并验证速度与准确率是否达到继续产品化的条件。目标架构为：

```text
浏览器录音
→ 本机 SenseVoiceSmall ASR
→ 本地确定性数学解析器
→ Math AST 校验与确定性 LaTeX
→ 低置信度时才调用 MiniMax Math AST
→ 公式预览
→ 用户确认
→ 插入答案区
```

本期必须满足：

- 音频默认只在开发电脑本地处理，不发送给 MiniMax 或 ASR 厂商；
- 高频、无歧义的高中数学表达在无云端额度时也能完成“语音 → 公式”；
- MiniMax 只接收低置信度转写文本，不接收音频；
- 不在本机实时链路中使用已经实测约 43 秒且语义不准确的 1.7B 通用语言模型；
- SenseVoice 程序、Python 环境、模型、缓存和临时音频都放在 D 盘；
- 继续复用现有 Math AST、安全校验、公式预览、用户确认和答案插入链路；
- 本期不训练或微调模型，不实现画板识别，不实现连续听写。

当前开发机为 Intel Core i5-1155G7（4 核 8 线程）、16GB 内存、Intel Iris Xe 集成显卡，无 NVIDIA 独立显卡。该配置适合先验证 SenseVoiceSmall，不适合把通用大语言模型作为实时主路径。

## 2. 方案比较与选择

### 方案一：FunASR Python 常驻服务 + SenseVoiceSmall CPU（选用）

使用 FunASR 官方 OpenAI 兼容服务，在启动阶段加载 SenseVoiceSmall，随后通过 `POST /v1/audio/transcriptions` 接收短音频。

优点：

- 官方服务路径，模型常驻，避免每次识别重新加载；
- 接口稳定，后续从开发电脑迁移到自有服务器时，前端 ASR 端口不需要理解运行时细节；
- 官方资料给出的 SenseVoice CPU 参考吞吐为约 17 倍实时速度，但本项目仍以本机实测为准；
- 直接支持健康检查、模型别名和浏览器联调。

代价：

- 需要 PyTorch、FunASR 和 Python 虚拟环境，磁盘占用高于单文件 GGUF；
- Intel Iris Xe 不能走 CUDA，本期主路径使用 CPU。

### 方案二：GGUF Q8 + Windows Vulkan 便携运行时（仅做对照测试）

使用官方 Windows Vulkan 版本，让 SenseVoiceSmall 尝试运行在 Intel Iris Xe 上。

优点是程序和模型较轻、无需完整 Python 推理环境，并可能利用集成显卡。缺点是官方轻量 HTTP 包装器每个请求会启动一个子进程，更适合本地工具、演示和集成测试；它不等同于模型常驻的生产服务。除非实测端到端延迟明显更优，且后续补充常驻原生服务，否则不把它作为第一版页面主路径。

### 方案三：继续使用浏览器 Speech API（只保留基线）

现有 `speech_to_text` 路径安装最少，但实际识别实现受浏览器与操作系统控制，无法保证完全本地，也不利于统一评测和以后迁移到自有服务器。本期只把它作为 A/B 基线和本地 SenseVoice 不可用时的显式开发降级，不作为目标架构。

## 3. 端到端架构

### 3.1 浏览器录音

现有 `SpeechFormulaRecognizer` 继续作为前端端口，但新增本地 SenseVoice 适配器。适配器负责：

1. 请求麦克风权限；
2. 录制单条短公式；
3. 在浏览器侧形成受控音频文件；
4. 上传到本机 ASR 服务；
5. 只把最终中文转写交给现有 `SpeechFormulaController`。

首版单次录音最长 15 秒，达到上限后自动停止。优先产生 16kHz、单声道 PCM WAV；若浏览器录音能力只能稳定产生 WebM/Opus，则必须在选定服务端入口验证解码支持，不能把格式兼容问题留到运行时猜测。

前端状态机仍保留“请求权限、监听、转换、预览、错误和取消”。用户取消、切题或控制器销毁后，迟到的 ASR/解析结果不得修改答案。

### 3.2 本机 ASR 服务

开发服务默认地址为 `http://127.0.0.1:8000`，只监听回环地址。服务启动时预加载 SenseVoiceSmall，健康检查成功后页面才启用“本地语音”入口。

输入限制：

- 只接受允许的音频 MIME 类型；
- 单文件最大 5MB；
- 音频最长 15 秒；
- 单机并发先限制为 1，多余请求排队或返回可恢复的忙碌状态；
- 请求和推理都必须有超时；
- 临时音频写入 D 盘专用目录，并在 `finally` 中删除。

服务返回干净转写文本和必要的耗时信息。若当前 SenseVoice 接口没有可靠、可校准的置信度，就不伪造一个概率；ASR 异常由空文本、噪声标签、过短/过长输入和服务错误等可验证条件表达。

### 3.3 本地数学解析优先

现有 `POST /api/practice/formulas/from-spoken-text` 在调用 MiniMax 前增加确定性本地解析器。解析器首批覆盖高频高中数学表达：

- 数字、变量、正负号、加减乘除、括号和幂；
- 根式、分式、等式与基本不等式；
- 常用三角函数、指数和对数；
- 区间、集合、下标及常见函数调用。

“高置信度”不是模型自报分数，而是同时满足以下条件：

1. 规范化后的有效词元被完整消费，没有无法解释的残余文本；
2. 语法只有一个有效主结构，不存在作用域或优先级歧义；
3. 结果通过 Math AST 版本、节点数、深度、符号和函数白名单校验；
4. AST 经过确定性 LaTeX 渲染和最终安全校验；
5. 解析器没有触发未知词、危险输入或需要猜测的修正规则。

本地解析成功时直接返回现有公开响应，不调用 MiniMax。解析不完整或存在歧义时进入低置信度路由。

### 3.4 云端低置信度兜底

低置信度时复用现有 MiniMax M2.7 Math AST 链路。只发送中文数学转写文本和固定协议提示，不发送音频、用户答案历史或无关个人信息。

本机没有配置云端额度时，低置信度路径返回可恢复状态：展示已识别文本，允许重新说、手动编辑或继续使用数学键盘，不得凭猜测插入公式。高置信度本地表达不受云端是否可用影响。

未来增加本地 Math AST 小模型时，它位于确定性解析器和 MiniMax 之间，并使用同一 AST 协议与安全审核器：

```text
确定性解析成功 → 直接返回
确定性解析失败 → 本地 Math AST 小模型
本地小模型仍低置信度 → MiniMax
```

## 4. 本机目录与磁盘约束

所有新增运行资产统一放在：

```text
D:\dev\local-ai\sensevoice\runtime
D:\dev\local-ai\sensevoice\venv
D:\dev\local-ai\sensevoice\models
D:\dev\local-ai\sensevoice\cache\pip
D:\dev\local-ai\sensevoice\cache\modelscope
D:\dev\local-ai\sensevoice\cache\huggingface
D:\dev\local-ai\sensevoice\cache\torch
D:\dev\local-ai\sensevoice\tmp
D:\dev\local-ai\sensevoice\benchmarks
```

安装和启动脚本只为当前进程设置 `PIP_CACHE_DIR`、`MODELSCOPE_CACHE`、`HF_HOME`、`TORCH_HOME`、`TEMP` 和 `TMP`，不永久覆盖用户全局配置。安装前后分别记录 C、D 盘可用空间；若发现安装器仍向 C 盘写入大文件，立即停止并调整路径。

不采用默认 Docker Desktop 安装作为本机首选，因为其 WSL 数据盘容易继续占用 C 盘，而且对当前单用户开发测试没有必要。

## 5. 基准测试与验收门槛

### 5.1 性能测试

先分别测试：

- FunASR Python 常驻 CPU 服务；
- GGUF Q8 CPU；
- GGUF Q8 Vulkan（驱动支持时）；
- 现有浏览器 Speech API 作为体感基线。

每条结果区分冷启动与热启动，并记录模型版本、运行时版本、后端、音频时长、推理耗时、端到端耗时、峰值内存以及 C/D 盘增量。不能把模型下载或首次加载时间混入热推理数据，也不能只用一条音频下结论。

对 2–10 秒短公式，主路径验收门槛为：

- 模型热启动后的实时因子 `RTF <= 0.5`，目标 `RTF <= 0.2`；
- 用户停止说话到获得转写的 P95 不超过 2 秒；
- 本地解析命中时，停止说话到出现公式预览的 P95 不超过 2.5 秒；
- ASR 服务额外内存峰值不超过 4GB，且运行时不导致系统持续换页或页面明显卡顿。

如果 Vulkan 首次编译、驱动兼容或每请求进程启动导致其端到端结果不优于常驻 CPU，则正式本机开发路径固定为 CPU，不为了“使用显卡”牺牲稳定性。

### 5.2 准确率测试

建立至少 30 条、目标 50 条的高中数学口语集，覆盖自然停顿、同义说法、数字与字母混说、噪声、括号作用域和典型歧义。分别统计：

- ASR 字符错误率和关键数学词错误率；
- 本地解析覆盖率；
- 高置信度路由精确率；
- 最终 LaTeX 完全匹配率；
- 候选公式 Top-2 命中率；
- 本地、云端兜底和失败各自的 P50/P95 延迟。

首轮开发验收目标：受支持表达的最终 LaTeX 完全匹配率不低于 90%，候选 Top-2 命中率不低于 95%。高置信度误接收比覆盖率更重要；无法确定的表达应降级为候选或手动处理，不能静默生成错误公式。

合成语音只用于重复性能回归，不替代真人录音准确率验收。最终至少由用户在实际页面朗读 10 条不同表达。

## 6. 安全、隐私与故障处理

- 本机 ASR 只绑定 `127.0.0.1`，CORS 只允许明确配置的 Flutter Web 开发源；
- 本地服务不写入原始录音和完整转写日志，默认只记录请求 ID、音频时长、路由结果、错误类型和耗时；
- 临时音频无论成功、失败或超时都必须删除；
- 页面不得包含 MiniMax 密钥，本地服务也不代理或保存该密钥；
- 本地 ASR 未启动、浏览器拒绝麦克风、录音格式不支持、超时或内存不足时，现有数学键盘仍可用；
- 用户确认前不得修改答案；云端失败不能覆盖本地草稿；
- 未来迁移到服务器时必须增加 TLS、认证、限流、上传体积限制和未成年人音频数据策略，不能直接把本机无认证端口暴露到公网。

## 7. 模块边界

前端仓库：

- `SpeechFormulaRecognizer`：保持“获得最终转写”的业务端口；
- 本地 SenseVoice 适配器：负责录音、上传、取消和 ASR 错误映射；
- `SpeechFormulaController`：继续编排转写、公式转换、预览与过期回调；
- 配置层：显式选择 `sensevoiceLocal | browserSpeech`，开发默认值在本机健康检查通过后使用 SenseVoice；
- UI：显示当前识别方式和可恢复错误，但不直接调用模型或拼接公式。

共享后端仓库：

- 本地确定性数学解析器：文本规范化、词法分析、语法分析和完整消费检查；
- 置信度路由器：决定本地返回或 MiniMax Math AST 兜底；
- 现有 Math AST 校验器和 LaTeX 渲染器：作为两条路径共同的唯一安全出口；
- 现有公开公式转换 API：响应结构保持兼容，不向 Flutter 暴露内部 AST。

本机工具目录：

- SenseVoice 安装与启动脚本不混入 Flutter UI 或共享后端业务代码；
- 基准结果可以写入项目文档，但模型权重、虚拟环境、音频样本和临时文件不得提交 Git。

## 8. 测试策略

实现阶段采用测试先行：

1. 为录音适配器的权限、停止、取消、超时和迟到结果补前端测试；
2. 为本地 ASR 客户端的成功、不可达、无效响应、超限和取消补测试；
3. 为数学解析器的每类语法、同义表达、残余词元、歧义和危险输入补单元测试；
4. 为“本地命中不调用 MiniMax”“低置信度只发送文本”“云端不可用可恢复”补路由测试；
5. 运行现有语音公式控制器、预览、插入和切题取消回归；
6. 在真实页面完成麦克风联调和真人口语验收。

前端至少执行相关 Flutter 测试与 Web 构建；共享后端至少执行相关 Vitest、类型检查和 lint。安装/基准阶段不以“命令能运行”代替准确率与延迟报告。

## 9. 分阶段交付

### 阶段一：本机容量与 ASR 基准

只在 D 盘安装候选运行时和模型，完成 CPU/Vulkan 对照、磁盘与内存核对，选择主运行时。此阶段不改页面生产链路。

### 阶段二：页面接入本地 SenseVoice

新增浏览器录音和本地 ASR 适配器，保留现有浏览器 Speech API 为显式开发降级，打开练习公式页面进行真人测试。

### 阶段三：本地数学解析优先

在共享后端加入确定性解析器和置信度路由，使高频表达完全离线工作；MiniMax 只处理低置信度文本。

### 阶段四：验收与服务器迁移准备

扩充高中数学口语集，修正规则与词表，形成版本化基准报告。只有数据证明确定性解析覆盖率已成为瓶颈，并积累合法授权的纠错样本后，才进入本地 Math AST 小模型选型或微调。

## 10. 已知限制

- SenseVoiceSmall 能否在这台电脑达到目标延迟必须实测；官方吞吐不能替代本机结果；
- Intel Iris Xe 的 Vulkan 支持取决于当前驱动，且官方轻量 HTTP 包装器不是常驻生产服务；
- 数学口语中的字母、同音词、负号和作用域仍可能被 ASR 错听，因此必须保留转写文本和公式预览；
- 第一版确定性解析器不会覆盖所有高中数学自由说法，未覆盖内容会进入云端或手动路径；
- 云端兜底未配置额度时，只影响低置信度表达，不影响已经被本地可靠解析的表达；
- 本期不收集训练数据，不承诺训练自己的 ASR 或 Math AST 模型。
