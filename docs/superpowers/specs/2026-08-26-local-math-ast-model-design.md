# 本地语音公式语义模型设计

## 1. 背景与结论

当前开发页面已经使用真实麦克风和本地 SenseVoice 完成音频转写，但题内公式转换在本地练习模式下仍注入 `DemoSpokenFormulaRepository`。该实现只匹配少量固定表达，不能代表“自由数学口语转公式”，也使转换失败界面无法区分 ASR 错误和语义解析错误。

本设计移除运行时固定表达映射，以本地量化语言模型理解自由中文高中数学口语，并复用已经完成的 Math AST 校验与确定性 LaTeX 渲染链路。开发测试默认完全离线运行，不要求 MiniMax Token，也不把音频或转写文本发送到外部服务。

## 2. 目标

- 用户可用不同普通话说法表达高中数学公式，不依赖完全匹配的句式；
- 麦克风、ASR、语义模型、Math AST 校验和 LaTeX 预览均为真实执行；
- 所有本地模型、缓存、日志和运行二进制放在 D 盘；
- 页面始终显示 SenseVoice 的最终转写，失败时明确指出失败层级；
- 模型只输出受控 Math AST，后端负责语义上限校验和 LaTeX 渲染；
- 在接入 Web 前先完成独立速度与准确率基准，未达门槛即停止本地集成。

## 3. 非目标

- 第一版不在当前笔记本上训练或微调模型；
- 第一版不承诺覆盖大学数学、证明题自然语言或整段题目求解；
- 不把测试语料变成运行时答案表、正则模板或固定公式映射；
- 不允许模型直接生成未经审核的 LaTeX 并写入答案区；
- 本地模型失败时不回退到演示转换器，也不猜测公式。

## 4. 硬件基线与模型选择

开发电脑基线：

- CPU：Intel Core i5-1155G7，4 核 8 线程；
- 内存：15.8 GB；
- GPU：Intel Iris Xe 集成显卡；
- D 盘可用空间：约 57 GB；
- SenseVoice 当前 CPU 常驻内存约 3.2 GB。

首选模型为 `Qwen3-1.7B Q4_K_M`，通过 llama.cpp CPU 推理。量化文件约 1.28 GB，优先关闭思考模式、使用短上下文和受限输出长度。若首选模型速度达标但语义准确率未达标，只允许再对 `Qwen3.5-2B` 做一次对照基准；不得在未测量的情况下连续更换或下载更多模型。

本地模型只是 Math AST 的候选生成器。JSON Schema/GBNF 约束保证结构可解析，但不能证明数学语义正确，因此现有 AST 跨节点语义校验、资源上限和安全 LaTeX 渲染仍是强制边界。

## 5. 运行架构

```text
Flutter Web :5174
  -> 真实 PCM/WAV
SenseVoice :8000
  -> 最终中文转写
UniPrism 共享后端 :3000
  -> OpenAI 兼容本地请求
llama.cpp + Qwen :8081
  -> Math AST V1 JSON
共享后端 AST 校验与 LaTeX 渲染
  -> recognizedText / normalizedText / latex / alternatives / warnings
Flutter 公式预览
  -> 用户确认后插入答案区
```

开发期服务目录：

```text
D:\dev\local-ai\
  sensevoice\
  math-ast\
    bin\
    models\
    config\
    logs\
    runtime\
```

llama.cpp 仅监听 `127.0.0.1:8081`。共享后端通过环境变量选择 `local` 公式模型提供方，并配置本地 Base URL、模型标识、连接超时和总超时。Flutter 不直接访问 8081，也不持有模型服务配置。

## 6. 后端集成

基线实现位于后端独立分支 `feature/spoken-formula-math-ast-backend`，当前提交 `aed6844` 已包含：

- Math AST V1 闭合集合与 Zod 校验；
- AST 跨节点语义与资源限制；
- 确定性 AST 到 LaTeX 渲染；
- LaTeX 安全校验；
- 模型候选格式错误的一次受控修复；
- `POST /api/practice/formulas/from-spoken-text`。

实施时先在该独立分支增加 `SpokenFormulaModelProvider` 边界，使 MiniMax 和本地 llama.cpp 共享同一候选协议。本地提供方调用 `127.0.0.1:8081/v1/chat/completions`，请求必须包含 Math AST JSON Schema、低温度、禁止额外文本和固定生成上限。

独立分支全部验证通过后，才允许把必要提交集成到用户指定的共享后端分支 `feature/dialogue-exploration-1-2-backend`。不得把后端实现复制进 Flutter 仓库。

## 7. Flutter 集成与用户状态

本地题目与公式转换的数据源必须独立配置：题目仍可来自本地 Mock，但公式转换必须使用 `RemoteSpokenFormulaRepository` 调用共享后端。`DemoSpokenFormulaRepository` 不得再出现在真实麦克风测试路径中。

页面状态按边界显示：

- 录音：显示录音中和停止操作；
- ASR 完成：立即显示“识别内容：{transcript}”；
- 本地语义转换：显示“正在理解数学表达”；
- 成功：显示公式预览、歧义候选和确认按钮；
- ASR 失败：提示麦克风或本地 SenseVoice 问题；
- 本地模型不可用：提示启动本地数学模型服务；
- AST 校验失败：保留转写并提示重新表达，不显示伪造公式。

## 8. 性能策略

- SenseVoice 与 Qwen 串行依赖，但两个模型服务都保持常驻，避免每次重新加载权重；
- llama.cpp 使用 8 个 CPU 线程，初始上下文上限 2048，输出上限按 AST 实际语料收紧；
- 禁止无边界思考输出；提示词只包含 Math AST 协议、必要数学边界和少量结构示例；
- 在服务启动后执行一次不计入指标的预热请求；
- 记录匿名性能字段：阶段、耗时、成功/失败原因码，不记录音频、用户原话、完整 AST 或模型输出；
- 第一版不做并行模型竞速，不同时常驻多个 Math AST 模型。

## 9. 基准与停止条件

接入 Web 前运行独立本地基准。语料至少包含 30 条不同说法，覆盖代数式、方程、不等式、分式、根式、函数、数列、极限、导数和积分。测试语料只用于离线验收。

首轮门槛：

- AST 可解析率：100%；
- 公式语义首选候选正确率：至少 90%；
- 转换耗时中位数：不超过 6 秒；
- 转换耗时 P95：不超过 12 秒；
- 不允许任何固定模板命中或未经 AST 校验的 LaTeX。

若 Qwen3-1.7B 未达性能门槛，记录结果并停止本地路线；若只差准确率且速度仍有余量，才测试 Qwen3.5-2B。第二个模型仍未达标时，不继续优化本地大模型，向用户报告数据并回到后端云 API 决策。

## 10. 验证范围

后端：

- 本地模型健康、超时、连接失败、无效 JSON、无效 AST、歧义候选和成功转换单元测试；
- 确认本地模式不读取或调用 MiniMax 配置；
- 确认请求只包含转写文本和固定协议，不包含音频或答题历史；
- 运行现有 Math AST、路由、限流和安全测试。

Flutter：

- 错误状态显示真实转写；
- Mock 题目可与远程公式转换组合；
- 真实测试路径不构造 Demo 转换器；
- 预览确认后才写入答案区；
- 运行相关 Flutter 测试、静态分析和 Web 构建。

端到端：

- 使用真实麦克风完成至少 10 条不同高中数学口语；
- 记录停止录音后 ASR、语义模型和总耗时；
- 人工核对识别原文、AST 对应公式、预览和答案插入一致。

## 11. 数据、安全与上线边界

- 开发模式下音频只发送到本机 SenseVoice；转写只发送到本机共享后端和 llama.cpp；
- 临时 WAV 在请求完成后释放，不持久化；
- 日志不得记录学生原话、音频、模型完整响应或答案；
- 服务只绑定回环地址，不向局域网或公网暴露；
- 生产上线时可把相同服务部署到自有服务器，保持公开 API 和 Math AST 协议不变；
- 模型许可证、版本、量化哈希和运行参数必须进入部署清单，确保结果可复现。

## 12. 交付判定

只有同时满足以下条件才可称为“本地语音转公式完成”：

1. 页面不再使用固定公式模板；
2. 真实音频经过 SenseVoice 和本地语义模型；
3. 页面可见实际转写和验证后的公式；
4. 独立基准达到速度与准确率门槛；
5. 后端、Flutter 和真实麦克风验收全部通过。

仅完成模型下载、服务健康检查、模拟请求或固定样例测试，不得声明功能完成。
