# 预习模块账号持久化、知识提供器与练习交接设计

## 1. 背景与目标

当前 1.2 预习模块已经具备真实 AI 多轮追问、主线与支线节点、概念投影和探索过程展示，但开发环境默认使用内存仓储，Flutter 对话客户端仍独立维护匿名身份，重新登录后无法稳定恢复账号历史。知识上下文目前来自 Mock Provider 或空事实，尚未形成可替换的正式知识服务适配层。

本轮目标是把预习模块完善为可独立交付的上游模块：

1. 登录账号能够跨 App 重启、后端重启和设备恢复预习会话及完整节点树。
2. 建立可配置、可测试、可观测的正式知识提供器边界；真实知识库未就绪时明确使用模型知识，不伪造知识库依据。
3. 固化预习到练习的版本化交接契约，使后续团队无需依赖预习页面内部状态即可开发练习模块。
4. 提供预习模块功能文档和逐项完成度审计，明确已实现、条件可用和未实现的能力。

## 2. 本轮范围

### 2.1 包含

- 学习会话、节点、概念投影和完成摘要的 Prisma/MySQL 持久化。
- 登录用户、匿名用户及匿名转登录的会话归属。
- 当前账号的预习历史列表、最近会话恢复和单会话完整读取。
- Flutter 请求携带登录 Bearer Token，并使用服务端账号身份恢复数据。
- `none | mock | remote` 三种知识提供器模式及统一工厂。
- Remote Knowledge Provider 的请求协议、超时、结构校验、错误转换和来源元数据。
- 知识服务不可用时的 `MODEL_PRIOR` 回退，以及回答来源的如实展示。
- `PrestudyHandoffV1` 交接契约和导出接口。
- 后端单元测试、路由测试、Flutter 单元/Widget 测试和本地 HTTP 烟测。
- 面向后续开发者的预习模块说明、接口说明、配置说明和完成度矩阵。

### 2.2 不包含

- 真实知识库的数据建设、清洗、审核和上线。
- 全量课程知识原子的稳定 ID、前置知识和章节映射。
- 练习题生成、练习判定、掌握度计算和复习调度的正式实现。
- 用预习对话替代练习证据或提前判定学生已经掌握知识。

## 3. 方案选择

采用“MySQL 事实源 + Redis 短期运行态 + Flutter 无状态恢复 + 可插拔知识提供器”。

- MySQL 保存账号会话、完整节点树和交接结果，是唯一长期事实源。
- Redis 只保存幂等结果、短期快照和并发锁，不承担长期学习记录。
- Flutter 不缓存完整节点内容；进入模块后从服务端查询当前账号历史并恢复。
- 知识库通过 `KnowledgeProvider` 端口接入；对话服务只消费统一的知识上下文。

不采用 Redis 主存储，因为 TTL 过期会丢失学习记录；不采用 Flutter 本地完整存储，因为它无法跨设备恢复，也无法可靠执行账号隔离。

## 4. 账号级持久化设计

### 4.1 存储策略

- 非测试环境默认使用 `PrismaLearningSessionRepository`。
- 只有显式设置 `LEARNING_SESSION_STORAGE=memory` 时才使用内存仓储。
- 生产环境禁止启用内存仓储，配置错误时启动或首次装配即明确失败。
- `LearningSession` 保存账号、外层探索会话、预习主题、状态和当前节点。
- `ThinkingNode` 保存问题、回答、追问、父节点、支线、概念标签和模型来源。
- Redis 运行态过期后必须能够从 MySQL 重新构建快照。

### 4.2 身份与归属

- 服务端从 Web Session 或小程序 Bearer Token 解析 `userId`，不接受客户端提交 `userId`。
- 登录用户创建的新学习会话写入 `LearningSession.userId`。
- 匿名用户只能通过签名 Cookie 或受信任匿名标识访问自己的 `ExploreSession`。
- 匿名身份登录并绑定 `ExploreSession` 时，在同一业务流程中将该探索会话下 `userId IS NULL` 的学习会话归属到当前账号。
- 账号查询只能使用后端解析出的 `userId`；账号 A 不能通过猜测 `sessionId` 或 `exploreSessionId` 读取账号 B 的数据。
- 登出只清理 Flutter 当前身份和页面指针，不删除服务端学习记录。

### 4.3 查询与恢复接口

`GET /api/learning-sessions` 增加账号/匿名范围内的会话列表能力：

- 查询参数：`exploreSessionId`、可选 `scenarioId`、可选 `status`、`limit`、可选游标。
- 登录用户按后端鉴权得到的 `userId` 查询；匿名用户仅查询当前 `exploreSessionId`。
- 返回轻量会话摘要，不在列表接口重复返回完整节点。
- 默认按 `updatedAt DESC, id DESC` 排序，确保“最近一次”稳定。

现有 `GET /api/learning-sessions/{id}` 继续返回完整节点树。Flutter 恢复流程为：先查询最近摘要，再按会话 ID 获取完整快照。已完成或已过期会话可只读查看；只有 ACTIVE 且未过期会话允许继续提交。

### 4.4 Flutter 身份接入

- `RemoteExplorationApi` 通过注入的身份提供器获取 Bearer Token、`exploreSessionId` 和匿名标识。
- 登录态调用现有小程序探索会话接口完成账号绑定；匿名态保持现有匿名访问。
- 页面初始化时加载预习历史并恢复最近 ACTIVE 会话；没有 ACTIVE 会话时显示新的预习入口。
- 历史列表允许打开已完成/已过期会话的只读节点图。
- 账号切换后重新解析身份，不复用上一个账号的内存会话 ID。

## 5. 正式知识提供器骨架

### 5.1 统一端口

保留 `KnowledgeProvider` 作为对话服务唯一依赖，并补齐来源元数据：

- `provider`: `none | mock | remote`
- `providerVersion`: 当前知识快照或接口版本
- `atomId`: 可为空的稳定知识原子引用
- `facts`: 经过提供器返回的事实
- `relations`: 前置、对比和应用关系
- `materials`: 允许用于当前问题的素材
- `references`: 可审计的知识来源引用；无知识库时为空数组

对话状态机不得直接请求知识库，也不得解析知识库私有响应。

### 5.2 三种模式

- `none`：正式知识库未接入。返回空事实、空关系和 `provider=none`，回答来源必须为 `MODEL_PRIOR`。
- `mock`：仅供开发者实验室和自动化测试使用。所有响应标记 `provider=mock`，不得在生产环境启用。
- `remote`：调用未来的正式知识服务。通过 Zod 校验响应，统一处理超时、无结果和协议错误。

环境变量 `LEARNING_KNOWLEDGE_PROVIDER` 选择模式。非测试环境默认 `none`；选择 `remote` 时必须配置知识服务地址。生产环境选择 `mock` 时直接拒绝运行。

### 5.3 失败与回退

- 没有命中知识、知识服务超时或暂时不可用时，当前轮知识事实为空。
- 真实 AI 仍可基于用户问题和对话路径回答，但 `answerSource` 必须为 `MODEL_PRIOR`。
- 不允许把模型常识写入 `facts` 后标记为 `KNOWLEDGE_BASE`。
- 只有 Remote Provider 返回有效事实和来源引用时才允许标记 `KNOWLEDGE_BASE`。
- 错误日志记录提供器、耗时、错误分类和请求追踪 ID，不记录 Token 或完整敏感对话。

## 6. 预习到练习的交接契约

### 6.1 契约职责

现有树导出能力固化为 `PrestudyHandoffV1`。练习模块只依赖该公开 DTO，不依赖 Flutter Controller、预习 Widget、Redis 快照或 Repository 内部类型。

交接数据包含：

- `schemaVersion: 1`
- 会话：ID、主题、场景、状态、开始/完成时间。
- 知识引用：可选 `atomId`、提供器、提供器版本和来源引用。
- 对话证据：节点 ID、父节点 ID、问题、回答、追问、节点状态、支线标志和时间。
- 概念投影：概念节点 ID、父节点、标签、关系、状态、置信度和证据节点 ID。
- 预习观察：已出现的误区、学生感兴趣的支线和仍待验证的概念节点。
- 下一模块提示：固定为 `PRACTICE`，只提供建议关注的证据 ID，不生成正式练习题，也不宣称掌握度。

### 6.2 兼容性规则

- 现有字段只允许向后兼容地增加；删除、改名或语义改变必须提升 `schemaVersion`。
- `atomId`、提供器版本和来源引用允许为空，练习模块必须支持自由问题预习结果。
- 节点关系以 ID 表达，显示文案不是跨模块主键。
- 预习置信度只表示当前对话生成/判断的可信程度，不等于练习掌握度。
- 练习模块产生的新证据写入练习自己的领域模型，只引用预习 `sessionId`、`nodeId` 或 `conceptNodeId`。

## 7. 模块边界与可交付性

预习模块负责：

- 接收学生问题；
- 生成回答和发散式追问；
- 保存对话树和概念投影；
- 恢复账号历史；
- 输出版本化交接数据。

练习模块负责：

- 根据交接数据和未来知识库选择或生成练习；
- 记录解题过程和答案；
- 计算练习维度的判定与掌握度；
- 把练习结果反馈给后续复习调度。

两个模块只能通过公开 DTO 和服务接口交互，不能直接共享页面状态、内存 Map 或未版本化 JSON。

## 8. 错误处理与安全

- 数据库不可用时返回稳定的服务错误，不静默切换到内存仓储。
- 知识服务不可用可以降级到模型知识，但必须保留真实来源标签。
- 列表、读取、导出和写入接口执行相同的账号归属校验。
- 列表限制最大页大小，避免一次读取账号全部节点。
- 幂等键仍用于创建会话和提交节点，重复请求不能生成重复节点。
- 日志、错误响应和交接数据不包含认证 Token、Cookie 或内部密钥。

## 9. 测试与验收

### 9.1 后端

- Prisma 仓储跨实例读取同一账号会话及完整节点。
- 内存仓储只在显式测试配置下启用，生产配置拒绝 `memory`。
- 账号 A/B 的列表、读取、导出和写入均隔离。
- 匿名会话登录绑定后出现在账号历史中，匿名凭据不再获得账号级访问。
- 历史列表分页、排序、状态和场景筛选正确。
- `none` 模式返回空知识依据并生成 `MODEL_PRIOR`。
- `mock` 生产禁用。
- `remote` 响应通过结构校验；超时、无结果和错误响应安全回退。
- `PrestudyHandoffV1` 符合固定快照，父子节点与概念证据引用完整。

### 9.2 Flutter

- 登录请求携带 Bearer Token，匿名请求携带匿名身份。
- 页面启动恢复当前账号最近 ACTIVE 预习。
- 账号切换不会展示前一账号会话。
- 已完成/已过期会话以只读方式打开。
- 无历史、加载中、网络失败和重试状态均有明确展示。
- 回答来源继续正确显示“模型知识”“知识库依据”或“安全兜底”。

### 9.3 联调

- 使用真实登录账号创建两轮主线和一条支线。
- 关闭 Flutter、重启后端后重新登录，节点数量、父子关系和回答内容保持一致。
- 使用另一个账号确认无法读取前一账号数据。
- 在 `none` 模式运行真实 AI，确认回答来源为 `MODEL_PRIOR`。
- 导出交接 JSON，并通过独立契约测试解析。

## 11. 完成定义

只有同时满足以下条件才能宣布可验收：

1. 本设计范围内的后端和 Flutter 代码全部实现。
2. 新增行为均经过先失败、后通过的自动化测试验证。
3. 相关后端测试、Flutter 测试和静态分析通过。
4. 真实账号重登与后端重启联调通过。
5. 交接 JSON 可由独立契约测试解析。
6. 预习模块交付文档完成，功能完成度与已知限制如实列出。
