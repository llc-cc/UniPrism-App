# UniPrism 语音转公式候选恢复架构设计

日期：2026-08-30  
状态：已实现并通过相关回归
适用范围：Flutter Web 练习评分快速演示页、Next.js 语音公式解析服务、SenseVoiceSmall 与 MiniMax 兜底链路

## 1. 背景

当前链路已经能够把语音识别成文字，也能处理一部分简单和复杂公式，但仍反复出现以下用户可见问题：

- 转写文字中已经包含明确数学内容，界面却没有任何公式候选；
- 一个候选审计失败时，其他正确候选也被整组丢弃；
- 局部恢复能力围绕极值、集合、对数等具体句型继续扩张，难以覆盖新的自然说法；
- MiniMax 返回超时、协议错误或不完整 AST 时，已有本地结果没有被稳定保留；
- 失败路径有时超过五秒，且用户只能重新录音，无法确认已经识别出的有效部分。

本设计把问题定义为候选生命周期和恢复架构缺失，而不是单个公式语法缺陷。后续不再以新增一批句型特判作为主要解决方案。

## 2. 目标与非目标

### 2.1 目标

1. 只要任一解析阶段产生了通过安全审计的公式候选，该候选就必须进入最终结果，不得因兄弟候选失败而消失。
2. 完整公式解析失败时，能够从原转写中恢复最长、可独立成立的数学表达式片段。
3. MiniMax 只进行一次受截止时间约束的兜底调用，失败时不得清空本地或片段候选。
4. 一个可信候选也要展示，但不能自动插入答案；多个可信候选由用户选择。
5. 从停止录音到界面进入确定且可操作状态，P95 不超过五秒。
6. 全部展示候选必须通过 AST、数学符号、变量/作用域、结构完整性和 LaTeX 安全检查。
7. 失败结果必须保留识别文字，并允许用户继续补充语音或切换公式键盘。

### 2.2 非目标

- 不承诺把任意自然语言或数学问题强制转换为公式。
- 不在本轮引入第二个云端模型、模型投票或循环修复。
- 不计算公式、不解题，也不根据题目答案猜测用户想输入的公式。
- 不把未通过审计的模型 LaTeX 或模型原文直接展示给用户。
- 不在本轮替换 SenseVoiceSmall，也不重新设计练习评分页整体布局。

## 3. 已确认的产品边界

- 候选准确性高于自动填充覆盖率；存在歧义时必须让用户确认。
- 单候选、多候选和部分候选都不得自动写入答案框。
- “继续补充语音”必须保留前文，并对合并文本重新运行完整链路。
- 最终零候选是允许的安全结果，但前提是系统确实没有得到任何通过审计的 AST；不能因为局部异常错误地产生零候选。
- 五秒目标指从用户停止录音到 UI 展示候选或可恢复失败状态，而不仅是后端某个函数的耗时。

## 4. 总体架构

```text
语音
  ↓
SenseVoiceSmall
  ↓
带原文位置映射的文本规范化
  ↓
完整公式解析 ───────────────┐
  │                         │
  └─ 未得到完整可信候选      │
          ↓                 │
通用公式片段提取             │
          ↓                 │
按剩余预算调用 MiniMax 一次   │
          ↓                 │
候选收集器 / 候选池  ←───────┘
          ↓
逐候选独立审计
          ↓
语义去重与确定性排序
          ↓
结果分级
  ├─ 单个可信候选：展示，等待用户确认
  ├─ 多个可信候选：全部展示，等待用户选择
  └─ 无可信候选：展示转写，允许继续语音或使用键盘
```

完整解析、本地片段恢复和 MiniMax 不再各自决定最终 UI 结果。它们只产生候选草稿，统一交给候选池、审计器和排序器处理。

## 5. 核心数据模型

后端内部新增候选草稿模型，不直接暴露给客户端：

```ts
type FormulaCandidateDraft = {
  ast: MathAstNode;
  origin: 'deterministic' | 'semantic' | 'fragment' | 'minimax';
  sourceSpan: { start: number; end: number };
  completeness: 'complete' | 'partial';
  interpretation: 'certain' | 'ambiguous';
  warnings: string[];
};
```

`sourceSpan` 使用规范化器保留的原文位置映射计算，不能依赖模型自行声明。它用于覆盖率排序和变量审计，不用于日志。

逐候选审计返回显式结果，不再让一个候选异常终止整组处理：

```ts
type FormulaCandidateAuditResult =
  | { kind: 'accepted'; candidate: AuditedFormulaCandidate }
  | { kind: 'rejected'; reasonCode: CandidateRejectionReason };
```

现有公开候选的 `id`、`latex` 和 `spokenBack` 保持兼容。前端通过请求字段 `candidateMetadataVersion: 1` 显式协商完整/片段元数据；协商成功后候选可增加 `matchKind: 'complete' | 'partial'`。旧客户端不发送能力版本，服务端必须从响应中移除 `matchKind`，以兼容其严格 JSON 解析器。

## 6. 模块职责

### 6.1 文本规范化与位置映射

规范化器继续处理空格、标点、同义数学表达和常见语音转写形态，同时保留每个规范化 token 到原始转写区间的映射。后续模块不得各自再次实现不一致的规范化逻辑。

### 6.2 `FormulaCandidateCollector`

候选收集器只负责接收各解析阶段产生的 `FormulaCandidateDraft`，限制单次请求的候选数量和资源上限。它不渲染 LaTeX、不执行审计，也不决定是否调用 MiniMax。

### 6.3 `FormulaFragmentExtractor`

片段提取器实现通用的“最长可成立数学片段”恢复：

1. 从完整规范化 token 区间开始；
2. 使用标点、连接词、已知语法边界和解析器返回的消费位置构造有限数量的候选区间；
3. 按区间长度从长到短调用现有确定性/语义 AST 解析能力；
4. 接受能够完整消费区间且通过基本结构限制的 AST；
5. 已接受区间覆盖的更短等价片段不再重复加入；
6. 外层算子槽位完整时可组合为完整公式，槽位不完整时只保留内部可信片段。

区间数量、嵌套深度和解析尝试次数必须有固定上限，避免长转写触发二次方级搜索。片段提取按通用语法边界工作，不得建立“极值恢复器”“log 恢复器”或“集合恢复器”等题型分支。

例如“求函数 f x 等于 x 平方加二的导数”在完整解析失败时，至少可以恢复 `f(x)=x^2+2`；只有当外层求导槽位也完整时才组合导数 AST，不能猜测缺失变量或作用范围。

### 6.4 `FormulaCandidateAuditor`

审计器对每个候选独立执行：

- AST schema、节点数、深度和运算元数量检查；
- 支持的数学节点和函数检查；
- 原文变量、数字、常量和运算符的新增/丢失检查；
- 括号、幂、根式、上下限、函数参数和条件作用域检查；
- 完整或部分结构的一致性检查；
- 确定性 AST 到 LaTeX 渲染及 LaTeX 白名单检查；
- 反向朗读文本生成。

审计失败只产生封闭原因码并丢弃当前候选。日志只能记录原因码、阶段、耗时和数量，不得记录学生原文、AST、LaTeX 或模型输出。

### 6.5 `FormulaCandidateRanker`

排序器先按语义签名去重，再使用稳定规则排序：

1. 原文覆盖率更高；
2. 没有新增或丢失变量、数字、常量和关键运算符；
3. 作用域证据更明确；
4. 完整公式优先于部分公式；
5. 同等条件下，确定性解析优先于语义解析，语义解析优先于 MiniMax；
6. 完全同分时按首次发现顺序稳定排序。

来源优先级只能用于同等审计结果的稳定排序，不能让来源较高但语义较差的候选覆盖来源较低的正确候选。

### 6.6 `SpokenFormulaResolutionOrchestrator`

编排器负责共享截止时间和阶段顺序：

1. 运行完整确定性与语义解析；
2. 没有完整可信候选时运行片段提取；
3. 仍需要补全且剩余预算满足最小模型窗口时，调用 MiniMax 一次；
4. 将所有草稿统一送入独立审计、去重和排序；
5. 根据候选数量、完整性和歧义状态返回最终结果。

编排器不得包含具体数学句型判断。MiniMax 失败、超时或返回非法协议时，只标记该阶段失败，已经存在的本地候选继续参与最终决策。

## 7. 结果分级与前端行为

### 7.1 一个可信候选

- 展示公式和反向朗读；
- 提供明确的“插入公式”确认操作；
- 不自动修改答案框；
- 若候选来自片段恢复，同时保留“继续补充语音”和“公式键盘”。

### 7.2 多个可信候选

- 最多展示三个去重后的候选；
- 每个候选均展示公式和反向朗读；
- 用户必须选择其中一个，系统不得自动选择第一项；
- 同时允许继续补充语音或转用公式键盘。

### 7.3 无可信候选

- 展示并保留识别文字；
- 显示可解释但不泄露内部实现的失败信息；
- 提供“继续补充语音”和“保留文字并使用公式键盘”；
- 不展示未审计 LaTeX，也不清空当前答案。

### 7.4 连续语音与竞态

继续录音时，客户端保留当前确认上下文，将旧转写与新转写按顺序合并后重新提交完整解析。每轮请求使用递增序号或请求标识；新录音开始、用户取消或页面切题后，旧请求的晚到响应必须被忽略。

## 8. 五秒时间预算

端到端计时从用户停止录音开始：

| 阶段 | 目标预算 |
|---|---:|
| SenseVoiceSmall 转写 | 不超过 1500 ms |
| 规范化、完整解析、片段恢复、本地审计 | 不超过 200 ms |
| MiniMax 单次兜底 | 使用剩余时间，通常不超过 3000 ms |
| 最终审计、去重、排序、序列化和 UI 状态切换 | 预留约 300 ms |

所有阶段共享同一个绝对截止点，不能在进入下一阶段时重置计时。MiniMax 只能缩短剩余预算，不能扩展总预算。到达五秒时 UI 必须进入候选结果或可恢复失败状态，禁止无限加载，也禁止取消后接受晚到结果。

本地完整或片段路径的后端目标耗时不超过 200 ms。外部模型本身无法保证始终返回候选，但其尾延迟不能阻止界面在五秒内恢复可操作状态。

## 9. 错误处理、安全和可观测性

以下错误均为可恢复阶段失败，不得清空其他候选：

- 本地完整解析未命中；
- 片段区间无法完整消费；
- 单个候选审计失败；
- MiniMax 网络错误、超时、非法 JSON、非法 Compact AST 或不支持结果；
- 候选去重后数量减少。

未知程序异常不得伪装成解析未命中，应保留服务端错误边界并返回通用失败响应。监控记录以下匿名指标：阶段结果、耗时、候选草稿数、审计通过数、审计原因码、是否进入模型兜底、是否超时、最终结果类别。禁止记录转写、公式、AST、LaTeX、API Key 或模型正文。

本设计不新增数据库表，不把 MiniMax 密钥传入 Flutter 客户端，也不改变现有服务端环境变量管理方式。

## 10. 测试设计

### 10.1 后端单元与集成测试

- 候选 A 审计失败时，候选 B、C 仍被保留；
- 候选乱序输入得到稳定排序结果；
- 语义相同但 AST/LaTeX 写法不同的候选正确去重；
- MiniMax 超时、协议错误和非法 AST 不清空本地或片段候选；
- 每个请求的 MiniMax 调用次数不超过一次；
- 超过截止时间的结果不能进入响应或缓存；
- 完整候选、部分候选、多候选和零候选分别返回正确结果分级；
- 继续语音使用合并后的完整转写重新解析；
- 片段提取存在固定区间、深度和尝试次数上限；
- 日志事件不包含原文、AST、LaTeX 或模型内容。

测试语料覆盖代数、分式、根式、幂、对数、三角、集合、区间、关系链、函数、分段函数、导数、积分、极限、求和、连乘、矩阵和行列式，并纳入当前所有截图与历史失败转写。

### 10.2 Flutter 测试

- 单候选展示但不自动写入答案；
- 多候选必须等待用户选择；
- 部分候选同时提供选择与继续入口；
- 零候选保留转写和恢复入口；
- 继续录音携带历史文本；
- 取消、新录音、切题和旧请求晚到不会污染当前状态；
- 五秒 watchdog 能结束加载并进入可恢复状态。

### 10.3 验收指标

- 完整公式验收语料中，正确完整公式进入前三候选的比例不低于 95%；
- 片段恢复语料单独统计可信片段恢复率，不得计入完整公式准确率；
- 明确无歧义的完整表达中，正确完整公式排第一的比例不低于 90%；
- 截图与历史失败案例 100% 回归通过；
- 非法、越权或未审计公式展示率为 0；
- 本地后端解析路径 P95 不超过 200 ms；
- 停止录音到确定 UI 状态的端到端 P95 不超过五秒；
- 模型失败或超时时，五秒内仍返回可继续操作的结果。

## 11. 实施结果与已知限制

本设计已在后端分支 `feature/spoken-formula-resilience-backend` 和前端集成分支 `integration/spoken-formula-frontend-main-20260828` 完成。实现包括独立候选审计、通用片段提取、统一排序与语义去重、一次有界 MiniMax 兜底、超时边界候选保留、旧客户端能力协商，以及 Flutter 坏候选隔离和结果基数重建。

截至 2026-08-30 的冻结语料验证结果：

- 完整公式：15/15 进入正确分级的 Top-3；
- 部分恢复：5/5 得到可信片段；
- 明确完整公式 Top-1：100%；
- 非法 LaTeX 候选：0；
- 本地恢复基准最近一次 P95：约 26.08 ms，最大约 38.08 ms；
- 后端语音公式相关回归：1252 条通过；
- Flutter 练习评估相关回归：339 条通过、2 条按原设计跳过。

上述准确率来自冻结的开发语料，不等同于真实用户录音总体准确率。SenseVoiceSmall 在噪声、口音和断句上的转写误差，以及 MiniMax 的真实网络尾延迟，仍需在负责人演示环境和后续生产样本中持续测量。五秒架构边界已经建立，但端到端 P95 仍应以真实设备、真实 ASR 和真实 MiniMax 请求的监控数据为准。

## 11. 分阶段迁移

1. **候选生命周期基础**：引入候选草稿、候选池、逐候选审计结果和稳定去重排序，先消除“一项失败导致整组清空”。
2. **通用片段恢复**：实现带位置映射的最长可成立片段提取，并以跨数学类别语料验证，不增加题型专用恢复器。
3. **编排与预算统一**：把完整解析、片段恢复和 MiniMax 接入同一绝对截止点，确保 MiniMax 只调用一次且失败不覆盖已有候选。
4. **前端确认与竞态闭环**：统一单候选、多候选、部分候选、零候选和继续语音状态，拒绝旧请求晚到结果。
5. **回归与指标验收**：运行后端 Vitest、Flutter analyze/test、语料准确率评估和端到端延迟测量，再提交可供负责人演示的版本。

每个阶段独立提交和验证。阶段之间不以手工页面成功代替自动化测试，也不在尚未通过当前阶段质量门槛时继续叠加下一层修复。

## 12. 已知限制

- SenseVoice 转写完全错误或没有保留数学关键信息时，后续解析无法恢复原本未出现的公式。
- 外部 MiniMax 的内容质量和网络尾延迟不可控，因此五秒保证是“界面进入确定可操作状态”，不是“任何输入必定在五秒内得到正确公式”。
- 通用片段恢复优先保留可证明安全的部分表达，不会猜测缺失变量、上下限、分支条件或作用域。
- 准确率指标只对版本化验收语料有意义；新增真实失败样本必须进入回归语料并持续评估，不能用单个成功案例代表总体准确率。
