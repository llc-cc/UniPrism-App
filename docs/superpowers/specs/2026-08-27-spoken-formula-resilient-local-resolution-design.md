# 高中数学语音公式韧性解析与反向朗读设计

状态：已确认，待实施

日期：2026-08-27

## 1. 背景与结论

当前链路已经具备真实麦克风录音、SenseVoiceSmall 本地 CPU 转写、本地确定性 Math AST 解析、MiniMax M3 低置信度兜底、AST 安全校验和公式预览。但是近期 10 条困难文本回归中，10 条都未命中本地规则，MiniMax 仅有 5 条通过 Compact AST 校验；失败请求虽然在 4 秒内结束，仍会向用户呈现公式转换失败。前端公式请求还保留 70 秒超时，旧模型路径也保留 30 秒超时，无法形成端到端 5 秒承诺。

本设计把产品目标从“每次强行生成一个公式”调整为“有效的高中数学表达在 5 秒内必须进入可操作状态”。可操作状态只有三种：

1. `resolved`：唯一高置信度公式；
2. `candidates`：二至三个安全候选及各自的简体中文反向朗读；
3. `clarification`：保留转写并提出一个具体、可点击回答的作用域问题。

困难表达不得落入笼统的“公式转换失败”“请换一种说法”或无期限等待。天然歧义不得为了提高表面成功率而自动插入答案；只有用户确认后的候选才能进入答案区。

## 2. 目标与非目标

### 2.1 目标

- 用户停止说话后 5 秒内显示公式、候选或具体澄清问题；
- 本地端到端语义正确率最终达到 95% 以上，本地 Top-3 候选命中率达到 99% 以上；
- 高置信度错误公式自动插入率不高于 0.5%；
- 在最终锁定的有效高中数学测试集中，笼统公式失败状态为 0；
- 复用唯一的 Canonical Math AST、安全校验和确定性 LaTeX 渲染出口；
- 通过反向朗读显式表达分子、分母、幂、根号、上下限、求值点和分段条件的作用域；
- MiniMax 只作不阻塞主流程的后台增强，不能定义 5 秒 SLA；
- 为后续任务专用本地 Math AST 小模型建立稳定接口和数据闭环。

### 2.2 非目标

- 不承诺把含糊口述静默猜成唯一公式；
- 不把证明题、整段题意理解、解题过程或大学数学纳入本期范围；
- 不在首个实施阶段训练新模型；
- 不把 43 秒级的 Qwen3-1.7B 通用模型重新放回实时链路；
- 不在首版生产关键路径中引入 MathLex、Speech Rule Engine 或 MathCAT；
- 不降低 AST、资源上限或 LaTeX 安全校验来换取表面成功率；
- 不默认保存真实用户音频。

## 3. 方案比较与选择

### 3.1 仅扩充本地规则

优点是速度最快、可解释且容易测试。缺点是同义表达和长距离作用域会持续扩大规则数量，难以单独承担 95% 的真实口语覆盖率。

### 3.2 确定性语法 + 任务专用小模型 + 反向朗读（采用）

确定性语法处理高频和结构明确的表达；任务专用小模型只在语法未命中时生成受控 AST 候选；反向朗读和语义锚点比对负责发现合法但作用域错误的结果。该方案兼顾速度、覆盖率和错误可控性。

小模型以独立 `MathAstCandidateProvider` 接口接入。首阶段接口落地但不启用未达标模型；后续只允许不超过 350M 参数、INT8 或同等量化、输出受语法约束的任务专用模型参加本机基准。模型热启动后单次候选生成必须 P95 不超过 2 秒，否则不得进入实时链路。

### 3.3 模型优先或云端优先

自由表达覆盖更强，但延迟、费用、可用性和结构输出稳定性都不能满足当前硬 SLA。本方案只保留云端后台增强，不让它阻塞首屏结果。

## 4. 端到端架构

```text
浏览器录音 / VAD
  -> SenseVoiceSmall 本地 CPU
  -> 原始 ASR 转写
  -> 中文数学归一化与语义锚点提取
  -> 本地确定性语法解析
       -> 唯一安全 AST ----------------------┐
       -> 多个安全 AST -------------------┐  │
       -> 未命中 -> 本地 Math AST 小模型  │  │
                      -> 1~3 个受控 AST --┤  │
  -> Canonical Math AST 安全与资源校验     │  │
  -> AST -> 简体中文反向朗读 + 语义签名    │  │
  -> 原始锚点与候选签名比对                │  │
       -> resolved / candidates / clarification
  -> Flutter 预览、朗读文本和用户确认
  -> 用户确认后插入答案区

MiniMax 后台增强：仅接收转写文本；不阻塞上述 5 秒结果，也不自动覆盖用户已看到的候选。
```

## 5. 后端模块与职责

### 5.1 数学归一化器

把 ASR 文本转换成带来源区间的数学词元，统一同义表达但不删除作用域信息。例如“平方、二次方”“除以、分之”“整体、括号里”“在 x 等于二处”等映射为稳定词元。归一化器同时输出：

- 已识别词元；
- 未消费片段；
- 明确作用域标记；
- 潜在歧义位置；
- ASR 常见数学同音纠错候选。

纠错不能静默改变变量、数字、正负号或不等号。存在多个合理纠正时必须产生候选或澄清。

### 5.2 可组合语法解析器

现有确定性解析器扩展为按优先级组合的表达式语法，运算符节点负责消费自己的主体和边界，避免为整句话新增固定模板。首个困难公式阶段必须覆盖：

- 高阶导数、求值点与复合被求导表达式；
- 求和、连乘主体中的幂、分式和函数；
- 包含端点语义的区间口述；
- 集合描述式；
- 任意数量分支的分段函数；
- 嵌套分式、根式与复合函数；
- 定积分、极限中的复杂主体；
- 对数底数和参数作用域；
- 排列组合等式。

解析成功必须完整消费有效词元。剩余文本、冲突作用域或多个等价优先级解释不得标为高置信度。

### 5.3 候选编排器

候选编排器合并语法解析器和本地小模型结果，按 Canonical AST 语义去重，最多保留三个候选。候选排序依据是可验证证据，不使用模型自报概率：

1. 原始数学词元是否完整覆盖；
2. 明确作用域是否一致；
3. 反向朗读语义锚点是否一致；
4. 是否存在未解释或模型新增的变量、数字、运算符；
5. AST 是否通过全部安全与资源限制。

任何候选都不得携带未校验 LaTeX。模型只生成候选 AST，最终 LaTeX 始终由后端确定性渲染。

### 5.4 简体中文反向朗读器

新增纯函数式 `MathAstSpeechRendererZhCn`，输入 Canonical Math AST，输出：

- `spokenText`：用户可见的简体中文结构化朗读；
- `semanticSignature`：供机器比较的运算符、参数和作用域签名；
- `segments`：可关联到公式子树的朗读片段，用于后续高亮。

朗读必须在危险边界处显式使用“括号”“整体”“分母结束”“从……到……”“在……处”“当……时”等词，不追求最短文本。例如：

```text
1 / (x² + 1)
-> 一除以括号 x 的平方加一括号

1 / x² + 1
-> 一除以 x 的平方，再加一
```

机器校验比较语义签名，不比较原文和朗读文本的普通编辑距离。原文没有给出足够作用域证据时，两种候选都可保留，由用户选择。

### 5.5 安全原因码与可观测性

MiniMax 和本地模型的候选拒绝必须记录不含用户原文和模型正文的原因码，例如：

- `SCHEMA_INVALID`
- `NODE_UNSUPPORTED`
- `ARITY_INVALID`
- `SOURCE_SYMBOL_ADDED`
- `SOURCE_SYMBOL_DROPPED`
- `SCOPE_CONFLICT`
- `SEMANTIC_LIMIT_EXCEEDED`
- `LATEX_GUARD_REJECTED`

原因码、路由、各阶段耗时和候选数量可进入匿名指标；音频、原始转写、完整 AST 和模型正文不得进入普通日志。

## 6. API 契约与兼容策略

共享后端新增版本化接口：

```text
POST /api/practice/formulas/resolve-spoken-text
```

旧的 `POST /api/practice/formulas/from-spoken-text` 保持兼容，避免影响其它共用后端客户端。新接口响应为：

```json
{
  "resolutionId": "opaque-resolution-id",
  "recognizedText": "一除以 x 平方加一",
  "normalizedText": "一除以 x 平方加一",
  "outcome": "candidates",
  "candidates": [
    {
      "id": "opaque-id-1",
      "latex": "\\frac{1}{x^{2}+1}",
      "spokenBack": "一除以括号 x 的平方加一括号"
    },
    {
      "id": "opaque-id-2",
      "latex": "\\frac{1}{x^{2}}+1",
      "spokenBack": "一除以 x 的平方，再加一"
    }
  ],
  "clarification": null,
  "warnings": []
}
```

约束：

- `resolved` 必须只有一个候选；
- `candidates` 必须有二至三个语义不同的候选；
- `clarification` 可以没有公式，但必须包含一个具体问题和二至三个可点击选项；
- 候选 ID 为请求内临时标识，不携带 AST 或用户原文；
- 响应不暴露内部模型、路由或置信度分数；
- Flutter 只能选择并插入本次响应中的候选 LaTeX，不接收或拼装客户端自造 AST；
- `resolutionId` 和候选 ID 只用于请求内 UI 关联及显式授权后的选择统计，不要求服务端保存公式候选会话。

## 7. Flutter 状态与用户体验

`SpeechFormulaController` 增加以下明确状态：

- `transcribing`：正在本机转写；
- `resolving`：已显示转写，正在解析；
- `resolved`：显示唯一公式、反向朗读和确认按钮；
- `choosingCandidate`：显示二至三个公式卡片及反向朗读；
- `clarifying`：显示一个具体问题和可点击选项；
- `infrastructureError`：仅用于麦克风、ASR或服务不可达，保留已有转写和公式键盘。

候选或澄清属于成功的交互状态，不使用红色错误样式。用户切题、取消或重新录音后，迟到的 ASR、后台 MiniMax 或候选结果不得修改当前答案。

确认行为始终是显式的。后台 MiniMax 返回更强候选时只能显示“增强结果可用”，不能自动替换用户已选公式。

## 8. 五秒截止与并发策略

从用户停止录音开始，由 Flutter 维护单一总截止时间：

| 阶段 | P95 预算 |
|---|---:|
| WAV 封装、上传与 SenseVoice | 1.8 秒 |
| 归一化、确定性解析、AST 校验与反向朗读 | 0.1 秒 |
| 本地任务专用小模型（仅未命中时） | 2.0 秒 |
| 前端解析与渲染 | 0.1 秒 |
| 波动余量 | 1.0 秒 |

总截止到达时必须使用已经获得的安全候选进入 `candidates` 或 `clarification`。前端 70 秒公式超时必须移除；旧 30 秒模型路径不得被新接口调用。

MiniMax 请求可以在本地结果之后后台发起，使用独立取消信号和短超时。页面销毁、重新录音、用户确认或题目切换均取消后台增强。相同转写的云端结果可短时去重缓存，但缓存不得包含音频，也不得让旧候选覆盖新请求。

## 9. MathLex、SRE 与 MathCAT 的定位

### 9.1 MathLex

MathLex 第一阶段仅作离线实验和 AST 覆盖参考。实验输入为 LaTeX 或符号文本，不把它当成中文自然语言解析器。可评估：

- Canonical AST 与 MathLex AST 的节点覆盖差异；
- LaTeX -> MathLex AST -> LaTeX 往返稳定性；
- 矩阵、向量、集合和多重积分节点的未来扩展；
- Rust/WASM 或 sidecar 集成的启动、延迟和部署成本。

没有独立收益数据前，不在共享后端增加 MathLex 生产依赖。

### 9.2 Speech Rule Engine

SRE 当前不进入中文主流程。它可作为 MathML 语义树和英文无障碍朗读的参考，但现有官方语言资源不满足简体中文产品要求。

### 9.3 MathCAT

MathCAT 的繁体中文能力以独立实验适配器验证。实验链路为 `Canonical AST -> MathML -> MathCAT zh-TW -> 术语评估`。生产简体中文反向朗读仍由本项目受控规则实现，避免繁简字符转换掩盖地区术语和作用域表达差异。

## 10. 数据闭环与隐私

数据记录分为默认匿名指标和显式授权语料：

### 10.1 默认匿名指标

仅记录请求 ID、公式结构类别、路由、结果状态、原因码、各阶段耗时、候选数量和版本号，不记录音频、原文、完整 AST 或答案内容。

### 10.2 显式授权语料

只有用户明确同意后才能保存：

- 音频；
- 原始 ASR 转写；
- 数学纠错后文本；
- 标准化文本；
- 候选 AST；
- 最终确认 AST；
- 反向朗读文本；
- 歧义类型；
- 用户修改记录；
- 模型、解析器和数据版本；
- 录音环境标签和阶段耗时。

授权语料必须加密存储、具备保留期和删除能力，并将身份标识与内容分离。开发机默认不持久化真实录音。

公开英语数据集只用于公式结构抽样、数据格式和训练方法参考。中文训练数据通过高中数学 AST 模板、受控简体中文朗读、多种口语改写、TTS 噪声增强和真实授权录音逐步形成。最终准确率只能在未参与模板、规则或训练的真实录音锁定集上计算。

## 11. 测试与验收

### 11.1 永久困难回归集

把已实测的 10 条困难表达作为第一组永久回归：高阶导数、平方求和、半开区间、集合描述式、三段分段函数、嵌套分式求导、根式定积分、嵌套根式极限、复合对数方程和组合数恒等式。

每条必须验证：

- 本地语法命中，或在 5 秒内进入包含正确公式的候选；
- 预期 AST 语义而非仅 LaTeX 字符串一致；
- 反向朗读明确表达危险作用域；
- 无 MiniMax 配置时仍得到可操作状态；
- 不出现笼统转换失败。

### 11.2 分层测试

后端至少覆盖：

- 归一化、词元来源区间和完整消费；
- 表达式优先级、嵌套作用域和多分支结构；
- AST 反向朗读与语义签名；
- 候选去重、排序、矛盾拒绝和原因码；
- 新 API 三种结果契约、鉴权、限流和输入边界；
- 5 秒截止、取消、缓存与迟到结果隔离；
- MiniMax 不可用时本地结果不受影响。

Flutter 至少覆盖：

- 三种成功结果状态与候选确认；
- 反向朗读展示、窄屏和滚动；
- 5 秒截止后不继续转圈；
- 重录、切题、取消和销毁时忽略迟到结果；
- 基础设施错误保留转写和公式键盘；
- 只有确认结果才能写入答案区。

### 11.3 产品验收指标

第一阶段以 200 条人工审核中文文本变体和至少 50 条真实录音验收，不对外宣称 95%。正式 95% 验收使用至少 1,000 条文本和 500 条真实录音的锁定集：

- 本地端到端首选公式语义正确率 `>= 95%`；
- 本地 Top-3 候选语义命中率 `>= 99%`；
- 高置信度错误自动接受率 `<= 0.5%`；
- `resolved | candidates | clarification` P95 `<= 3 秒`，硬截止 `<= 5 秒`；
- 有效范围内表达的笼统公式失败状态为 `0`；
- 本地处理率 `>= 95%`，MiniMax 调用率不计入本地达标结果。

## 12. 分阶段交付

### 阶段一：韧性协议与已知困难语法

新增版本化结果协议、三种成功 UI 状态、5 秒总截止、安全原因码、简体中文反向朗读器，并使 10 条困难回归在无 MiniMax 时全部得到正确公式或正确候选。

### 阶段二：高中数学语法覆盖与基准

按高中数学模块扩展可组合语法，建立 200 条文本和 50 条真实录音基准，输出覆盖矩阵和失败分类。

### 阶段三：中文授权数据闭环

实现显式授权、脱敏、版本化标注和删除流程，积累真实 ASR 错误、候选选择和用户修改数据。

### 阶段四：任务专用本地小模型

使用中文配对数据训练或微调不超过 350M 参数的候选 AST 模型，量化后通过 2 秒 P95、内存、准确率和许可证门槛才接入。未达门槛则继续依赖确定性语法和候选澄清，不更换为通用 1.7B 模型。

### 阶段五：MathLex 与 MathCAT 实验评估

离线评估 AST 覆盖、MathML 反向朗读质量和部署成本。只有明确提升覆盖或无障碍能力且不破坏 5 秒 SLA 时，才另行设计生产接入。

## 13. 已知限制

- 语音本身缺失作用域信息时，只能给候选或追问，无法保证自动唯一化；
- SenseVoice 没有可靠数学词级置信度时，不能伪造概率分数；
- 首阶段修复已知困难语法，不等同于已经达到正式 95%；
- 基础设施故障仍需如实展示，但必须保留转写草稿、候选和公式键盘；
- 本地任务专用模型需要中文授权数据，不能直接用英语 MathSpeech、MathBridge 或 S2L 数据替代真实中文验收；
- 共用后端的旧 API 在迁移期继续存在，新旧客户端不能共享不兼容响应结构。

## 14. 完成判定

只有同时满足以下条件，才能宣布“困难公式韧性解析第一阶段完成”：

1. 10 条困难回归全部在无 MiniMax 时进入正确公式、正确候选或具体澄清；
2. 页面从停止录音到可操作结果硬截止不超过 5 秒；
3. 页面不再为数学理解失败显示笼统错误；
4. 反向朗读能够区分至少分式、幂、根号、积分/求和上下限、导数求值点和分段条件；
5. 候选未经用户确认不能插入答案区；
6. 后端相关 Vitest、类型检查及 Flutter 相关测试、静态分析和 Web 构建通过；
7. 验收报告分别列出本地覆盖、Top-3 命中、错误接受和 P50/P95 延迟，不再以少量模板通过率代替真实准确率。
