# 学生叙事式探索课堂 UI 设计

## 背景

现有 1.2 探索课堂已经具备 Session、Thinking Tree、Evidence、互动素材事件和学习结果闭环，但主界面直接展示了“阶段、证据、来源、节点”等系统术语。学生首先看到的是系统运行状态，而不是当前学习目标、问题和动作，导致产品能力完整但体验接近开发者监控页。

## 目标

- 首屏按“学生目标 → 当前问题 → 当前动作 → 本轮发现 → 下一步”组织内容。
- 将引导教学的技术状态转换为学生能理解的叙事，不改变服务端快照和阶段推进规则。
- 将每轮对话呈现为连续探索时间线：`你的问题/猜想 → 一起验证 → 你的发现 → 下一步`。
- 隐藏 `SAFE_FALLBACK`、Evidence code、内部阶段名等实现细节，但保留可理解的提示与验证进度。
- 保留完整思维树、白板、素材事件、微测、反思和结束总结能力。

## 非目标

- 不修改 Next.js API、Session 状态机、Thinking Tree、Evidence 数据结构或互动事件协议。
- 不新增知识库、数据库表、缓存或外部请求。
- 不在 Flutter 客户端重新判断学生是否掌握；页面只投影服务端状态。
- 不把本次调整扩展为全应用视觉系统重构。

## 方案比较

### 方案 A：只替换技术文案

优点是改动最小。缺点是页面仍保持“状态栏 → 阶段卡 → 对话卡”的开发者层级，不能解决体验主次颠倒。

### 方案 B：重建全屏沉浸式故事页

优点是视觉自由度最高。缺点是需要重写大量滚动、输入、素材和历史节点交互，风险与当前目标不匹配。

### 方案 C：学生叙事投影层（采用）

保留控制器、DTO 与交互组件，新增集中式 UI 文案映射，并调整现有组件的信息顺序和视觉语义。完整能力继续存在，但主页面只展示学生此刻需要理解和执行的内容。

## 信息架构

### 章节总览

1. `今天的学习旅程`：章节主题、要发现的核心关系、整体进度。
2. `从你的问题开始`：自由问题入口保持最靠前。
3. 三段学习旅程：`先发现规律`、`动手试一试`、`回看我的发现`。
4. `选择一个想弄懂的问题`：课程知识路线作为入口，不使用“知识树后台”语气。

### 探索会话

1. 开场：`今天，我们一起发现……`，突出当前学生问题。
2. 当前任务：用服务端 `teachingFlow` 投影为 `说出猜想 / 动手验证 / 确认发现 / 整理收获`。
3. 验证提示：将证据计数改为“还需要一次验证”或“这个发现已经得到验证”。
4. 探索时间线：每轮显示学生问题、AI 引导、本轮发现和下一步。
5. 探索足迹：完整概念路径和 Thinking Tree 收到 `回看我的探索` 入口，不占据主要教学注意力。

## 文案映射

| 技术状态 | 学生界面 |
|---|---|
| DIALOGUE | 说出猜想 |
| ASSET | 动手验证 |
| FOCUS | 确认发现 |
| REFLECT | 整理收获 |
| Evidence 缺失 | 还需要一次验证，确认你的想法 |
| Evidence 就绪 | 这个发现已经得到验证 |
| SAFE_FALLBACK | 当前提示 |
| MODEL_PRIOR / KNOWLEDGE_BASE | 主界面不展示来源标签 |
| 已探索 | 你的发现 |
| AI 反问 | 下一步 |
| 正在突破 | 这一轮我们在发现 |

## 组件边界

- `student_learning_narrative.dart`：仅负责把技术状态映射为学生文案，不渲染 Widget，也不改变业务状态。
- `chapter_workspace_components.dart`：调整章节总览标题、阶段名称和状态文案。
- `remote_exploration_page.dart`：重排会话层级，渲染学习旅程、当前任务和探索时间线。
- `live_tree_page_test.dart`：验证主界面不再暴露技术术语，并保留互动事件、地图入口与微测交互。

## 状态与失败处理

- 网络错误继续使用现有错误模型和重试按钮；不伪造 AI 回答。
- 只读历史继续显示不可编辑提示，但文案强调“回看学习过程”。
- 老快照没有 `teachingFlow` 时仍显示叙事式对话时间线，不要求新字段。
- 未知回答来源保持静默，兼容滚动发布。

## 响应式与可访问性

- 桌面端限制内容宽度，时间线保持纵向阅读，不再横向堆叠系统状态。
- 手机端阶段旅程允许换行，操作按钮保持可点击且不隐藏。
- 继续使用稳定 `ValueKey`，避免视觉调整破坏自动化测试和事件绑定。

## 验收标准

- 首屏能看到学生问题和当前任务，不出现“证据 0/2”“安全兜底”“AI 反问”等技术文案。
- 引导素材仍可操作并上报同一事件，按钮启用规则不变。
- 微测、反思、白板和完整探索地图入口仍可使用。
- 章节总览使用学生旅程语言，原有节点选择与自由提问入口保持可用。
- 相关 Flutter Widget 测试、完整 Flutter 测试和规定的静态分析通过，或明确区分已有问题。

## 第二轮结构修正：从章节目录变成当前学习任务

首轮只替换了学生文案，但仍保留“章节头图、自由提问、三张阶段卡、五个知识节点、问题预览、第二套输入框”的旧页面骨架，导致同一个开始动作被重复呈现。第二轮不再增加文案层，而是收敛章节总览的信息架构。

### 首屏唯一主任务

- 首屏只保留一个 `student-mission-hero`，主标题是当前节点的 `hookQuestion`。
- 章节名称、当前节点名称与说明作为背景信息，不与问题争夺视觉主位。
- 猜想输入是可选项；唯一主按钮同时支持直接开始或带着学生自己的问题开始。
- 错误提示仍紧邻主任务，重试逻辑保持不变。

### 次要内容降级

- 三个阶段合并为一条 `chapter-learning-journey-strip`，只显示阶段名称和当前状态，不重复摘要、预计分钟与进度条。
- 课程知识节点收进 `chapter-question-switcher`，默认折叠；切换节点会更新首屏任务，不直接创建会话。
- 完全自由提问收进 `direct-ai-teacher-entry`，默认折叠；它保留原有独立问题创建能力，但不与课程主任务并列。
- 删除推荐问题预览卡和第二套节点详情卡，避免同一问题在页面中出现三次。

### 第二轮验收

- 初始页面同时只有一个主要开始按钮和一个课程问题输入框。
- 首屏可直接读到当前核心问题，不需要先浏览知识节点列表。
- 三个阶段仍可见，但以一条紧凑旅程呈现，页面不再出现三次“预计 10 分钟”。
- 知识节点与自由问 AI 默认折叠，展开后原有选择、输入和会话创建回调继续可用。
- 不修改远程接口、DTO、控制器或后端配置。
