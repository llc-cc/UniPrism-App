  # 无知识库条件下的真实 AI 回答、追问与节点设计

## 1. 背景

1.2 预习探索当前已经具备会话、回答、追问、概念节点、分支、回溯和导出框架，但自由问题仍经过 `MockKnowledgeProvider`。未命中 Mock 原子时，`KnowledgeContext.facts` 为空，而现有提示词禁止模型使用输入以外的知识，因此真实模型无法自然回答未知问题，只能退回泛化模板。

当前阶段尚无正式知识库。首先完成一个不依赖知识库、仅依赖学生当前输入与当前会话路径的真实 AI 闭环；未来知识库接入时作为高优先级事实来源增强回答，不改变前端接口和节点交互。

## 2. 目标

- 任意未收录问题都可由真实模型先直接回答，再给出具体、可回答的探索追问。
- 学生回答上一轮追问时，模型能够判断该输入是回答、追问、求助还是主题切换，并据此继续。
- 回答和追问只依赖当前学生输入、当前分支最近会话和模型自身知识，不以知识库存在为前提。
- 每轮同时形成稳定的 `mapLabel`，继续驱动现有概念路径、完整节点图、支线与回溯。
- 正式知识库接入后，知识库事实优先于模型自身知识，现有 API 与 Flutter 页面无需重写。
- 每轮记录实际回答来源与模型身份，不能把本地模板伪装成真实 AI。

## 3. 非目标

- 本阶段不建设正式知识库、检索增强生成、引用系统或素材目录。
- 不扩展练习判分、掌握度判断、复习调度和课程编排。
- 不重做现有 Flutter 对话页和探索地图布局。
- 不承诺模型自身知识等同于课程审核事实；本阶段通过来源标记、提示词边界和安全兜底控制风险。

## 4. 方案选择

采用“模型知识优先、知识库可插拔”的单轮结构化生成方案。

未采用以下方案：

- 直接删除知识边界限制：改动少，但无法区分回答依据，未来接知识库时会重新耦合。
- 回答与追问拆成两个模型调用：质量控制更独立，但延迟和成本增加，当前已有结构化输出与追问质量门，首版没有必要。

## 5. 架构

### 5.1 上下文模式

教学引擎新增稳定的回答依据枚举：

- `MODEL_PRIOR`：没有可用知识库事实，允许使用模型自身知识。
- `KNOWLEDGE_BASE`：存在经过允许的知识库事实，知识库为最高优先级依据。
- `SAFE_FALLBACK`：远程模型不可用、超时或结构化结果未通过质量门，使用确定性安全兜底。

`KnowledgeProvider` 继续负责章节入口、可选知识事实与素材白名单，但自由问题未命中时不再被视为不可回答。它返回空事实只代表当前没有外部知识依据，不代表禁止模型回答。

### 5.2 模块职责

- `LearningSessionService`：选择当前父节点，构造当前分支最近上下文，保存完整节点；不决定模型是否可使用自身知识。
- `LearningDialogueEngine`：选择教学策略、确定回答依据、调用真实模型、执行结构校验与追问质量门、生成安全兜底。
- `KnowledgeProvider`：提供可选事实、关系和素材；未来替换为正式知识库实现。
- `LearningThinkingNode`：保存问题、回答、追问、节点标签、教学策略、回答依据、模型、提示词版本和置信度。
- Flutter：继续消费 `nodes` 与 `conceptNodes`；可在开发诊断信息中区分真实模型与本地兜底，不持有模型密钥和知识决策。

## 6. 数据契约

每轮结构化模型输出保持单次调用，并扩展为：

```json
{
  "answer": "本轮直接回答",
  "followUpQuestion": "基于当前问题或回答的具体追问",
  "mapLabel": "3 到 12 个字的概念名称",
  "turnIntent": "NEW_QUESTION | ANSWER_TO_TUTOR | HELP_REQUEST | TOPIC_SWITCH",
  "confidence": 0.8,
  "materialIds": [],
  "sideBranchSuggested": false
}
```

服务端补充并持久化：

```text
answerSource = MODEL_PRIOR | KNOWLEDGE_BASE | SAFE_FALLBACK
model        = 实际模型名或 local-safe-fallback
promptVersion
strategy
strategyReason
```

新增字段在响应中保持向后兼容：旧客户端忽略它们，新客户端 DTO 使用可空解析。数据库或运行时仓储的字段扩展由 repository 统一处理，不由 API Route 直接写入。

## 7. 每轮数据流

1. 学生在当前路径继续，或从历史节点显式选择继续/开支线。
2. `LearningSessionService` 从父节点沿 `parentId` 构造当前分支最近五轮，不混入其他支线。
3. `KnowledgeProvider.resolveQuestion` 返回可选事实和素材；没有命中时返回空事实。
4. 引擎根据输入确定回答依据：存在可用事实时为 `KNOWLEDGE_BASE`，否则为 `MODEL_PRIOR`。
5. 策略引擎根据首轮、卡住、错误证据和收口边界选择问题链、苏格拉底追问、类比迁移等策略。
6. 模型接收当前问题、学生阶段、当前路径、会话主题、回答依据模式、可选知识事实和素材白名单。
7. 模型一次生成回答、追问、意图和 `mapLabel`。
8. 服务端执行 Schema 校验、本地追问检查和必要的质量重生成。
9. 通过后原子性保存完整 ThinkingNode，并从完整节点投影 `conceptNodes`。
10. Flutter 显示回答与“AI 反问”，顶部路径和完整探索地图随服务端快照更新。

## 8. 提示词规则

共同规则：

- 先区分学生是在提出新问题、回答上一轮、表示不会还是切换主题。
- 新问题必须先回答，再解释关键依据，最后追问；禁止只反问不回答。
- 学生回答上一轮时，先明确回应其表达，再根据薄弱处继续。
- 追问必须具体指向依据、条件、反例、联系、观察或方向选择；禁止“你觉得呢”等空反问。
- 不重复当前路径最近三轮的回答或追问。
- `mapLabel` 表示本轮形成的知识概念，不复述“能解释一下吗”等对话动作。

`MODEL_PRIOR` 规则：

- 允许使用模型自身通识知识回答，不要求知识库事实存在。
- 不编造引用、教材出处、实验数据或已验证的学生掌握结论。
- 对时效性、高风险或不确定事实明确说明不确定性，并将追问转向澄清范围。

`KNOWLEDGE_BASE` 规则：

- 输入中的知识库事实为最高优先级依据；与模型记忆冲突时以知识库为准。
- 素材只能使用白名单 ID。

## 9. 真实模型启用策略

后端采用明确的 `auto / remote / local` 模式：

- `auto`：开发环境默认；存在模型密钥时使用真实模型，否则使用本地兜底。
- `remote`：要求真实模型；缺少密钥或调用失败时返回可重试错误，不静默伪装成成功。
- `local`：只用于确定性测试、离线开发和回归。

生产环境固定为 `remote`。任何模式都在节点中保存实际 `answerSource` 与 `model`。现有 `LEARNING_REMOTE_AI_IN_DEV` 在过渡期兼容读取，随后由统一模式替代。

## 10. 节点与合并

- 每次成功轮次始终保存一个完整 ThinkingNode，包含原问题、回答和追问。
- 概念图继续按 `mapLabel` 归一化精确去重，并沿对话 `parentId` 找最近概念父节点。
- `MODEL_PRIOR` 不改变节点合并算法；回答依据只是证据元数据。
- 从历史节点开支线时，上下文与节点父链都从所选节点开始，不读取原活跃分支的后续内容。
- 重复概念可合并为一个概念节点，但完整对话证据必须保留。

## 11. 失败与安全

- 超时、网络错误、非 JSON、Schema 不合格和追问质量不合格均进入有界重试。
- `auto` 模式在远程失败后允许使用 `SAFE_FALLBACK`，并如实记录来源；`remote` 模式失败时保留旧快照并向客户端提供重试。
- 生成与节点保存必须原子化；失败不得写入半个节点或改变当前路径。
- API 继续执行来源校验、JSON 限制、限流、会话归属与幂等校验。
- 模型密钥只存在于后端环境变量，不进入 Flutter、响应或日志。

## 12. 测试

后端单元测试覆盖：

- 空知识事实时使用 `MODEL_PRIOR`，真实模型输出被保存而非退回泛化模板。
- 知识事实存在时使用 `KNOWLEDGE_BASE`，提示词声明知识库优先。
- 学生回答上一轮时，最近路径进入提示词并影响后续追问。
- 新问题、上一轮回答、求助和主题切换四类意图。
- 连续三轮不重复同一回答或追问。
- “不懂/不会”降低难度并切换为具体观察或类比。
- 从历史节点开支线时不混入原活跃分支后续上下文。
- `auto`、`remote`、`local` 三种模式及缺少密钥、超时、坏 JSON、质量门失败。
- `answerSource`、`model`、`promptVersion` 的仓储与 API 往返。

Flutter 测试覆盖：

- 新增字段的兼容解析。
- 真实模型节点与安全兜底节点均可正常展示回答、追问和概念标签。
- 连续轮次、节点增长、显式开支线和失败重试不回归。

联调验收：

1. 在没有知识库命中的自由问题上完成至少三轮真实模型对话。
2. 每轮先回答再追问，追问引用当前学生表达且不重复。
3. `nodes` 随每轮增长，`conceptNodes` 形成可读路径。
4. 从首节点开支线后，新问题只继承该节点以前的上下文。
5. 响应中可确认 `answerSource=MODEL_PRIOR` 和实际模型名。
6. 关闭模型密钥后，`auto` 明确记录 `SAFE_FALLBACK`；`remote` 返回可重试错误。

## 13. 兼容与演进

首版保持现有 HTTP 路径和 Flutter 页面入口不变。正式知识库接入时只需替换 `KnowledgeProvider` 并返回事实、关系和素材，教学引擎会自动切换为 `KNOWLEDGE_BASE`。如果未来需要引用溯源，可在知识库模式增加引用列表，不改变当前无知识库模式的对话和节点契约。
