# 八领域 A 类时效正文采集 Agent 设计

状态：用户已确认范围与执行方向。

## 1. 目标

复用现有高校 Python crawler、正文入库接口、内容清洗与版本化能力，将 A 类时效信息流扩展为八个领域。Agent 在本机完成真实页面验证后部署到 ECS，由 systemd 定时运行，将公开详情页正文直接提交后端。

本期八个领域为：

1. 高校与教育机构；
2. 政府与公共数据；
3. 新闻与社会热点；
4. 科研与学术；
5. 技术与开源；
6. 产品与产业趋势；
7. 职业与就业数据；
8. 知识、文化与自然。

“社区与用户体验”属于 B 类低频体验语料，本期不采集、不修改，也不把知乎、贴吧、V2EX、小红书等逐条帖子混入 A 类信息流。

## 2. 最小来源范围

第一轮每个领域先接通一个无需认证、公开可访问且能进入详情正文的来源；现有四所高校继续保留。

| 领域 | 第一轮来源 | 详情正文 |
|---|---|---|
| 高校与教育机构 | 教育部教育要闻；北大、清华、人大、中南大学官网 | 政策、新闻、活动或专业详情正文 |
| 政府与公共数据 | 国家统计局最新发布 | 数据发布说明正文 |
| 新闻与社会热点 | 新华网 | 新闻详情正文 |
| 科研与学术 | arXiv 计算机科学最新列表 | 论文详情页的标题、作者和完整摘要；不复制未明确授权的 PDF 全文 |
| 技术与开源 | GitHub Trending | 仓库详情与公开 README 正文；不抓取仓库代码或私有内容 |
| 产品与产业趋势 | 工业和信息化部统计分析 | 产业政策、统计分析或运行情况正文 |
| 职业与就业数据 | 人力资源和社会保障部就业政策 | 政策与就业服务正文 |
| 知识、文化与自然 | Wikimedia 开放知识页面 | 带来源署名的公开正文 |

来源只有在无需登录、无需验证码、域名和路径均在白名单内、正文保存策略已登记时才启用。列表摘要不能冒充详情正文；详情无有效正文时本条失败，不降级入库。

## 3. 架构与职责

- `sources.yaml` 保存来源代码、领域、列表入口、允许域名、详情路径规则、单轮上限和调度参数。
- Python crawler 负责列表发现、详情页访问、正文提取和内存分批上传。
- 静态 HTML 优先使用轻量请求与解析；现有 Playwright 仅用于必须渲染的页面，并保持串行执行以控制 ECS 内存。
- crawler 本地状态只保存来源、规范化 URL、正文 SHA-256 和成功时间，不保存网页正文。
- Next.js 内部接口继续负责令牌鉴权、来源和域名二次白名单、正文规范化、来源权益、去重、版本记录和 MySQL 写入。
- B 类采集器、社区表、登录浏览器和 `ExperienceSignalAggregate` 不在本次改动范围内。

## 4. 增量与去重

每轮始终刷新列表页以发现新链接，但不重复请求已经成功入库且列表未显示更新的详情页。

去重按以下顺序执行：

1. `sourceId + externalId` 识别同一来源记录；
2. 规范化 URL 哈希识别 URL 参数或锚点差异；
3. 标题、正文和关键元数据的内容哈希判断实质变化。

未发生变化时不创建新内容或版本，只更新必要的最后发现时间。正文哈希变化时更新原记录并创建 `ContentVersion`。状态文件只能在后端明确确认本批成功后原子推进；上传失败、部分失败或进程中断都不得提前记录成功，下一轮必须能够重试。

为兼容昨天已经入库的数据，首次部署增量状态为空时允许做一次受控基线运行；后端幂等层会把已有正文计为 `unchanged`。基线成功后生成状态，第二轮不得再次提交相同详情页。

## 5. 数据流与失败处理

数据流：

`systemd → 读取自动化开关 → 逐来源刷新列表 → 发现候选详情 → 白名单校验 → 提取正文 → 规范化与哈希 → 分批上传 → 后端去重/版本化 → 成功后推进来源状态`

单个来源或页面失败不能终止其他领域。失败按 `访问拒绝`、`登录或验证码`、`超时`、`跳转越界`、`正文为空`、`版式变化`、`上传失败` 分类记录；不绕过访问控制。每个请求最多进行有限重试并采用退避，整轮保持串行和有界页面数量。

## 6. 调度与部署

- 默认每天 03:00 运行一次，复用现有 `uniprism-university-crawler.timer`。
- 每个来源配置独立游标和页面上限，避免某一来源占满整轮。
- 部署时先备份 ECS 当前 crawler 和后端来源白名单文件，再上传 Python crawler、来源配置、systemd 覆盖配置及最小后端白名单改动。
- 后端不新增数据表或迁移；来源白名单与通用来源标签先通过相关 Vitest，再采用一次受控、可回滚的低内存 Webpack 发布路径。不得再次在 ECS 上循环触发高内存 Turbopack 构建。
- 不修改数据库结构，不重跑已有迁移，不停止与本功能无关的服务。

## 7. 验证与验收

实施顺序：

1. 为八领域来源配置、正文提取、白名单和增量状态补充定向测试；
2. 本机每个领域抓取至少一条真实详情正文；
3. 连续运行两次，确认第二轮相同详情不再提交；
4. 上传 crawler 到 ECS，手动运行一轮并核对入库批次；
5. 再运行一轮确认增量状态有效；
6. 确认主站在线、timer enabled/active 且存在下一次 03:00 计划。

验收标准：八个 A 类领域均至少有一个来源取得真实详情正文并成功入库；第二轮不重复新增或重复上传相同详情；正文变化能够产生更新版本；单来源失败不影响其他来源；主站和 B 类流程不受影响。

## 8. 已知边界

- 第一轮以每领域一个稳定来源为目标，第二来源不阻塞本次上线。
- 公开可访问不等于允许面向用户发布；本次允许清洗入库，推荐、AI 使用和推送仍由来源权益开关控制。
- arXiv 首期正文定义为官方详情页完整摘要，GitHub 首期正文定义为公开 README；不复制论文 PDF、仓库代码、图片、评论或账号资料。
- 页面结构变化需要更新对应来源适配规则，不使用通用大模型自由浏览替代确定性提取。
