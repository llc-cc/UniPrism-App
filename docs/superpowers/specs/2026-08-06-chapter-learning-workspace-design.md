# 章节学习工作台与自适应追问设计

## 目标

将 1.2 从单个知识点聊天页升级为章节级学习工作台。学生进入章节后，先看到本章全貌，再从任一知识节点发起探索；对话过程中同时保留章节知识结构和学生个人思维轨迹。

本阶段交付范围固定为：章节整体查看、连续对话追问、章节知识树、个人思维树。练习与复习在章节总览中可见并展示状态，但不在本阶段展开完整答题或复习调度流程。

## 方案

采用单页工作台：桌面端左侧承载章节概览和连续对话，右侧常驻树面板；移动端保留当前路径并通过底部面板展开完整树。树面板可在“章节知识树”和“我的思维树”之间切换。

旧版 `ExplorationLabPage` 和 `ExplorationSessionPage` 不再作为开发者入口，所有入口统一进入远程章节工作台，防止继续出现两套回答逻辑。

## 章节数据边界

后端 Mock Knowledge Provider 提供章节契约，Flutter 只负责渲染：

- 章节：`chapterId`、标题、说明、预计时间、总进度；
- 阶段：学习、练习、复习及其状态、进度和摘要；
- 知识节点：节点 ID、教学原子 ID、标题、说明、节点类型、父节点、推荐状态和钩子问题；
- 节点关系只用于章节导航，不与学生会话产生的个人思维树混存。

知识库接入后只替换 Provider，页面和会话 API 不改变。

## 页面与交互

章节入口默认展示：

1. 章节标题、目标、预计学习时间和总体进度；
2. 学习、练习、复习三个阶段卡片；
3. 本章知识路线，当前推荐节点高亮；
4. 点击知识节点后展示该节点核心问题，并允许立即开始探索。

进入会话后：

- 左侧按真实时间顺序连续展示学生问题、AI 回答、素材和针对性反问；
- 右侧“章节知识树”用于看全章位置，“我的思维树”用于查看真实提问轨迹；
- 选择章节节点只改变浏览焦点；选择个人节点后才显示继续、支线、回溯、记忆候选操作；
- 页面不得同时混用旧 Mock Gateway 和远程会话状态。

## 对话调度修正

回答前识别学生状态：正常追问、明确卡住、可验证错误、理解稳定。

当学生说“不懂、不知道、不会、太抽象、卡住”时：

1. 禁止要求复述、总结或说出必要条件；
2. 改用更短的单步解释，并优先调用类比或可操作素材；
3. 反问必须降低门槛，询问学生想从哪种表示继续，或要求观察一个具体变化；
4. 最近三轮回答和反问做规范化去重，重复时切换表达路径。

正常追问仍遵循“回答是燃料、学生提问是主线”，反问必须指向定义、条件、反例或连接，不使用“你觉得呢”。

## 数据状态

- 章节树来自知识 Provider，是稳定的课程结构；
- 思维树来自 Learning Session API，是学生行为事实；
- 会话节点保存所用策略、回答、反问、素材和质量评分；
- 练习、复习阶段状态首版由 Mock 章节进度提供，后续接入真实学习事件聚合。

## 验收

- 学生能在一个页面看见完整章节以及学习、练习、复习三个阶段；
- 能从任一章节知识节点开始 1.2 对话探索；
- 桌面端可切换章节知识树和个人思维树，个人节点操作不影响章节树；
- 输入“不懂”后不再出现复述或必要条件问题，而是得到降阶解释与具体下一步；
- 连续三轮不重复同一回答或反问；
- 旧开发者入口进入同一远程章节工作台；
- 知识数据保持 Mock Provider 边界，未来接入正式知识库不修改 UI 契约。
