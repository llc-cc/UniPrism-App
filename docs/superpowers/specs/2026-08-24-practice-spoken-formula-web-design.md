# 练习公式 Web 语音输入设计

## 目标

在 UniPrism Flutter Web 的练习公式输入框中增加中文语音输入。学生说出一条简短数学表达后，浏览器先将语音识别成文本，后端再将数学口语转换为受控 LaTeX；前端校验并预览结果，只有学生确认后才插入当前公式光标位置。

初版只支持 Chrome 和 Edge，不处理 Android、iOS、连续听写、离线识别和白板笔迹识别。

## 设计原则

- 语音识别与数学语义转换分开，界面同时展示识别文字和公式预览，便于判断错误发生在哪一层。
- 模型只转写，不求解、不化简、不纠正学生表达。例如“x 加 x”必须保留为 `x+x`。
- 学生确认前不修改已有答案；失败、取消和超时均保留原 LaTeX 与光标上下文。
- 浏览器只发送最终识别文本，不向 UniPrism 后端上传或保存音频。
- 模型密钥只保存在后端环境变量，Flutter Web 不包含任何第三方密钥。
- 现有草稿、提交与答案协议继续使用单个 LaTeX 字符串，不新增数据库字段。

## 用户交互

语音入口位于公式键盘顶部的辅助操作栏，避免压缩填空题内嵌公式框。用户先聚焦公式输入框，公式键盘和“语音输入”按钮随之显示。

交互顺序：

1. 点击“语音输入”，浏览器请求麦克风权限。
2. 获得权限后开始监听，并显示“正在听…”和“停止”操作。
3. 浏览器产出最终中文文本后停止监听，界面进入转换状态。
4. 后端返回候选 LaTeX 后，界面显示识别文字、渲染后的公式、警告和可选候选。
5. 用户选择“插入公式”“重新说”或“取消”。
6. “插入公式”将选中的 LaTeX 插入当前公式光标；其余操作不改变答案。

若浏览器不支持语音识别，辅助栏显示不可用说明，现有公式键盘保持可用。

## 前端架构

### `SpeechFormulaRecognizer`

定义浏览器语音识别端口，只负责初始化、权限、开始、停止、取消和返回最终文本。Web 适配器使用 `speech_to_text`，语言固定为 `zh-CN`，初版按短句模式工作。

识别器不负责调用后端，也不直接修改公式控制器。测试使用可注入的假实现，不依赖真实麦克风。

### `SpokenFormulaRepository`

定义数学口语转换端口。远程实现复用 `PracticeApiClient` 的认证、超时和标准错误信封，将文本请求映射为类型化结果。

### `SpeechFormulaController`

编排语音识别、后端转换、取消和重试。状态机为：

```text
idle
  -> requestingPermission
  -> listening
  -> transcriptReady
  -> converting
  -> preview
  -> inserted

任意异步状态 -> error
取消或完成 -> idle
```

控制器用操作序号忽略过期异步回调，防止用户取消或重新开始后，旧请求覆盖新状态。销毁时停止监听，并禁止后续回调更新 UI。

### `FormulaLatexValidator`

集中处理候选 LaTeX 的长度、危险命令和解析校验。候选必须同时通过受控命令过滤、现有 `TeXParser` 解析和 `Math.tex` 渲染检查，才能进入预览。

禁止的内容包括 HTML/脚本相关命令、外部资源命令、宏定义和超出初版数学表达范围的环境。校验失败不会降级为普通文本插入。

### `PracticeFormulaVoicePanel`

负责麦克风按钮、监听状态、识别文本、错误提示和候选预览。组件依赖控制器状态，不直接发送网络请求。宽屏和 375px 窄屏均不得产生布局溢出。

`MathAnswerField` 只负责把确认后的 LaTeX 插入已有 `MathFieldEditingController`，并沿用当前 `onChanged` 草稿通知链路。

## 后端接口

### 请求

```http
POST /api/practice/formulas/from-spoken-text
Content-Type: application/json
Authorization: Bearer <access-token> 或 PracticeParticipant <participant-token>
```

```json
{
  "text": "从零到一积分 x 的平方 d x",
  "locale": "zh-CN"
}
```

`text` 去除首尾空白后必须非空，初版最大 200 个 Unicode 字符；`locale` 只接受 `zh-CN`。接口需要沿用练习身份校验，并按用户或参与者身份限流。

### 成功响应

```json
{
  "ok": true,
  "data": {
    "recognizedText": "从零到一积分 x 的平方 d x",
    "normalizedText": "从 0 到 1 积分 x 的平方 dx",
    "latex": "\\int_0^1 x^2\\,dx",
    "alternatives": [],
    "warnings": []
  }
}
```

`alternatives` 最多两个，且每个候选必须经过与主候选相同的服务端校验。服务端不返回模型自报的数值置信度，避免把不可校准分数呈现为可靠概率。

### 错误响应

错误继续使用练习 API 的标准信封，至少覆盖：

- `INVALID_SPOKEN_FORMULA_REQUEST`：空文本、超长或语言不支持；
- `SPOKEN_FORMULA_AMBIGUOUS`：无法形成安全主候选；
- `SPOKEN_FORMULA_INVALID_LATEX`：模型输出未通过校验；
- `SPOKEN_FORMULA_RATE_LIMITED`：调用频率过高；
- `SPOKEN_FORMULA_SERVICE_UNAVAILABLE`：模型超时或上游不可用。

## 后端转换流程

1. 校验身份、请求体、长度与限流。
2. 对常见口语做轻量规范化，例如中文数字、`d x`、空白和全角符号；不改变数学结构。
3. 调用支持结构化输出的模型，要求严格返回 `normalizedText`、`latex`、`alternatives` 和 `warnings`。
4. 明确提示模型只转写，不计算、不化简、不补全题意。
5. 对主候选和备选执行 LaTeX 长度、命令白名单和解析检查。
6. 没有安全候选时返回明确错误，不把原始模型文本透传给客户端。

接口为无副作用转换，不写数据库、不保存音频。日志只记录请求 ID、耗时、结果类型和脱敏错误码；默认不记录完整识别文本或 LaTeX。

## 错误与恢复

- 权限拒绝：解释如何在浏览器地址栏重新授权，保留公式键盘。
- 浏览器不支持：禁用语音按钮并提示改用 Chrome/Edge。
- 未检测到语音：回到空闲状态，允许立即重试。
- 用户取消：停止监听并使当前异步操作失效，不展示迟到结果。
- 网络或模型超时：显示重试，不改变已有答案。
- LaTeX 校验失败：不预览、不插入，提示重新表达。
- 存在歧义：展示主候选、最多两个备选和具体警告，由用户选择。
- 重复点击：同一时间只允许一个监听或转换操作。

## 测试设计

### Flutter 单元测试

- 状态机完整成功路径；
- 权限拒绝、不支持、无语音、识别错误和取消；
- 转换超时、接口错误、无效 LaTeX 和重试；
- 过期识别结果或网络结果不能覆盖新操作；
- 确认前答案不变，确认后只在当前光标插入候选；
- 校验器覆盖允许命令、危险命令、超长和解析失败。

### Flutter Widget 测试

- 聚焦答案框后出现语音入口；
- 监听、转换、预览和错误状态文案正确；
- 取消与重新说不修改答案；
- 主候选和备选可选择并插入；
- 1100px 与 375px 布局无溢出；
- 不支持语音时公式键盘仍然可用。

### 后端 Vitest

- 请求体、身份、限流和标准错误信封；
- 结构化模型响应映射；
- “只转写、不化简”的代表性中文数学表达；
- 危险命令、无效 LaTeX、空候选和上游超时；
- 日志不包含原始语音文本和模型密钥。

### 手工 Web 验收

在 Chrome 和 Edge 中使用真实麦克风验证权限、开始/停止、以下代表性表达、取消、重试和光标插入：

- `x 的平方加二 x 加一`；
- `根号下 x 加一`；
- `二分之一乘以 m v 的平方`；
- `从零到一积分 x 的平方 d x`；
- `当 x 趋近于无穷`；
- `负二的平方`，必须提示作用范围歧义。

## 首版验收标准

1. Chrome 和 Edge 能从真实麦克风获得一条中文短句并进入公式转换。
2. 支持数字、字母、四则运算、括号、分数、根式、幂、积分、求和和极限的常见中文说法。
3. 用户确认前原答案保持不变，确认后候选插入当前光标并进入现有草稿链路。
4. 权限拒绝、浏览器不支持、无语音、网络错误、模型错误和无效 LaTeX 均有可恢复提示。
5. Flutter 相关测试、后端相关 Vitest 和 Chrome/Edge 手工验收通过。

## 非目标与后续版本

- Android、iOS 和桌面原生应用权限适配；
- Firefox、Safari 的一致语音体验；
- 录音上传、连续听写和离线语音模型；
- 白板笔迹、图片数学 OCR；
- 自动求解、步骤生成或答案正确性判断；
- 保存语音、识别历史或新增数据库表。
