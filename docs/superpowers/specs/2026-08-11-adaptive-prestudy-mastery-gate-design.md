# 自适应预习掌握闸门设计

## 1. 背景与目标

现有 1.2 预习探索已经搭建章节入口、远程会话、连续对话、互动素材、微测、反思总结、历史恢复和开放探索兼容链路。本次不重建第二套课堂，而是在现有 `GUIDED_LESSON` 会话聚合上补齐自适应教学闭环：先判断学生当前理解，再决定讲解深度；所有学生都必须完成一道独立基础题，答对后才能完成当前知识点，并自主选择是否进入更高阶内容。

最终用户流程为：

```text
选择章节
→ AI 老师呈现章节大纲与可学习方向
→ 学生选择知识点
→ 诊断提问
→ 根据诊断结果选择讲解深度
→ 所有学生完成无提示基础题
→ 答错则针对性讲解并换题复验
→ 独立答对后完成当前知识点
→ 展示 2～3 个更高阶方向
→ 学生选择继续学习或结束
```

## 2. 已确认的产品规则

1. 课堂以一对一讲解和发散式追问为主，练习只承担诊断与掌握验证，不演变为连续刷题。
2. 学生即使表示“已经会了”，也不能直接完成知识点；诊断表现良好时只能跳过重复讲解，仍必须完成一道独立基础题。
3. 通过条件同时包含答案正确和关键原理成立。只猜中答案、照抄提示或在提示开启时完成，都不能形成独立掌握证据。
4. 答错不是终止条件。AI 老师必须根据错误类型缩小问题、解释缺失原理、给出例子或互动素材，再提供一道同层但不同表述的新题复验。
5. 系统不能无限重复同一道题。连续三次未通过后，进入完整示范与更小步教学，但仍不能自动标记掌握；学生需要在后续新题中独立答对。
6. 当前知识点完成后展示更高阶方向及其关联原因，由学生决定继续或结束，不自动跳转。

## 3. 现有框架审计

### 3.1 已有且必须保留

- Flutter 章节知识节点通过 `GUIDED_LESSON` 创建引导会话，自由问题继续使用 `OPEN_EXPLORATION`。
- 后端 `LearningSession` 聚合持久化 `teachingFlow`，阶段推进以服务端快照为准。
- 当前阶段已覆盖 `DIALOGUE → ASSET → FOCUS → REFLECT`，并具备素材事件、练习尝试、幂等、revision、账号历史和会话恢复。
- Flutter 已有教学目标、阶段动作、素材互动、微测弹窗、反思总结和技术轨迹展示。
- 旧会话没有 `teachingFlow` 时仍按开放探索渲染。

### 3.2 当前缺口

- 现有诊断回答无论质量如何都会进入素材阶段，不能让已掌握学生跳过重复讲解。
- 微测动作只传 `practiceId`，弹窗没有展示具体题干。
- 只有负数乘法具备可返回 `MASTERED` 的确定性判定；其它已登记 Mock 教案会永久停留在 `PARTIAL`。
- 微测失败后只返回通用对话提示，没有把判题反馈、缺失原理和下一轮题目编入明确的修复动作。
- 更高阶方向虽有 `nextChallenges` 数据雏形，但预习场景会清空该列表，完成页也没有选择入口。
- 当前 Flutter 默认加载固定的负数章节，学科/章节选择与 Provider 大纲尚未形成完整用户入口。

这些缺口必须先补齐，不能把“协议或 DTO 已存在”当成用户已经可以使用的功能。

## 4. 方案选择

采用“扩展现有引导会话聚合”的自适应掌握闸门方案。

不采用仅修改页面文案的方案，因为判定、重试和解锁必须由服务端持久化，才能恢复、审计并防止客户端自行声明掌握。

不在本阶段采用完全动态的 AI 课程规划。章节大纲、练习和进阶关系先由版本化 `GuidedLessonProvider` 提供；AI 老师负责自然语言讲解与追问，但不能自行改写通过条件。未来正式知识库替换 Provider 时，不改变 Flutter 会话协议。

## 5. 自适应教学状态与决策

### 5.1 保持现有阶段兼容

继续使用 `DIALOGUE`、`ASSET`、`FOCUS`、`REFLECT`，避免破坏现有快照和页面：

- `DIALOGUE`：首次诊断或答错后的针对性修复对话。
- `ASSET`：仅在学生需要讲解、示例或互动验证时进入。
- `FOCUS`：所有学生都必须进入的无提示基础题验证。
- `REFLECT`：已经取得独立正确证据，可以总结并选择后续方向。

流程快照增加版本化字段：

- `diagnosticLevel`: `UNKNOWN | READY_FOR_CHECK | NEEDS_CLARIFICATION | NEEDS_TEACHING`；
- `attemptRound`: 当前独立验证轮次；
- `activePractice`: 当前必须展示的题目快照，包含题干、作答格式和判定版本；
- `repairFocus`: 上次失败后需要补足的原理或步骤；
- `nextLearningOptions`: 当前知识点通过后可选择的后继知识节点。

旧 V1 快照缺少这些字段时使用安全默认值，不影响历史会话读取。

### 5.2 诊断分流

诊断回答由后端依据教案规则和安全的结构化评估得到以下结果：

- `READY_FOR_CHECK`：学生能够正确表达核心原理。直接进入 `FOCUS`，跳过素材讲解，但不能跳过基础题。
- `NEEDS_CLARIFICATION`：结论基本正确但依据不完整。教师先做一次短追问或局部说明，再进入 `FOCUS`。
- `NEEDS_TEACHING`：答错、说不知道或出现关键误解。进入 `ASSET`，完成讲解或互动后再进入 `FOCUS`。

模型只能生成面向学生的表达，诊断级别由服务端可审计规则或受约束评估结果决定，客户端不能提交诊断结论。

### 5.3 基础题与通过规则

每个可启动的引导教案必须同时登记：

- 至少三道同目标、同难度、不同表述的基础题变体；
- 题目实际题干和作答字段；
- 关键答案、关键原理或结构化评分规则；
- 错误类型到 `repairFocus` 的映射；
- 对非终点知识点登记 2～3 个完成后的高阶方向；终点知识点必须显式标记为终点。

缺少题目、判定规则或修复映射的教案不能创建 `GUIDED_LESSON`，服务端返回可识别业务错误，不能创建一条永远无法完成的课堂。后继关系缺失不应阻断已经开始的学习和完成操作，但非终点教案的契约测试必须失败并要求补齐配置。

每次提交产生 `MASTERED | PARTIAL | RETRY`：

- `MASTERED`：答案与原理均通过且本次未使用提示，进入 `REFLECT`。
- `PARTIAL`：结论或方法部分正确，回到 `DIALOGUE` 做局部修复。
- `RETRY`：关键结论错误或证据不足，回到 `DIALOGUE` 做基础讲解。

重新验证必须选择不同题目变体，并保留前次尝试和反馈。学生看见的是具体缺口与下一步，不显示内部评分、证据代码或模型置信度。

## 6. 章节大纲与进阶选择

章节入口继续由 `KnowledgeProvider.getChapterOverview()` 提供结构化大纲。第一阶段允许使用已审核的 Mock/版本化大纲，AI 老师将标题、核心原理和关联方向转成自然语言开场，不在客户端硬编码教学事实。

Flutter 需要启用真实可用的章节选择入口，不再把未使用的学科选择器或固定默认章节视为完成状态。若当前只登记一个章节，页面应明确显示可用范围，不伪造其它章节。

知识点独立通过后，服务端在 `REFLECT`/完成快照中返回 2～3 个 `nextLearningOptions`。每项包含：

- 后继知识点 ID、标题和所属章节；
- 与当前知识点的关系；
- 难度提升说明；
- 预计用时和开场问题；
- 是否满足前置条件。

学生选择某项后，通过现有会话创建能力开启新的 `GUIDED_LESSON`；选择结束则保留总结和推荐，稍后可以从历史恢复。终点知识点或后继 Provider 暂时不可用时仍允许正常完成，并显示“当前暂无已审核的进阶方向”。

## 7. 前后端职责

### 7.1 后端

- `GuidedLessonProvider` 提供大纲、诊断规则、题目变体、判定规则、修复映射和后继关系。
- 引导流程协调器只做确定性阶段编排，不读写数据库、不生成模型思维链。
- `LearningSessionService` 调用教学模型、判定器和 Repository，并在同一会话 mutation 中持久化教学阶段与证据。
- Repository 继续负责 revision、幂等、素材事件和练习尝试持久化。
- 会话完成和高阶推荐只根据已持久化的独立正确证据解锁。

### 7.2 Flutter

- 页面展示服务端给出的章节大纲、教师动作、具体题干、反馈与进阶方向。
- Controller 只提交学生回答、素材事件、练习尝试和后继选择，不自行判定会不会或是否通过。
- 微测弹窗必须显示题干，提交期间禁用重复操作，失败后保留草稿并允许按同一幂等动作重试。
- 完成页提供“继续学习”和“先结束”，不自动创建下一会话。

## 8. 失败与边界

- 教案缺少题目、判定器或修复映射：创建前拒绝并指出教案配置错误；仅后继关系不可用时不阻断当前知识点完成。
- 模型讲解失败：保留当前阶段，使用已有安全降级文案，不伪造掌握结果。
- 判定服务失败：保留学生作答草稿和当前题，不记入通过证据。
- 网络重试：复用事件/尝试的稳定 ID，防止重复累计证据或重复推进阶段。
- 连续三次未通过：切换到完整示范与更小步教学；不设自动通过，也不使用无限递归重试。
- 学生主动退出：保存当前阶段和草稿边界，下次从服务端快照恢复。
- 旧开放探索和已完成历史会话保持原行为，不能因新字段缺失崩溃。

## 9. 验证与回归审计

开发前先运行当前前后端相关测试建立基线；开发后同时验证新闭环和已有预习框架。

### 9.1 后端必测路径

- 已会学生：诊断通过 → 跳过素材 → 仍显示并完成基础题 → 进入反思。
- 不会学生：诊断失败 → 讲解/素材 → 基础题失败 → 针对性修复 → 新题独立通过。
- 提示完成不能形成 `INDEPENDENT`；必须换题无提示通过。
- 每个已登记 Mock 教案都存在可达的 `MASTERED` 路径。
- 三次失败触发完整示范，但不会自动通过或死循环。
- 只有独立通过后返回进阶方向；选择后创建新的正确知识点会话。
- 会话能从 `DIALOGUE`、`ASSET`、`FOCUS`、`REFLECT` 分别恢复。
- 重复提交、revision 冲突、模型失败、判定失败和未知教案都有确定性结果。
- `OPEN_EXPLORATION` 和旧快照兼容测试继续通过。

### 9.2 Flutter 必测路径

- 章节入口呈现服务端大纲并能启动指定知识点。
- 已会学生可以跳过讲解，但不能跳过基础题。
- 微测明确展示题干、推理和答案输入。
- 错误反馈、修复动作和换题过程可见。
- 提交中不能重复点击，失败后可以重试。
- 独立通过后展示进阶选项，选择继续或结束均产生正确动作。
- 历史恢复、只读完成页、长对话滚动、移动端布局和自由探索模式不回归。

### 9.3 完整质量门槛

- 后端运行引导流程、Session Service、Repository、Route 和迁移相关 Vitest。
- 后端运行 TypeScript 检查与 Prisma 校验。
- Flutter 运行 `dart analyze lib/main.dart test`、对话探索相关测试和完整 `flutter test`。
- 明确区分本次新增失败与两个仓库原有的未提交改动或既有失败。

## 10. 数据与安全

- 不新增客户端密钥或外部凭证。
- 教学状态继续存入版本化会话 JSON；练习尝试和素材事件沿用现有持久化边界。
- 不记录或返回模型思维链，只保存学生可见提示、结构化判定、证据来源和可审计 reason code。
- 章节大纲、题目、答案和后继关系必须来自允许的 Provider；客户端不能伪造通过、提示状态或解锁关系。

## 11. 本阶段明确不做

- 不让大模型自由生成不可审计的课程图或正确答案。
- 不接入完整正式知识库、MCP 教学资产市场或跨学科自动排课。
- 不建立复杂积分、排名、奖励动画或题海系统。
- 不重写现有会话、历史、思维树和开放探索架构。
