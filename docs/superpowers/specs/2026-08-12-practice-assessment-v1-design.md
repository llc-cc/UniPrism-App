# 练习评分与能力画像 V1 设计

日期：2026-08-12

## 1. 目标

在 UniPrism 中新增独立的“练习”模块，以 2026 新高考 I 卷数学的 19 道题为第一套基准卷，完成以下闭环：

1. 为题目生成可解释、可版本化的多维难度画像；
2. 记录学生答案、解题步骤、提示和修改等事实；
3. 将一次作答转换为阅读、理解、计算、推理、技巧、自我纠错和表达七类能力证据；
4. 将多次证据聚合为知识点级学生能力画像；
5. 保存可直接导出为小模型训练集的结构化样本；
6. 保持评分引擎可替换，V1 不依赖已经训练好的小模型。

V1 不承担自动组卷、跨学科评分、遗忘曲线复习调度和高考分数预测。

## 2. 与预习模块的边界

练习模块使用独立的领域目录、状态和数据契约，不导入 `dialogue_exploration` 下的 Controller、Widget、DTO 或 Repository 实现。

预习模块只能通过版本化的 `PrestudyHandoffV1` 向练习模块提供：

- 来源预习会话 ID；
- 建议关注的证据节点；
- 可选的知识原子 ID；
- 学生在预习阶段暴露的误区线索。

练习模块拥有并管理：

- 试卷与题目版本；
- 作答会话和作答尝试；
- 答案判定、题目画像、能力证据；
- 长期能力画像；
- 训练样本导出。

练习结果不能回写或修改预习节点。后续若需要让预习模块读取练习结论，应新增反向的版本化交接 DTO。

## 3. V1 内容范围

第一套基准卷固定为 `cn-gaokao-2026-new-i-math-v1`，包含 19 道题：

- 第 1 至 8 题：单项选择；
- 第 9 至 11 题：多项选择；
- 第 12 至 14 题：填空；
- 第 15 至 19 题：解答题，按小问和关键步骤判定。

试题正文、图片和官方答案必须来自获得使用权限的内容源。仓库只保存经过授权导入的内容或测试用自造题，不能把第三方回忆版直接作为生产题库。每次导入保存来源标识、内容摘要哈希、授权标记和题目版本；内容或评分规则变化必须生成新版本，历史作答继续引用旧版本。

## 4. 核心领域模型

### 4.1 题目难度画像

`QuestionDifficultyProfileV1` 对题目自身评分，与具体学生无关。六个维度都采用 `0..4` 有序等级：

- `knowledgeLoad`：调用知识的数量、层级和组合程度；
- `readingLoad`：信息密度、条件识别和新定义转换要求；
- `reasoningLoad`：推理链、分类讨论和证明深度；
- `calculationLoad`：运算长度、符号复杂度和精度要求；
- `techniqueDependency`：对构造、不变量、换元、反例等方法的依赖；
- `stepDepth`：完成题目所需关键步骤数量与阶段数量。

每个维度保存 `band`、`confidence`、`evidenceCodes` 和 `source`。`overallBand` 由版本化规则根据六个维度计算，不允许评分器单独生成一个与子维度矛盾的总分。

### 4.2 题目评分规则

`QuestionRubricV1` 包含：

- 题型和各小问分值；
- 最终答案的判定器类型；
- 一条或多条允许的解题路径；
- 每条路径的关键步骤、前置依赖和允许的等价表达；
- 知识点标签及其对能力维度的相关权重；
- 常见错误标签及对应的错误位置；
- 哪些能力维度可以由该题观察。

Rubric 是判题和能力分析的共同输入，但二者输出保持分离。

### 4.3 作答尝试

`PracticeAttemptV1` 保存不可变的提交快照：

- 学生、练习会话、题目版本和 rubric 版本；
- 客观题选项、填空表达式或解答题各小问答案；
- 按顺序编号的学生解题步骤；
- 打开、请求提示、提交、查看反馈、重新提交和完成等粗粒度事件；
- 服务端计算的用时、提示次数、提交次数和修改次数；
- 幂等键与创建时间。

客户端只上报事实，不上报能力分数、答案是否正确、总用时或学生 ID。身份、派生统计和判定均由服务端完成。V1 不采集逐键输入。

### 4.4 一次作答的能力证据

`AttemptAssessmentV1` 对以下七个维度分别输出：

- `reading`；
- `understanding`；
- `calculation`；
- `reasoning`；
- `technique`；
- `selfCorrection`；
- `expression`。

每个维度必须包含：

- `status`：`observed`、`insufficientEvidence` 或 `notApplicable`；
- `band`：仅在 `observed` 时出现，范围 `0..4`；
- `confidence`：范围 `0..1`；
- `evidenceStepIds`：只能引用本次作答中真实存在的步骤；
- `factCodes`：提示、重做、规则判定等确定事实；
- `errorTags`：来自 rubric 的版本化错误标签；
- `assessorVersion` 和 `rubricVersion`。

最终答案正确不自动提高理解、推理或技巧；没有过程证据时这些维度必须输出 `insufficientEvidence`。答错也不自动降低所有维度，例如思路正确但算术出错时，应保留理解和推理证据。

### 4.5 长期能力画像

`StudentAbilityProfileV1` 按“学科 + 知识点 + 能力维度”聚合，而不是给学生一个全局数学能力总分。每个聚合项保存：

- 连续估计值 `0..100`；
- 置信度；
- 有效样本数；
- 最近证据时间；
- 最近证据 ID；
- 聚合器版本。

聚合权重由题目对该维度的相关度、作答独立程度、题目难度、评估置信度和时间衰减共同决定。提示后完成属于辅助证据；反馈前自主修改并修正可提升自我纠错证据。证据不足时不更新对应维度。

## 5. 评分流水线

一次提交按以下顺序处理：

1. API 校验身份、题目版本、当前会话状态、字段长度和幂等键；
2. Repository 保存不可变作答快照和事实事件；
3. 确定性判题器同步计算选项、表达式或分步得分；
4. 同步返回题目结果和可面向学生展示的反馈；
5. 后台评估任务读取题目画像、rubric、作答步骤和确定事实；
6. `AttemptAssessor` 生成七维能力证据；
7. 证据校验器拒绝不存在的步骤引用、越界分数、非法错误标签和与确定事实冲突的结果；
8. 有效证据写入 Repository，并由聚合器更新学生能力画像；
9. 训练样本投影器生成去标识化的训练记录。

后台评估失败不回滚已经完成的判题，也不阻塞学生继续答题。失败任务保存可重试状态；多次执行以 `attemptId + assessorVersion` 保证幂等。

## 6. V1 评分器策略

评分器通过 `AttemptAssessor` 端口接入，V1 提供两种实现：

1. `RuleBasedAttemptAssessor`：使用确定事实、步骤命中和 rubric 错误标签产生基础能力证据，作为无模型配置时的可靠保底；
2. `RemoteStructuredAttemptAssessor`：调用已配置的大模型，要求严格 JSON 输出，并在写入前通过同一证据校验器。

生产环境不得静默启用 Mock 评分器。远程评分器超时、输出非法或与规则冲突时回退规则评分；规则仍无法判断的维度标记为证据不足。

V1 不把题目评分和学生评分合成一次大模型调用。题目画像在题目版本发布时生成并缓存；学生评分只在提交作答后生成。

## 7. 小模型训练数据与训练方式

训练数据由 `TrainingExampleV1` 表达：

- 输入：题目类型、题目内容引用、题目画像、rubric、标准步骤、学生步骤、答案、确定事实和交互统计；
- 标签：七个能力维度的状态、`0..4` 等级、证据步骤 ID 和错误标签；
- 元数据：题目结构族、知识点、题目版本、评分器版本和标签置信度；
- 隐私：不包含用户 ID、会话 ID、设备信息或自由对话中的个人信息。

冷启动阶段由规则标签和结构化大模型标签形成自动银标。只有满足以下条件的样本进入训练集：

- 通过 Schema 和证据引用校验；
- 不与确定性判题事实冲突；
- 标签置信度达到版本化阈值；
- 两次独立评估在关键维度上达到一致性阈值；
- 文本通过个人信息清洗。

小模型选择中文数学能力较好的 1B 至 4B 基座，使用 QLoRA 做监督微调。训练目标是多任务有序分类，不直接回归任意 `0..100` 分数：

- 七个维度分别预测证据状态；
- 对 `observed` 维度预测 `0..4` 等级；
- 预测可引用步骤和错误标签；
- 置信度由验证集上的输出概率校准得到，不使用模型自报置信度。

训练、验证和测试集必须同时按学生和题目结构族隔离。同一道题仅替换数字或情境的变式属于同一结构族，不得跨集合泄漏。

小模型首次上线后只接管高置信度样本；低置信度、规则冲突和未见题型继续回退远程评分器或输出证据不足。模型更新必须保留旧版本，历史能力证据不自动重算。

## 8. Flutter 模块结构

新增 `lib/features/practice_assessment/`，采用以下边界：

- `core/`：练习会话、题目、作答草稿、判题结果和能力证据模型；
- `adapters/`：HTTP API、DTO 和首版 Mock Repository；
- `application/`：练习会话 Controller，只编排加载、保存草稿和提交；
- `presentation/`：整卷导航、题目作答、结果反馈和能力概览；
- `practice_assessment.dart`：模块公开导出。

页面不解析评分 JSON、不推导答案正确性、不聚合能力分。所有网络请求必须具有超时、错误转换和空数据保护；异步 UI 更新前检查 `mounted`。

V1 通过开发者工具提供独立“练习评分实验室”入口。它不挂在预习页面内部，也不复用预习页面 Controller。后续正式导航只需要替换入口装配，不改变模块内部协议。

## 9. 后端模块结构

正式后端新增 `lib/practice-assessment/`：

- `contracts.ts`：Zod 请求、响应和领域契约；
- `questionRepository.ts`：试卷、题目版本与 rubric 读取；
- `attemptRepository.ts`：会话、提交、事实事件和能力证据持久化；
- `answerJudge.ts`：选择、填空和分步确定性判题；
- `attemptAssessor.ts`：评分器端口、规则实现和远程实现；
- `assessmentValidator.ts`：证据引用与规则冲突校验；
- `abilityAggregator.ts`：长期能力聚合；
- `trainingProjection.ts`：去标识化训练数据投影；
- `service.ts`：用例编排，不包含数据库和模型供应商细节；
- `http.ts`：鉴权、限流、幂等和错误映射。

本 Flutter 仓库不复制正式后端内部实现。若需联调，只保存版本化 HTTP 契约和 Mock 适配器；后端代码在正式后端仓库按相同模块名实现。

## 10. HTTP 契约

V1 至少提供：

- `GET /api/practice-papers/cn-gaokao-2026-new-i-math-v1`：读取已授权的整卷摘要；
- `POST /api/practice-sessions`：创建整卷练习，可选携带 `PrestudyHandoffV1` 来源 ID；
- `GET /api/practice-sessions/{id}`：恢复题目进度、草稿和已判结果；
- `PUT /api/practice-sessions/{id}/drafts/{questionId}`：幂等保存草稿；
- `POST /api/practice-sessions/{id}/attempts`：提交某题或小问；
- `POST /api/practice-sessions/{id}/events`：上报允许的粗粒度事实事件；
- `POST /api/practice-sessions/{id}/complete`：完成整卷；
- `GET /api/practice-sessions/{id}/summary`：获取作答结果和学生可见能力概览。

所有写接口使用 `Idempotency-Key`。服务端只信任认证身份，不接受客户端指定用户 ID。标准答案、完整 rubric、内部置信度和训练标签不下发 Flutter。

## 11. V1 用户体验

学生进入练习评分实验室后看到 19 题目录和进度。客观题选择答案后填写一条可选“解题依据”；填空题填写答案和关键步骤；解答题按小问输入多步过程。

解题依据在客观题中保持可选：不填写仍可判题，但阅读、理解、推理和技巧通常记为证据不足。系统不能为了获得训练数据阻止学生提交正确答案。

提交后立即展示：

- 该题或小问的确定性结果；
- 命中的关键步骤；
- 一个最重要的错误或下一步提示；
- 能否修改后再次提交。

能力概览只展示“已观察到的优势、待巩固和证据不足”，V1 不向学生显示内部模型置信度、训练标签或过度精确的单题能力分。

## 12. 测试与验收

Flutter 至少覆盖：

- 练习模块不依赖预习内部类型；
- 19 题目录按题型和编号解析；
- 客观题、填空题和解答题草稿校验；
- 草稿保存、提交、失败重试和恢复；
- 证据不足不会显示为能力低；
- 长内容滚动、加载、空状态和失败状态。

后端至少覆盖：

- 题目/rubric 版本不可变；
- 四类题型的确定性判题；
- 等价表达、部分步骤、提示和重提边界；
- 幂等提交不产生重复尝试；
- 评分失败不影响判题结果；
- 证据引用、等级范围、错误标签和规则冲突校验；
- 能力聚合忽略证据不足项；
- 训练投影不包含身份字段；
- 跨账号访问隔离和输入长度限制。

Flutter 验证执行相关 `dart analyze` 与 `flutter test`；后端执行相关 Vitest、TypeScript 类型检查和数据库契约检查。

## 13. 分阶段交付

V1.0：独立 Flutter 练习模块、版本化契约、19 题元数据加载、Mock 数据、作答流程、规则评分展示和训练事件结构。

V1.1：接入正式后端的会话、题库、判题、能力证据和持久化；启用结构化远程评分器。

V1.2：积累自动质检后的银标数据，训练并离线评估第一个小模型；只对高置信度样本灰度启用。

V1.3：增加同结构变式题、能力画像驱动选题和错因补救，但保持本设计的版本化契约兼容。

## 14. 已知限制

- 没有人工审核时，语义能力标签属于自动银标，模型质量上限受评分 rubric 和教师模型影响；系统通过规则冲突校验、双评估一致性和拒绝低置信度样本降低风险，但不能把银标宣称为人工金标。
- 只有 19 道真题无法训练可靠小模型；真题用于建立 rubric 和验收，训练仍依赖真实作答与同结构变式题。
- V1 不根据单题结果直接预测高考分数，也不把一次作答解释为稳定人格或固定能力。
- 正式题目内容接入依赖明确的使用授权与内容版本，开发阶段可用自造题验证完整技术链路。
