# 练习底层判断审查与规则选题 V1 设计

## 目标

第一版解决两个开发验收问题：

1. 开发人员选择一道题后，能够同时确认题目六维难度的 Gold、Actual、偏差与规则版本。
2. 开发人员能够审查一次模拟或真实作答经过判题、行为事实提取、七维证据判断和画像更新的完整链路。

在此基础上增加一个不依赖小模型的规则选题预览，验证“根据知识范围和能力缺口选择下一题”的规则是否合理。规则选题本期只在管理端运行和解释，不改变学生 App 的正式题序。

## 方案选择

### 方案 A：统一管理端审查台（采用）

沿用 `/admin/practice-benchmark`，把题目难度、模拟行为、真实作答和规则选题放在同一管理端工作区。共享现有 Question Difficulty Engine、Cognition V2 Engine、Gold 和画像更新器，避免页面另写一套判断逻辑。

优点是开发人员能沿同一道题查看静态难度、动态作答证据和推荐原因；缺点是管理端需要增加只读脱敏投影。

### 方案 B：在 Flutter App 内显示内部判断

实现速度表面较快，但会破坏“App 只展示学生安全反馈”的边界，也容易把置信度、错误标签和内部步骤泄露给学生，因此不采用。

### 方案 C：只保留离线 JSON 报告

安全且简单，但产品负责人不能交互构造行为或查看选题排序，不能满足第一版测试需求，因此不采用。

## 管理端信息架构

管理端保留现有五个 Benchmark 区域，并新增两个区域：

- `统一判断审查`：选择题目和模拟行为后，在一页展示题目难度、输入行为、判题、事实、七维证据、画像前后和偏差。
- `规则选题预览`：输入当前知识范围、七维能力、最近练习和队列位置，展示候选题得分、分桶与推荐理由。

真实作答审查作为 `统一判断审查` 的只读数据源。管理员先从最近作答列表选择 attempt，再查看脱敏审查投影；不得在网络响应中返回答案原文、解题过程原文、参与者 ID、会话 ID、邮箱、手机号或 token。

## 题目难度审查

每道题展示六个固定维度：

- `knowledgeLoad` 知识负荷
- `readingLoad` 阅读负荷
- `reasoningLoad` 推理负荷
- `calculationLoad` 计算负荷
- `techniqueDependency` 技巧依赖
- `stepDepth` 步骤深度

展示 Gold、Actual、带符号偏差、绝对偏差、人工标注理由和 `difficulty-rule-v1`。Gold 继续来自独立文件，不能复制题目种子中的 difficulty。

## 作答内部审查

审查链固定为：

```text
行为摘要
  → 判题 outcome
  → facts / rubric steps
  → READ、COMP、REPR、STRAT、CALC、PROOF、CHECK
  → 画像 before / after / direction
```

每个维度展示：

- `OBSERVED`、`INSUFFICIENT_EVIDENCE` 或 `NOT_APPLICABLE`
- 仅 `OBSERVED` 有 0～4 档；另外两种状态保持 `null`
- 置信度、证据质量、命中步骤、事实代码、错误标签
- 画像的档位、证据数、信息量、成熟度和变化方向

模拟案例可以显示输入答案和过程，因为内容由管理员当次输入且不持久化。真实作答只显示尝试次数、上次结果、提示等级、答案修改次数、过程修改次数、重访次数和时间线质量，不显示答案或过程原文。

## 规则选题 V1

### 输入

- 当前知识点集合
- 七维能力档位；`null` 表示证据不足，不能按 0 档处理
- 最近作答的题目、知识点、结构族、结果和时间
- 当前推荐队列位置
- 候选题的知识点、结构族、六维难度和派生七维需求

### 五层机制

1. **知识约束**：与当前知识完全无关的题默认过滤；无知识范围时进入开发预览降级模式并明确标记。
2. **能力缺口**：优先选择对当前薄弱且已有证据维度有训练价值的题；证据不足维度不视为低能力。
3. **难度匹配**：目标需求靠近能力档位上方约 `0.3`，连续成功后由画像提高自然推动难度上升。
4. **迁移与多样性**：降低近期重复题和重复结构族得分，奖励相同目标能力下的新结构族或不同知识情境。
5. **间隔复习**：对到期知识点增加复习价值，避免候选池全部来自当前薄弱点。

### 队列配比

使用确定性的十题周期：

- 位置 1～6：`TARGET_GAP`，当前能力缺口，占 60%
- 位置 7～8：`CONSOLIDATION`，当前知识巩固，占 20%
- 位置 9～10：`REVIEW_TRANSFER`，间隔复习或迁移，占 20%

若目标分桶没有候选题，按 `TARGET_GAP → CONSOLIDATION → REVIEW_TRANSFER` 的稳定顺序回退，并在结果中记录回退原因。

### 可解释评分

每个候选题返回 0～100 的基础分和分项：

```text
total = knowledgeMatch
      + abilityGapMatch
      + difficultyMatch
      + transferValue
      + spacingValue
      + varietyValue
      - overloadPenalty
```

推荐结果必须包含规则版本、目标分桶、每个分项、总分、主要推荐理由和风险提示。相同输入必须得到相同排序；同分按题号、题目 ID 稳定排序。

## 七维题目需求派生

当前19题没有独立的七维题目需求人工标注，因此第一版从已有特征保守派生并明确标记为 `derived-demand-v1`：

- READ：阅读负荷
- COMP：知识负荷与推理负荷的组合
- REPR：表征转换次数和题型
- STRAT：技巧依赖与非常规模式
- CALC：计算负荷
- PROOF：推理负荷、解答题类型和步骤深度
- CHECK：自检 rubric、易错变形和步骤深度

派生需求只服务选题规则预览，不作为新的题目 Gold，也不能反向修改难度 Gold。

## 安全与权限

- 所有管理端 API 必须先通过 `requireAdminSession`。
- 真实作答端点只读、`no-store`，使用固定上限和严格 ID 校验。
- 真实作答 DTO 使用白名单构建，并通过测试禁止答案、过程、身份和 token 字段。
- 学生提交 DTO 保持不变，不返回 V2 Shadow、置信度、事实代码或错误标签。
- 本期不新增数据库表，不改变 V1 正式画像，不训练或调用小模型。

## 错误与降级

- 找不到 attempt：返回 404，不回退到任意其他学生数据。
- 数据库不可用：真实作答区域显示不可用，但模拟审查、难度 Benchmark 和规则选题仍可运行。
- 能力证据不足：保持 `null`，选题时使用中性先验并降低能力缺口权重。
- 当前知识无候选题：显示过滤原因并允许开发人员切换到降级预览，不静默推荐无关题。

## 验收

1. 选择任一道题可以在同一管理端页面查看六维 Gold、Actual 与偏差。
2. 自定义“首次错误、无提示、自主修改、第二次正确”时，能够查看 CHECK 等七维证据和画像变化。
3. 管理员可选择真实 attempt 并查看脱敏行为摘要与七维 Shadow，响应不含答案、过程和身份字段。
4. 手工设置 REPR=1.9 后，规则预览优先展示 REPR 需求接近且略高于1.9的相关题，并解释分数。
5. 十题推荐周期满足 60/20/20；近期重复结构受到惩罚；证据不足不会被当成0档。
6. 相同输入重放两次的排序和解释完全一致。

## 第一版限制

- 当前19题是自造结构演示题，不是2026新高考Ⅰ卷官方题目。
- 七维题目需求是规则派生值，后续需要独立人工标注和文献校准。
- Adaptive V1 只做管理端预览，不直接改变学生 App 题序。
- V2 仍是 Shadow；现有 Benchmark 质量目标未全部达标前，不替换 V1 正式画像。
