# 练习填空题数学公式键盘 V1 设计

状态：已确认，待实施
日期：2026-08-13

## 1. 目标

在现有练习评估 App 的填空题中提供可直接排版的数学公式输入框和屏幕软键盘，使学生能够输入分式、根式、上下标、函数、关系符号等普通文本键盘难以表达的答案，同时继续复用现有草稿保存、行为事件、提交判题和认知证据链路。

本期只改填空题的答案输入体验。选择题保持现有选项控件；解答题继续使用普通答案与解题过程文本框；不新增第二套练习会话或独立判题接口。

## 2. 方案选择

第一版采用 Flutter 原生 `math_keyboard` 作为公式编辑内核，并用 UniPrism 的颜色、间距、圆角和响应式容器调整外层样式。

未选择以下方案：

- 不把参考仓库的 React `MathLive` Web Component 嵌入 Flutter。该实现适用于 Next.js，直接复用会造成 Web 与移动端两套编辑行为和平台视图测试负担。
- 不在第一版自研完整公式 AST、光标和撤销系统。符号数据可以自有，但复杂编辑状态复用成熟组件，减少分式槽位、上下标导航和软键盘遮挡错误。
- 不使用普通 `TextField` 拼接 LaTeX 并另开预览框。学生应直接看到排版结果，而不是编辑裸命令。

## 3. 前端架构

### 3.1 组件边界

新增独立的填空题公式输入模块，建议拆分为：

- `MathAnswerField`：持有 `MathFieldEditingController` 与 `FocusNode`，负责外部草稿和公式编辑状态的双向同步。
- `PracticeFormulaKeyboardTheme`：统一公式输入框、键盘容器、焦点态和错误态的 App 样式，不承载答案业务规则。
- `practice_formula_symbols.dart`：从数学/物理符号大全提取受控分类、变量和首版可见键位；数据与 Widget 分开，便于后续扩展物理键盘。
- 现有 `_QuestionCard`：只根据题型选择普通输入或 `MathAnswerField`，仍通过 `onAnswer(String)` 把结果交给 Controller。

`PracticeSessionController` 继续只保存字符串草稿，不依赖公式组件类型。页面切题、恢复草稿和远程保存时，公式输入组件以 `question.id` 和当前 `draft.answer` 为真实来源，避免上一题编辑状态串入下一题。

### 3.2 页面集成

`PracticeAssessmentLabPage` 外层使用 `MathKeyboardViewInsets`，让数学软键盘出现时和系统键盘一样推动内容，而不是遮挡输入框或提交按钮。

填空题输入区表现为：

1. 点击排版后的公式输入框获得焦点；
2. 页面底部打开数学键盘；
3. 点击分式、根式、幂等结构键后，光标自动进入第一个可编辑槽位；
4. 左右键在公式节点间移动，退格删除当前节点，确认键收起键盘；
5. 每次实际公式变化只触发一次 `updateAnswer`，继续沿用现有防抖草稿保存与 `ANSWER_CHANGED` 行为事件。

电脑网页同时支持物理键盘输入，学生不必只能点击软键盘。

## 4. 键盘内容与视觉

符号来源以 `D:\ywkeji\Uniprism\UniPrism_New-main\docs\high-school-math-physics-formula-keyboard-latex.md` 为准。第一版面向 2026 新高考数学填空题，按使用频率控制首屏密度：

- 数字与常用：`0–9`、小数点、`+ - \times \div =`、括号、分式、平方、根式、`\pi`；
- 变量与函数：`x y z a b c n`、上下标、绝对值、`\sin \cos \tan \log \ln`、指数；
- 关系与集合：`< > \le \ge \ne \in \notin \subset \cup \cap \emptyset \infty`；
- 辅助操作：键盘分页、光标左/右、退格、确认。

物理专用量、单位、完整希腊字母和微积分高级模板保留在符号数据分类中，但不挤入数学填空题首屏。后续物理练习可以复用同一组件并切换科目配置。

视觉上参考用户提供的网格键盘：浅灰背景、白色主键、深色功能键、蓝紫色选中标签；窄屏维持可触达键宽，宽屏限制键盘最大宽度并居中。公式编辑框使用现有练习卡片的边框和焦点色，不复制参考页面的整体视觉。

## 5. 数据契约

填空题答案继续使用现有 `PracticeDraft.answer: String`，其内容改为不带 `$`、`\(`、`\)` 等定界符的 LaTeX，例如：

```text
\frac{3}{2}
\sqrt{2}
x^2-1
```

不保存渲染后的 HTML、SVG、图片或组件 AST。这样现有草稿版本、幂等提交和事件接口无需改变，也为未来数学、物理题库统一公式字段保留稳定格式。

前端限制单个填空答案最大 1,500 个字符；后端必须重复执行长度与危险命令检查，客户端校验不能作为安全边界。

## 6. 判题兼容

公式能够排版不等于答案数学正确。第一版只增加受限、可解释的表示规范化，不实现任意代数证明：

- 保留现有选择题规范化逻辑；
- 填空题接受 LaTeX 和现有纯文本标准答案；
- 统一空白、Unicode 常用数学符号和受控 LaTeX 命令；
- 至少保证 `\frac{3}{2}` 与 `3/2`、`\sqrt{2}` 与 `sqrt(2)` 等键盘会产生的等价表示能够匹配；
- 不使用字符串替换把未知命令静默修好，不把 KaTeX 能渲染当成答案正确；
- 不在第一版声明任意含变量表达式恒等，例如 `x+x` 与 `2x` 的自动等价判定。

非法、超长或不受支持的公式返回学生可理解的提交错误，原草稿保留，不写入新的 attempt，也不产生能力证据。

## 7. 数据流

```text
学生点击填空题公式输入框
→ MathField 根据按键维护结构和光标
→ onChanged 输出规范 LaTeX 字符串
→ PracticeSessionController.updateAnswer
→ 防抖保存草稿并记录受限 ANSWER_CHANGED 事件
→ 提交时后端验证公式输入
→ 受限公式规范化后与 rubric 标准答案比较
→ 现有判题、七维 Shadow、正式能力画像流程继续运行
```

学生响应不返回标准答案、内部证据代码或规范化细节。管理端仍可通过现有审查链路解释判题事实。

## 8. 错误与边界处理

- 草稿恢复：控制器中的 LaTeX 原样恢复到排版输入框；解析失败时保留原值并显示错误，不能清空学生答案。
- 切题：失焦前沿用现有草稿 flush；新题组件按 `question.id` 重建编辑控制器。
- 网络失败：公式仍留在本地状态，继续使用现有保存失败和重试提示。
- 键盘遮挡：页面由数学键盘 inset 推动并保持可滚动；375px 窄屏不得横向溢出。
- 重复回调：外部草稿同步到 MathField 时不再次调用 `updateAnswer`，避免自动保存循环和虚假修改次数。
- 无障碍：结构键提供中文语义标签，焦点顺序可通过 Tab 操作，错误信息不只依赖颜色。

## 9. 测试与验收

### Flutter 单元与 Widget 测试

- 填空题显示数学公式输入框，解答题仍显示普通文本输入框；
- 数字、运算符、分式、根式、平方和函数能够产生预期 LaTeX；
- 分式和根式插入后光标位于正确槽位；
- 切换题目再返回时恢复各自公式草稿，不串题；
- 外部恢复草稿不会重复产生答案变更事件；
- 公式变化进入现有自动保存链路，提交请求携带相同 LaTeX；
- 375px 和桌面宽度下键盘不溢出，输入框与提交操作可滚动到可见区域；
- Mock 与 Remote 两种 repository 均可使用填空题公式输入。

### 后端单元测试

- `\frac{3}{2}` 能匹配当前标准答案 `3/2`；
- 常用 Unicode 和键盘 LaTeX 表示规范化稳定；
- 非法命令、超长输入和不完整结构被拒绝且不创建 attempt；
- 公式校验失败不更新能力画像；
- 现有选择题、解答题判题回归不变。

### 手工验收

在 App 的练习页面进入第 12–14 道填空题，分别输入分数、整数和含符号公式，验证排版、光标、删除、切题恢复、提交判题和刷新恢复。远程模式下确认后端收到的是 LaTeX 源字符串，而不是 HTML 或截图。

## 10. 已知限制与后续

- V1 只保证受控表示的规范化，不提供通用计算机代数系统；
- 解答题过程中的行内公式、题干富文本公式和物理单位键盘不在本期；
- `math_keyboard` 的编辑内核作为外部依赖，若未来需要完全定制键位布局，可保留当前 LaTeX 契约并替换 UI 实现；
- 自适应推荐功能在填空题输入闭环完成后继续实施，本设计不改变推荐算法。
