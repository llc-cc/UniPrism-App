# 知识森林测试版设计

状态：用户已确认测试版范围、交互闭环和技术方向。

## 1. 背景与目标

UniPrism 按“知识树 → 对话树 → 两者转换链路”的顺序建设长期知识资产。第一阶段先在现有 Flutter App 中交付一个可真实操作的知识森林测试版，用最小成本验证以下核心体验：

```text
Agent 的 AI 回答
→ AI 判断回答具备沉淀价值并显示轻量提示
→ 用户主动点击“提炼为知识”
→ DeepSeek 返回结构化候选节点与关系
→ 用户整批预览、逐个勾选和编辑
→ AI 推荐已有主题树或建议新建主题树
→ 用户确认后写入本次 App 会话内的知识森林
→ 使用 reactive_mind_map 查看知识树
```

本测试版的成功标准是确认产品交互、节点信息密度和移动端树形浏览效果，不承担正式知识资产持久化。

## 2. 已确认的产品决策

1. 每位用户拥有多棵主题知识树，整体构成“个人知识森林”，不建立单一无限扩张的用户全局树。
2. 长期模型采用“UniPrism 公共知识底座 + 用户个人知识森林”双层结构。
3. 个人节点引用公共节点时，采用“公共引用 + 用户确认时的版本快照 + 个人覆盖层”。测试版保留对应字段边界，但不建设正式公共知识数据库。
4. DeepSeek 只生成候选节点，用户确认前不得写入正式知识树。
5. 一次回答可提炼多个节点；预览整批结构，同时允许逐个勾选、编辑和确认。
6. AI 只在判断回答有沉淀价值时显示入口，仍由用户点击后发起提炼。
7. AI 推荐目标知识树或建议新建主题树，用户可在确认前修改。
8. 第一版只绘制主要父子关系；跨分支关系保存在节点详情中，不强行绘制到画布。

## 3. 方案比较与结论

### 方案 A：固定数据的纯 UI 演示

开发最快，但不能验证 DeepSeek 的结构化提炼质量，也不能验证从真实 Agent 回答进入知识树的闭环。

### 方案 B：真实 DeepSeek + 会话内知识森林

复用现有 Agent 回答和服务端 DeepSeek 封装，在 App 当前进程内保存确认后的树和节点。它能验证完整用户体验，同时避免在交互尚未验证前引入数据库迁移、公共知识版本和多租户权限。

### 方案 C：直接建设生产级知识平台

一次完成数据库、公共知识底座、个人覆盖层、权限和版本管理，长期方向正确，但会把产品验证和基础设施建设绑定，首轮反馈成本过高。

结论：测试版采用方案 B。验证通过后，以本设计中的领域边界为基础另行设计生产持久化。

## 4. 技术边界

### 4.1 可视化组件

Flutter 锁定依赖：

```yaml
reactive_mind_map: 1.2.2
```

该组件负责节点布局、连接线、缩放、拖动、展开、收起、聚焦和点击回调。UniPrism 不重复实现这些能力。

业务代码不得直接把 `MindMapData` 当作知识领域模型。新增单向适配器，将 UniPrism 的 `KnowledgeTreeSnapshot` 转换为 `MindMapData`；页面之外不传播第三方组件类型。这样未来 Fork、替换组件或升级为图谱渲染时，不影响服务端协议和领域状态。

测试版锁定精确版本，避免依赖自动升级改变 API。只有出现跨分支绘线、节点拖动编辑、大节点量性能或上游维护问题时，才考虑 Fork；Fork 时保留 MIT 许可证声明。

### 4.2 DeepSeek

DeepSeek 只能从服务端调用，Flutter 不保存或接收模型密钥。新增知识提炼测试接口，复用现有服务端 DeepSeek JSON 封装和错误转换，不新建第二套模型客户端。

接口输入只包含当前用户主动选择的回答、必要的原问题、会话标识以及现有主题树的最小元数据。不得把完整用户画像、其他会话、联系方式或无关数据库内容交给模型。

## 5. 领域模型

测试版使用与第三方组件无关的 Flutter 领域模型：

- `KnowledgeForestSnapshot`：本次进程内的主题树集合；
- `KnowledgeTreeSnapshot`：树标识、主题、根节点和更新时间；
- `KnowledgeNode`：标题、摘要、类型、主要父节点、个人备注和确认状态；
- `KnowledgeEdge`：父子关系及可选的相关关系；
- `KnowledgeSourceRef`：来源内容或原始回答的可追溯引用；
- `KnowledgeCanonicalSnapshot`：预留公共节点 ID、公共版本和确认时快照；
- `KnowledgeExtractionBatch`：一次 DeepSeek 提炼返回的候选节点、关系和目标树建议；
- `KnowledgeNodeCandidate`：可勾选、编辑、接受或拒绝的临时节点。

候选节点与已确认节点必须是不同类型，避免 UI 状态错误地把模型输出视为用户资产。节点 ID 由客户端为本次测试生成稳定值；重复确认同一批次时按批次 ID 和候选 ID 幂等合并。

首版候选节点类型限制为：

- `topic`：主题或知识分组；
- `concept`：相对稳定的概念；
- `insight`：有依据的观点或结论；
- `method`：可复用的方法；
- `action`：下一步行动；
- `resource`：外部来源或学习资料。

## 6. 接口设计

新增开发期知识提炼接口：

```http
POST /api/dev/knowledge/extract
```

请求示意：

```json
{
  "conversationId": "conv_123",
  "messageId": "msg_456",
  "question": "人工智能专业适合我吗？",
  "answer": "……",
  "availableTrees": [
    { "id": "tree_ai", "title": "人工智能专业" }
  ],
  "clientTraceId": "uuid"
}
```

响应示意：

```json
{
  "batchId": "batch_123",
  "suggestedTree": {
    "mode": "existing",
    "treeId": "tree_ai",
    "title": "人工智能专业"
  },
  "nodes": [
    {
      "candidateId": "candidate_1",
      "parentCandidateId": null,
      "type": "concept",
      "title": "人工智能专业",
      "summary": "研究感知、学习、推理与智能系统构建的交叉专业。",
      "selected": true,
      "confidence": 0.86
    }
  ],
  "relatedEdges": [],
  "traceId": "trace_abc"
}
```

服务端必须限制问题、回答、树数量和节点数量；对 DeepSeek 返回结果执行结构校验、文本长度裁剪、空节点过滤、重复标题合并和非法父节点修复。模型返回不能直接携带任意 URL；来源链接只允许继承自现有已验证的 Agent 来源卡片。

该接口仅用于开发和内部测试，沿用现有开发接口的生产环境拒绝策略。测试版不新增数据库写接口。

## 7. Flutter 页面与交互

### 7.1 Agent 回答入口

每条非错误的 Agent 回答可携带稳定的本地消息 ID。测试版使用服务端返回的沉淀建议；当现有回答协议暂时没有该字段时，只对内容长度和类型满足最小规则的回答显示“可提炼为知识”提示，点击后仍由 DeepSeek 完成正式候选提炼。

提炼中禁用重复点击并显示局部加载状态。失败时保留原回答和入口，允许用户重试。

### 7.2 候选预览

预览使用独立页面或全高底部面板，包含：

- AI 推荐的目标树，可选择其他已有树或改为新建主题树；
- 候选结构概览；
- 每个节点的勾选状态、类型、标题和摘要编辑；
- 来源与原始回答说明；
- “确认加入知识树”主操作。

取消预览不得改变知识森林。父节点未选中而子节点被选中时，将子节点提升到最近的已选父节点；若不存在，则挂到目标树根节点，且预览中明确显示调整结果。

### 7.3 知识森林与知识树

Agent 页增加“我的知识森林”入口。知识森林用普通卡片或列表展示主题树，不使用思维导图同时渲染全部树。

进入单棵树后使用 `reactive_mind_map`：

- 默认聚焦根节点；
- 支持缩放、拖动、展开和收起；
- 通过自定义节点样式区分节点类型；
- 点击节点打开详情面板；
- 详情展示摘要、个人备注、来源、相关节点和原始回答入口；
- 当前树为空时显示空态和返回入口。

## 8. 状态流与失败处理

知识提炼状态机：

```text
idle
→ extracting
→ previewing
→ confirming
→ confirmed
```

失败状态分别保留在 `extracting` 和 `confirming` 的来源步骤，重试不能生成重复节点。

失败处理：

- DeepSeek 超时或不可用：显示“暂时无法提炼”，保留重试；
- 返回 JSON 无效：服务端转换为明确的结构化错误，不把原始模型输出返回 App；
- 候选为空：说明当前回答不适合沉淀，不创建空树；
- 组件渲染异常：回退为节点列表，保证知识内容仍可查看；
- 用户离开预览：丢弃未确认候选；
- App 重启：测试版知识森林清空，并在页面明确标注“内部测试数据，不会长期保存”。

## 9. 数据、安全与版权

- Flutter 端不新增模型密钥、数据库凭据或任意 HTTP 能力；
- 服务端只接受当前回答的有限文本并限制调用频率；
- 不将外部正文复制进知识节点，节点只保存允许展示的摘要和来源引用；
- 原始回答引用只用于回溯，不把完整会话复制到每个节点；
- 高风险结论只作为候选并显示来源提醒，不以 AI 置信度替代事实审核；
- 测试版不开放分享、协作、公开发布和用户间知识复制。

## 10. 测试与验收

### 后端单元测试

- 有效 DeepSeek JSON 转换为候选批次；
- 无效 JSON、空节点、超长字段、重复标题和非法父节点被安全处理；
- 节点数量和请求长度受限；
- DeepSeek 超时和错误转换为稳定错误码；
- 生产环境拒绝开发接口；
- 任意模型 URL 不进入可信来源字段。

### Flutter 测试

- Agent 回答显示提炼提示并能发起请求；
- 提炼中阻止重复请求，失败后可以重试；
- 候选节点支持逐个勾选和编辑；
- 目标树推荐可被用户修改；
- 未选父节点时子节点按规则重新挂载；
- 确认后知识森林出现目标树，进入后能够渲染节点；
- 点击节点显示详情和原始回答引用；
- 空态、测试数据提示和 App 重启不持久化边界清晰。

最低验证命令：

```text
dart analyze lib/main.dart lib/agent_experience.dart test
flutter test
```

若新增后端测试，同时运行对应 Vitest 文件。

### 验收场景

1. 用户在 Agent 中提出一个专业探索问题并取得真实 DeepSeek 回答；
2. 回答出现“可提炼为知识”提示；
3. 用户点击后看到多个结构化候选节点；
4. 用户取消一个节点、修改一个标题并接受目标树建议；
5. 确认后进入知识森林，打开主题树并查看思维导图；
6. 点击节点能够看到摘要、来源及原始回答关联；
7. 网络失败时原回答不丢失，重试不产生重复节点。

## 11. 已知限制与后续

- 测试版数据仅存在 App 当前进程，不能跨设备或跨启动恢复；
- 公共知识底座、版本快照和个人覆盖层只定义模型边界，不连接正式数据库；
- 暂不建设对话分支树；
- 暂不在画布绘制跨分支关系；
- 暂不验证超大知识树性能，测试版控制单批候选和单树节点规模；
- 测试效果确认后，再为正式多租户存储、懒加载、公共知识版本和对话树转换链路编写独立设计。
