# 万有棱镜 App：70+ 人格标签内容来源与 Agent 接入目录

> 文档版本：v1.1  
> 更新日期：2026-07-28  
> 适用范围：Flutter App、现有 Web/小程序共用后端、AI Agent 个性化内容检索与后续定时推送  
> 本文定位：内容源选型和接入准备文档，不是数据库设计文档，也不替代平台合同、律师意见或主管部门正式答复。

## 1. 先给结论

这个功能可以实现，但不能把所有平台都理解成“注册企业账号后就能抓取全站内容”。

最稳妥的建设路线是：

1. 先接入有明确官方 API、开放数据或已取得授权的来源；
2. App 只向自己的后端发请求，所有第三方 Token 和大模型 Key 均保存在后端；
3. 后端先检索候选内容，再由大模型完成标签、摘要、适龄性和推荐理由生成；
4. 对标题、摘要、正文、图片、视频、缓存、AI 改写和推送分别判断授权范围；
5. 对新闻、时政、教育政策等高风险内容增加来源白名单、人工审核和下架机制；
6. 小红书、虎扑、今日头条等没有开放全站检索能力的平台，不作为第一阶段采集源。

当前最适合万有棱镜 MVP 的组合是：

`知乎官方搜索 + 教育部/阳光高考 + OpenAlex/Crossref + GitHub/Stack Exchange + O*NET/ESCO + 世界银行开放数据`

微博完成官方应用申请后，再作为“热点信号源”接入。新华社、人民网、知网等内容在取得正式商务授权后进入生产环境。

## 2. 接入等级说明

本文使用以下等级，防止把“能打开网页”误认为“能在 App 中合法使用”。

| 等级 | 含义 | 当前建议 |
| --- | --- | --- |
| A | 有公开、官方、可自助调用的 API 或开放数据 | 可以开始开发，但仍需遵守许可、限流和署名要求 |
| B | 有官方 API，但需要注册、Token、OAuth、审核、订阅或特殊权限 | 可以准备和测试，生产前完成审核 |
| C | 需要机构订阅、商务合同、数据采购或书面授权 | 先联系商务，拿到授权范围后开发 |
| D | 有官网、RSS 或公开页面，但没有明确面向本场景的开放 API | 可人工调研；自动采集前核对 robots、用户协议和书面许可 |
| E | 没有面向本场景的公开能力，或协议明确限制自动抓取 | 不做爬虫，不作为当前正式数据源 |

### 2.1 目录数量总览

本文共盘点 90 个去重后的来源。为避免 A/B、D/C 等混合等级被重复计数，下面按
`E > C > D > B > A` 的优先级归入风险更高的一类：

| 类别 | 数量 | 是否现在开发 | 费用判断 |
| --- | ---: | --- | --- |
| A：公开 API 或开放数据 | 17 | 可以直接开发 | 多数免费，但仍有署名、许可和限流要求 |
| B：注册、Token、审核或特殊权限 API | 21 | 可以申请并测试 | 很多提供免费额度，但不能据此承诺生产长期免费 |
| C：商务合同、采购或书面授权 | 19 | 先联系商务，授权后开发 | 通常收费，价格和范围以合同为准 |
| D：只有官网、页面、RSS 或下载文件 | 21 | 适合人工同步、白名单或定期导入 | 页面免费访问不等于允许自动采集和 App 再分发 |
| E：没有适合接口或限制自动抓取 | 12 | 当前不开发采集器 | 即使付费注册普通账号也不代表获得内容授权 |

因此，目录中有 38 个来源具备“公开 API/开放数据或可申请官方 API”的技术路径，
但真正适合第一阶段的不是全部 38 个。第一阶段应选择能覆盖主要标签、国内网络可用、
许可边界清晰且维护成本可控的 15～20 个来源。

| GBIF | 普通物种检索不需要 | 真实接口 HTTP 200 | 物种、生物多样性、生态与环境 |
| NASA 图片与影音资料库 | 不需要 | 真实接口 HTTP 200 | 航天、天文、行星和地球科学素材 |
| The Met Collection API | 不需要 | 真实接口 HTTP 200 | 艺术、设计、美术史和博物馆藏品 |

因此当前后端共有 **20 个**内容源适配器。其中 O*NET 仍待官方 Key；世界银行
适配器已经完成，但需要在实际部署网络复测连通性。新增来源仍然采用“按问题选择
最多 4 个相关来源”的策略，并不会让每个问题同时调用 20 个平台。

这一步仍然属于实时查询阶段：没有新增 Redis、数据库统一内容池、定时采集或清洗
任务。第三方结果不会因为本轮接入而被长期保存。

### 2.3 “第一批 15 个来源”尚缺什么

| 尚缺项目 | 当前真实情况 | 下一步 |
| --- | --- | --- |
| 知乎热榜 | 当前只实现 `zhihu_search`，没有单独实现 `hot_list` | 使用现有 Access Secret 新增热榜适配器并验证额度 |
| 微博关键词/热搜 | 开发者认证仍在审核，不能把网页结果当 API 数据 | 审核和套餐权限通过后再实现，不先写非官方爬虫 |
| 教育部新闻 | 没有面向本 App 的通用公开搜索 API | 先做官方来源白名单、链接和人工/版本化同步方案 |
| 中国教育新闻网 | 尚无内容授权合同 | 联系商务确认摘要、缓存、AI 处理和推送范围 |
| 新华社供稿 | 尚无内容授权合同 | 联系供稿服务，拿到接口和合同后开发 |
| 阳光高考 | 没有确认可批量调用的公开 API | 第一版保留原文跳转和人工核验，不抓网页 |
| 国家职业分类大典 | 尚未导入权威版本化数据 | 取得官方公开文件后做本地结构化导入 |
| O*NET | 代码已完成但缺 Key | 用项目/公司信息完成组织审核并配置 `ONET_API_KEY` |

这意味着当前不是“15 个第一批来源全部接完”，而是第一批中已有 6 个核心来源可用，
1 个（O*NET）代码完成待凭证；同时额外完成了 arXiv、PubMed、Stack Exchange、
Hugging Face 和 Hacker News。微博和商业媒体不能用代码绕过平台审核。

### 2.4 必须分别确认的权利

即使平台提供 API，也不代表以下权利自动全部获得：

- 在 App 中展示标题和链接；
- 展示摘要、正文、评论、作者头像和图片；
- 将内容保存一周或长期归档；
- 交给大模型做摘要、标签、向量化或改写；
- 向用户发送通知；
- 商业化使用或向第三方用户再分发；
- 去掉原平台页面、广告、署名或跳转参数。

生产接入应以平台文档、API 返回协议、合同和书面授权中最严格的范围为准。

## 3. App 标签如何映射到 11 类内容

现有测评中的学科、兴趣活动、性格、工作方式和职业价值观，不需要为每一个标签单独接一个平台。推荐先归并为 11 个内容领域，再在每个领域内使用细粒度标签排序。

| 内容领域 | 可覆盖的现有标签示例 |
| --- | --- |
| 1. 国内热点与社交讨论 | 社会趋势、表达、辩论、公共议题、组织活动、热点敏感度 |
| 2. 专业、院校与职业 | 专业选择、学习体验、就业、成长、稳定、收入、工作环境 |
| 3. 学术与科研 | 数学、物理、化学、生物、实验、分析、抽象思考、研究探索 |
| 4. 软件、AI 与机器人 | 信息技术、编程、软件构建、小机器人、AI、工程实践 |
| 5. 商业、财经与管理 | 商业实践、组织、管理、经济、收入、风险、项目节奏 |
| 6. 人文、历史、文学、语言与社会 | 语文、文学、历史、政治、外语、写作、演讲、共情 |
| 7. 生物、地理、环境、户外与自然 | 生物、地理、环境、自然观察、户外活动、现场工作 |
| 8. 艺术、设计、音乐与创作 | 音乐、视觉艺术、手工、创作、审美、表达 |
| 9. 体育与健康运动 | 体育兴趣、团队合作、竞争、训练、赛事、户外运动 |
| 10. 游戏、数字媒体与互动娱乐 | 电子游戏、互动体验、游戏设计、数字内容、社区趋势 |
| 11. 视频、海外社区与开放课程 | 短视频、外语、国际视野、公开课、跨文化学习 |

推荐逻辑应同时考虑“用户喜欢什么”和“用户不希望收到什么”。例如，喜欢 AI 不等于愿意接收高频行业裁员新闻；喜欢财经也不等于允许系统生成投资建议。

## 4. 十一类内容来源与官方访问路径

### 4.1 国内热点与社交讨论

**适用标签：** 社会趋势、热点、辩论、表达、组织、公共议题、兴趣探索。

| 来源 | 等级 | 官方入口或申请路径 | 可获取内容与边界 | 当前判断 |
| --- | --- | --- | --- | --- |
| 知乎数据开放平台 | B | [平台首页](https://developer.zhihu.com/) · [开发文档](https://developer.zhihu.com/docs) · 个人中心申请 Access Secret | 官方说明包含 `zhihu_search`、`global_search`、`hot_list` 等能力；具体结果、额度、缓存和商用范围以账号权限及合同为准 | 已完成个人 Token 和真实检索测试，可作为当前主来源 |
| 微博开放平台 CLI/API | B | [CLI/Agent 接入页](https://open.weibo.com/cli/index) · [开放平台](https://open.weibo.com/) · 控制台申请应用、OAuth 和相应能力 | 平台展示发布、互动、关键词检索和趋势分析能力；能否获得热点、搜索及商用权限取决于产品套餐和审核 | 适合作为热点信号源，完成官方申请后接入 |
| 小红书开放平台 | E（全站内容检索） | [开放平台](https://ad-market.xiaohongshu.com/) · [小程序平台文档](https://miniapp.xiaohongshu.com/docs/frame/globalConfiguration) | 公开能力主要面向广告、商业合作、店铺、小程序、私信等，不等于开放全站笔记搜索和批量内容获取 | 当前不要爬取全站笔记；只有拿到针对内容使用的书面合作授权后再接 |
| 今日头条 | E（通用文章检索） | [头条内容发布方案](https://open.douyin.com/platform/resource/docs/ability/content-management/toutiao-publish-solution/) · [OAuth 文档](https://open.douyin.com/platform/resource/docs/develop/permission/toutiao-or-xigua/OAuth2.0/) | 公开能力重点是授权账号的发布和管理，不代表可搜索、复制和分发今日头条全站文章 | 不作为当前内容检索源 |
| 抖音开放平台 | B/E | [视频搜索能力](https://open.douyin.com/platform/resource/docs/ability/search-management/video/) | 官方视频搜索存在特殊权限、时间范围和使用场景限制，不能据此理解为可任意抓取全站视频 | 若确有品牌/视频场景再单独申请 |
| 哔哩哔哩开放平台 | B/E | [开放平台文档](https://openhome.bilibili.com/doc) | 主要围绕授权用户、UP 主及业务合作能力；不是默认开放的全站视频与评论搜索 API | 当前不作为全站采集源 |
| 微信公众号 | B/E | [永久素材列表接口](https://developers.weixin.qq.com/doc/offiaccount/Asset_Management/Get_materials_list.html) | 可管理已授权公众号自己的素材；不能通过该接口搜索全部公众号文章 | 仅接自有或已明确授权的公众号 |
| 虎扑 | E | [虎扑用户协议](https://www.hupu.com/policies/user) | 用户协议对未经书面许可的爬虫和自动抓取有明确限制；没有面向本场景的公开全站 API | 不做自动抓取 |

**推荐用途：**

- 知乎：围绕学生输入的问题检索专业讨论、经验回答和解释性内容；
- 微博：识别当日热点词和讨论热度，不直接作为权威事实结论；
- 权威事实核验：回到政府、学校、研究机构或获授权媒体原文。

**不建议：** 直接把社交平台热度等同于真实性，也不要让大模型把多个帖子拼成“事实新闻”。

## 7. 当前就能实现的接入方案

### 7.1 第一阶段：现在开始开发

下面这些来源具备较清晰的官方路径，适合先把“根据用户标签检索真实内容”跑通：

1. **知乎官方搜索**
   - 当前状态：已经取得 Token 并验证真实返回；
   - 用途：根据用户问题和兴趣词检索经验型内容；
   - 上线前：确认商用、缓存、AI 摘要、作者信息和推送范围。

2. **教育部专业目录和教育政策**
   - 用途：提供权威专业基础、政策变更和原文链接；
   - 第一版可先人工同步结构化目录，政策内容以链接和白名单展示。

3. **OpenAlex + Crossref**
   - 用途：为学科、专业和科研兴趣提供真实论文元数据与摘要；
   - 优点：来源稳定、可追溯、适合 AI 做通俗解释。

4. **GitHub + Stack Exchange + Hacker News**
   - 用途：为 AI、编程、机器人和软件开发标签提供项目、问答和趋势；
   - 必须保留原链接、作者/站点信息和许可证判断。

5. **O*NET + ESCO**
   - 用途：把人格、兴趣、技能、工作环境与职业连接起来；
   - 这是比“只搜热点文章”更适合万有棱镜核心定位的数据基础。

6. **世界银行开放数据**
   - 用途：补充行业、国家、教育、就业和经济趋势；
   - 数据适合做可解释的趋势卡片，不直接生成投资建议。

7. **Wikidata/Wikimedia、Open Library、GBIF、NASA、The Met**
   - 用途：补齐人文、阅读、自然、航天和艺术标签；
   - 可按用户标签逐步开启，不必第一天全部上线。

### 7.2 第二阶段：完成账号申请后接入

- 微博开放平台：热点词、关键词检索和趋势；
- O*NET API Key；
- Semantic Scholar、Hugging Face、Kaggle；
- YouTube Data API：仅作为海外可选来源；
- Unsplash/Pexels：作为合法配图来源；
- 中国气象数据网等需要注册的数据服务。

### 7.3 第三阶段：需要公司签约或采购

- 新华社、人民数据、央视网、中国新闻网、光明网、中国教育新闻网；
- 知网、万方、维普；
- 招聘平台的职位和薪酬数据；
- Sportradar、Stats Perform 等专业体育数据；
- Coursera、edX 等课程平台的深度数据。

### 7.4 当前明确不做

- 抓取小红书全站笔记；
- 抓取虎扑、NGA、TapTap、豆瓣等社区页面；
- 抓取今日头条全站文章；
- 使用公众号素材接口搜索全部公众号；
- 把哔哩哔哩、抖音的账号授权接口当成全站内容搜索；
- 下载或长期保存没有开放许可证的论文、图片、音乐和视频；
- 绕过登录、验证码、限流、反爬或付费墙。

### 7.5 当前“数据源优先”实施批次

在继续数据库内容池、Redis 和推送之前，先按下面顺序补齐内容覆盖。这里的“接入”是
指完成后端适配器、真实返回、来源字段、失败隔离和测试，不代表自动获得商业再分发权。

#### 批次 A：补完已经具备条件的核心来源

1. 知乎 `hot_list`：复用现有 Access Secret，补充国内社区热点信号；
2. O*NET：完成组织审核、配置 Key，补齐职业兴趣、技能和工作环境；
3. 教育部专业目录：继续使用已经导入的 2026 版本，增加年度更新校验；
4. ESCO：保留现有 API，同时准备下载官方数据集作为稳定的本地备份。

#### 批次 B：无需商务合同即可扩展的免费/开放来源

| 覆盖领域 | 下一来源 | 注册要求 | 费用判断 |
| --- | --- | --- | --- |
| 商业、经济、管理 | 世界银行 Indicators API、ILOSTAT | 世界银行不需要 Key | 可免费开始，遵守来源说明和限流 |
| 人文、历史、语言、基础知识 | Wikimedia REST API、Wikidata | 公共读取可开始；高频建议认证并提供 User-Agent | 可免费开始，必须署名并遵守开放许可 |
| 生物、环境、户外 | GBIF | 公共 API 可开始 | 可免费开始，逐数据集保留许可和引用 |
| 航天、地球科学 | NASA Open APIs | 可先用 DEMO_KEY，正式测试申请免费 Key | 可免费开始，检查每项媒体权利说明 |

| 音乐知识 | MusicBrainz API | 不强制 Key，必须设置可联系的 User-Agent 并限速 | 可免费开始，不包含音乐播放版权 |

#### 批次 C：等待平台审核

- 微博关键词和热搜：开发者认证、套餐及具体检索权限通过后开发；
- YouTube Data API：需要 Google Cloud 项目和 API Key，且要评估中国大陆可访问性；
- Semantic Scholar、Kaggle、NASA 正式 Key：按需要申请免费账号或提高额度。

#### 批次 D：商务并行，不阻塞开发

- 中国教育新闻网、新华社、人民数据、央视网等权威媒体；
- 知网、万方、维普等中文学术数据库；
- 招聘薪酬数据、体育实时数据、商业课程平台。

本阶段不应等待 C/D 批次全部完成。先完成 A 和 B，已经能够覆盖专业职业、学术科研、
AI 编程、商业经济、人文历史、自然环境、艺术音乐和游戏等主要标签；国内热点层待微博
审核通过后补入，正式新闻层待媒体合同完成后补入。

## 8. 推荐的 MVP 内容源组合

### 8.1 最小可用组合

| 目标 | 推荐来源 |
| --- | --- |
| 用户输入问题的社区经验 | 知乎官方搜索 |
| 专业与教育政策 | 教育部专业目录、教育部新闻、阳光高考原文链接 |
| 学科与科研趋势 | OpenAlex、Crossref、arXiv |
| AI/编程/机器人 | GitHub、Stack Exchange、Hacker News |
| 职业和工作方式匹配 | O*NET、ESCO |
| 宏观就业与社会趋势 | 世界银行、ILOSTAT |
| 基础知识与跨学科补充 | Wikidata/Wikimedia |

### 8.2 推荐检索流程

```text
用户问题 + 画像标签
        ↓
将意图拆成 2～5 个检索词
        ↓
按标签选择官方内容源
        ↓
后端调用各来源 API
        ↓
权限过滤 + 时间过滤 + 去重
        ↓
大模型提取标签、摘要、适龄等级和推荐理由
        ↓
规则评分 + 用户兴趣匹配
        ↓
人工审核或自动安全检查
        ↓
App 展示真实来源和原文链接
        ↓
用户主动订阅后才进入定时推送
```

### 8.3 大模型在流程中的职责

大模型适合：

- 把“我喜欢机器人但不喜欢纯理论”转换成多个检索词；
- 对不同来源的候选结果做标签和主题聚类；
- 生成简短摘要和“为什么推荐给你”；
- 判断内容是否适合学生年龄和当前学习阶段；
- 识别疑似广告、重复内容、标题党和信息冲突。

大模型不应该：

- 在没有检索结果时伪造“真实平台内容”；
- 伪造作者、阅读量、发布时间和原文链接；
- 把社区回答包装成教育部政策；
- 绕过平台授权读取内容；
- 自行决定新闻许可、版权或商业使用范围。

## 9. 后端接入原则

为了不影响已有 Web、小程序和报告模块，新增能力应采用独立功能边界：

```text
Flutter 测试入口
       ↓
独立内容检索 API
       ↓
来源适配器（知乎/OpenAlex/GitHub……）
       ↓
统一结果格式
       ↓
DeepSeek 标签、摘要与推荐理由
       ↓
返回 App
```

实施要求：

- 第三方 Token 和 DeepSeek Key 只放在后端环境变量或密钥管理服务；
- Flutter 不保存平台 Secret；
- 每个来源使用独立适配器，不能修改已有报告、登录、测评和小程序逻辑；
- 任何一个平台失败时，不影响其他来源和已有业务；
- 返回结果必须包含真实来源名称、原始 URL、发布时间和内容类型；
- 开发环境、测试环境、生产环境使用不同 Key；
- 日志不得记录完整 Token、手机号、用户画像全文或第三方私密数据；
- 后续正式上线时增加限流、超时、重试、熔断、缓存和来源下线开关。

## 10. 推送、审核与合规准备

### 10.1 人工审核是否需要管理端

生产上线建议有一个轻量管理端，至少支持：

- 查看待推送内容和原始来源；
- 查看 AI 摘要、标签、推荐理由和目标人群；
- 通过、驳回、修改、暂停和撤回；
- 配置允许来源和禁止关键词；
- 查看投诉、纠错和下架记录；
- 对教育政策、时政、灾害、医疗、未成年人等内容强制人工审核。

MVP 内测阶段可以先使用数据库列表或简单内部页面，正式推送前再完善角色权限和审计日志。

### 10.2 上线前需要准备的材料

- 产品功能说明和信息流页面截图；
- 全部内容来源清单及 API/合同/许可证明；
- 数据流图：采集、AI 处理、缓存、展示、推送、删除；
- 隐私政策、第三方 SDK 清单、个人信息处理规则；
- 个性化推荐开关、兴趣标签查看/修改/删除入口；
- 推送订阅、频率、免打扰和关闭入口；
- 内容安全制度、人工审核规则、投诉举报和纠错机制；
- 未成年人保护和适龄内容策略；
- 大模型服务商、模型名称、输入输出数据范围和安全评估材料；
- 新闻类服务是否需要许可的主管部门咨询或法律意见；
- App 备案、ICP、公安备案、算法备案/登记及生成式 AI 相关要求的专项核对。

具体备案义务会随产品形态、运营主体、服务地区和功能变化而变化，应在上线前以主管部门当时的正式口径为准。

## 11. 建议的实际推进顺序

### 第 1 周：确定合法且可开发的来源

- 固定 11 类标签映射；
- 保存知乎开放平台文档、账号权限和调用额度；
- 申请 O*NET、GitHub、Crossref/OpenAlex 等必要账号；
- 建立来源许可台账，记录是否允许摘要、缓存、AI 处理和推送；
- 不等待所有商务平台，先使用 A/B 级来源开发。

### 第 2 周：完成多来源真实检索

- 保留现有知乎独立测试接口；
- 新增 OpenAlex、Crossref、GitHub、O*NET/ESCO 适配器；
- 所有结果展示真实来源、时间和原始链接；
- 增加超时、空结果和来源失败提示；
- 禁止任何演示卡片混入真实结果页面。

### 第 3 周：完成个性化排序

- 将测评标签映射到 11 个内容领域；
- 用户输入用于生成检索词，历史行为仅用于排序；
- 点击、停留、收藏和“不感兴趣”更新偏好；
- 大模型只处理召回结果，不凭空生成外部内容。

### 第 4 周：完成订阅和审核闭环

- 用户主动选择领域、时间、频率和免打扰；
- 后端生成候选推送任务；
- 管理端审核高风险内容；
- App 通知跳转到带真实来源的内容详情；
- 完成停止订阅、删除历史和投诉纠错入口。

### 商务工作并行进行

- 联系新华社/人民数据/中国教育新闻网等获取正式报价和授权范围；
- 联系知网/万方确认 API、摘要、AI 处理和终端展示许可；
- 完成微博应用申请；
- 取得书面许可前，不把小红书、虎扑、今日头条等列为正式采集源。

---

## 12. 最终建议

万有棱镜当前不要继续追求“接入平台数量”，而应优先完成一个可信闭环：

> 用户兴趣和问题 → 官方 API 检索 → 返回真实内容 → DeepSeek 生成摘要和推荐理由 → 显示原始来源 → 用户反馈 → 后续订阅推送

建议第一版正式支持：

1. 知乎；
2. 教育部专业目录和教育政策；
3. OpenAlex、Crossref、arXiv；
4. GitHub、Stack Exchange、Hacker News；
5. O*NET、ESCO；
6. 世界银行、ILOSTAT；
7. Wikidata/Wikimedia。

这组来源已经能覆盖专业选择、学科科研、AI 编程、职业兴趣、国际趋势和通识知识，足以验证 70+ 标签的个性化效果。微博在应用权限完成后加入热点层；权威媒体和中文学术数据库在公司取得合同后加入生产层。

小红书、虎扑、今日头条、豆瓣、NGA、TapTap 等来源暂不通过爬虫接入。这样既能尽快完成真实功能，也不会因为一个不确定的数据源拖慢后端开发和后续上线。
